# マニュアル

設置手順を書いたマニュアルを配布物に含める。
**別ファイルとして同梱するのではなく、Markdown をバイナリに埋め込み、
アプリ内の URL で読めるようにする**。

- ソースは `docs/manual/{ロケール}/*.md` に置く。
  リポジトリ上でそのまま読め、差分レビューもできる。
  **原典は日本語 (`ja/`)**。
- **紹介のサイト (`site/`) には載せない**。アプリの中だけで読む。
- **ページの URL は、ファイル名から番号を除いた部分** (`02-setup.md` → `/help/setup`)。番号の振り直し (目次の並べ替え) は URL を変えない。
  番号を除いた部分を変えるときは、画面から張ったリンク (ログイン画面・軸の画面、下記) も合わせて直す。変えても黙って切れるだけで、検査では見つからない。
- **他のページへのリンクは、原典のファイル名で書く** (`[設置する](02-setup.md)`)。
  リポジトリ上でも辿れる。アプリは `/help/setup` に向け直す。
- **画像は `docs/manual/{ロケール}/images/*.webp` に置き、本文には `images/<名前>.webp` で書く**。
  画面の文言が写るので言語ごとに持ち、訳の無い画像は原典に落とす (ページと同じ)。アプリは `/api/v1/help/images/<名前>` で配る。
  バイナリに入るので、WebP にして1枚あたり数十 KB に抑える。OS で違う画面は Windows のものを載せる。
  **注意の囲みは引用 (`>`) で書く**。アプリは警告の帯と同じ色で囲む。読み落とすと困ることだけに使う。
- **画面の操作は、画面に出ている言葉のまま書く** (「フォルダーを追加...」なら「追加する」)。
  分かりやすい言葉に言い換えると、読んだ人が画面でその言葉を探せない。
  画面の言葉で誤解されそうなこと (「削除」でパソコンのファイルまで消えるか等) は、言い換えずに注意の囲みで補う。
  **画面は2倍の解像度で撮り、縮めずに置く**。表示する側は `2x` として扱い、実物と同じ大きさで出す (本文より広ければ縮める)。
- `rust-embed` でバイナリに埋め込む (フロントエンドのビルド成果物と同じ仕組み)。
  配布物は引き続き実行バイナリ1つで、同梱ファイルが増えない。
- `/help` で目次、`/help/{ページ}` で各ページを表示する。
  **匿名で読める** (設置直後、まだログインできない状態で参照する文書のため)。
- 入り口は、トレイのメニューの「マニュアル」、ログインした人のユーザーメニュー、関連する画面からのリンク (下記)。
  トレイに置くのは、設置した人がログインの前にも目次から読めるようにするため。ログインしていない人の画面から入れるのは、ログイン画面の設置の手順への案内 (サーバーの PC だけ) しかない。
- **タブレット以上では、目次を左のサイドバーとして固定する** (GitBook・Notion・Docusaurus 等の定番)。
  本文を読み進めてもサイドバーはヘッダーの下に留まり、他のページへ移るたびに
  先頭までスクロールし直さずに済む。スマートフォン幅は並べる横幅が無いので、
  目次を本文の上に置く1段のレイアウトにする。
- **スマートフォン幅の個別ページでは、目次を「目次」ボタンの中にたたみ、本文から見せる**。
  目次を並べたままだと最初の画面を埋め、選んだページの本文がスクロールしないと見えないため。
  Docusaurus・GitBook・Microsoft Learn もスマートフォン幅では目次をたたむ。
  ページを移ったら、開いた目次はたたみ直す。`/help` の目次だけの画面は並べたまま。
- **本文の文字は 16px (`text-base`)**。一覧・フォームの 14px より一段大きくする。長い文章を読む画面なので、読みやすさを優先する。
  見出しは h2 を 20px、h3 を 18px にし、表とコードは本文と同じ大きさにする。目次と前置きの大きさは他の画面と同じまま。
  **本文の先頭の h1 (ページの題) は 24px で出す**。スマートフォン幅では目次をたたむので、目次の塗りではどのページかが分からないため。
  Microsoft Learn・Apple のサポートなど、マニュアルのサイトはページの先頭に題を置く。
  個別ページでは目次の上の「WebLAV の使い方」を見出しにせず、本文の題をそのページの h1 にする。
  目次の上の前置きは「はじめに」の1段落目と重ねない。「はじめに」で同じ文が2回出るため。
- レンダリングはフロントエンド側で行う。Markdown → HTML の変換をサーバーに
  持たせない (バイナリサイズと、サニタイズの責任を増やさないため)。
  ソースは自分たちで書くものだけなので、外部入力のサニタイズ問題は生じない。
- **表示言語は画面の表示言語 (→ ui.md「UI 全般」) に従う**。
  マニュアルだけの切り替えは持たず、URL にも言語を出さない。
  画面が1つの言語で揃い、利用者が覚えることが増えないため
  (ui.md「UI 全般」の「範囲はヘッダーのトグル2つ」と同じ方針)。
  - 取得する言語は API のクエリ (`locale`) で渡す。ブラウザーの URL には出ない。
  - 知らない値は原典 (日本語) として扱い、422 にはしない (ui.md「ホーム・グループ・フォルダー・アーカイブの並び順」と同じ扱い)。
    ただし**画面の表示言語を足すときはマニュアルの訳も同時に足す**ので、
    通常この落ち方はしない。訳が追いつくまでの保険として持つ。
  - 目次の構成と並びは**原典が決める**。
    訳が追いついていない言語でも目次が変わらないようにするため、訳だけにあるファイルは目次に出さず、訳の無いページは原典の本文を返す。
  - 応答には**実際に返した言語**を載せ、本文と目次の `lang` 属性にはそれを使う。
    訳の無いページは原典に落ちるため、要求した言語をそのまま書くと嘘になる。
  - **言語を URL に載せる案は見送った**。
    得られるのは「この URL を渡せば相手の設定によらず英語で開く」ことだけで、
    同じ教室・同じ家庭の LAN で使うものなので、言語の違う相手にリンクを渡す場面が薄い。
    URL とトグルの2系統を抱える手間に見合わないと判断した (→ ui.md「UI 全般」)。
- 管理画面の関連する箇所から該当ページへリンクする。少なくとも次の2つ。
  - アーカイブの軸の画面 → 軸の決め方の解説
  - ログイン画面 → 最初の管理者を作る手順。サーバーの PC から開いていて、管理者がまだいないときだけ出す (トレイの「セットアップ」と同じ条件)。最初の管理者はサーバーの PC でしか作れず、作った後は押した先でできることが無いため

収録するページ:

読み手ごとに分ける。設置する人・登録する人・見る人が、自分の用のページだけを読めば済むようにするため。
上級の話 (`config.toml`・HTTPS) は、初めての人が読む「設置する」から外す。

| ページ | 読み手 | 内容 |
|---|---|---|
| はじめに | 全員 | 何ができるか、しくみ (公開できるフォルダーとコンテンツの関係を図で)、クイックスタート (慣れた人が設置から開くまでを済ませる最短の手順) |
| 設置する | 設置する人 | インストール、最初の管理者の作成、管理画面を開くまで |
| ログインと表示 | 全員 | ログイン・ログアウト、自分のパスワードの変更、言語と明るい・暗い表示 |
| 公開できるフォルダーを追加する | 設置する人 | サーバーの PC の `localhost` でだけ操作できること、追加・名前の変更・削除 |
| コンテンツを登録する | 登録する人 | 種類ごとの登録、公開範囲、グループ、変更・削除 |
| アーカイブを設定する | 登録する人 | 始めから公開までの例、軸 (追加・編集・削除)・ファイル名の語・並び順・再スキャン・公開と非公開 |
| ファイルを見る | 見る人 (に伝える人) | スマートフォンで開く、絞り込み・並び順、音声・ビューアー |
| ユーザーを管理する | 管理者 | 追加、「管理者」と「編集者」の違い、パスワードの再設定、削除 (登録したコンテンツの行方) |
| 運用する | 設置する人 | 起動・終了、サイト設定、バックアップ、アップデート、アンインストール、置き場所 |
| Pro にする | 設置する人 | Free の上限、料金、申し込みと結ぶ (つながらない PC の返しのコード)、外す、解約、Pro を移す |
| うまくいかないとき | 設置する人 | 症状から引く切り分け。管理者が1人だけでパスワードを忘れたときの復旧もここ |
| よくある質問 | 全員 | できないこと (外から見る・NAS など) と、その理由 |
| 安全に使うために | 導入を決める人 | 前提、WebLAV が守っていること、使う人にお願いすること |
| 詳しい設定 | 詳しい人 | `config.toml` の書き方と項目の一覧、HTTPS (リバースプロキシ) |
