# 閲覧体験と画面の決めごと

## 音声のページ内プレイヤー

- **振り分けはファイルの種類 (拡張子→MIME) で決まる**。コンテンツの種類では
  決まらない。`archive` のアイテムでも `folder` の中のファイルでも、
  音声なら常にページ内で再生される。
- ページ下部に固定表示されるプレイヤーコンポーネントを1つ置く。同時に鳴るのは
  1トラックのみ。
- **操作は再生・一時停止・シーク・10秒戻す・10秒進む・前の曲・次の曲・曲が終わったときの動き・シャッフル・ミュート**。
  音量の調節は置かない。iOS ではページから音量を変えられず、PC も OS の音量で足りるため。
  キーボードのショートカットも置かない。入力欄との衝突を気にするわりに使う人が少ないため。
- **前・次の曲は、再生を始めた一覧に並んでいた音声の表示順で決める**。
  アーカイブなら絞り込んだ後の並び。音声でない行は飛ばす。
  並びは再生を始めた時点で写し取り、別の画面へ移っても変えない。
  プレイリストを作る・並べ替える機能は持たない。
  - 「前」は、再生位置が3秒を過ぎていれば曲の頭へ戻す。3秒以内なら前の曲へ移る。音楽アプリで一般的な動き。
  - 端では止まる。最初の曲で3秒以内なら「前」は頭へ戻すだけ、最後の曲では「次」を押せない。全曲リピートのときだけ、端から反対の端へ移る。区切って取る一覧は、続きを取り切るまで端を端と見なさない (まだ取っていない曲を飛ばさないため)。
  - 一時停止中に前・次で曲を替えても、止めたままにする。次の音源を選んでおき、合図で鳴らせるようにするため。
    一覧の行を押したときと、続けて再生で次へ進んだときは鳴らす。
  - 今の曲の行をもう一度押したら、頭に戻さず続きから鳴らす。
- **曲が終わったときの動きは、1つのボタンで「1 曲で止まる → 続けて再生 → 全曲リピート → 1 曲リピート」と順に替える**。
  Spotify・Apple Music のリピートのボタン (オフ → 全曲 → 1曲) と同じ形に、教材を1つずつ聞くための「1 曲で止まる」を足したもの。
  - 続けて再生は最後の曲が終わったら止まり、全曲リピートは最初の曲へ戻る。1 曲リピートは `<audio>` の `loop` に任せる (曲の終わりを待って鳴らし直すより途切れず、ロック画面でも止まらない)。1 曲リピートでも「次」「前」は曲を替える。
  - 最初は「1 曲で止まる」。4つを順に回すので `aria-pressed` は付けず、ボタンの名前に今の状態を出す。止まる以外は押した見た目にする。
- **シャッフルは、リピートと別のオン・オフのボタンにする** (Spotify・Apple Music と同じ)。並び順の設定で、曲が終わったときの動きと組み合わせて使うため。
  - オンにすると、今の曲を先頭にして残りを混ぜる。今の曲は止めずに続ける。オフにすると元の並びに戻り、今の曲の次から続ける。
  - 全曲リピートと一緒なら、最後の曲から最初へ戻るたびに混ぜ直す。同じ順を繰り返さないため。終わった曲は先頭に置かない。
  - 区切って取るアーカイブの一覧は、サーバーで混ぜた順を取る (→ archive.md「音声のシャッフル」)。フォルダーの一覧のように全部が手元にある並びは、手元で混ぜる。
- 曲が終わったときの動きとシャッフルは `localStorage` に置き、その端末で覚える。
  「UI 全般」の「設定をアカウントや DB に保存しない」と同じ扱い。
- **操作部分は `<audio>` の標準コントロールを使わずに自前で作る**。
  標準の見た目はブラウザーごとに違い、足したボタンと揃わないうえ、タップ領域 44px (→ 「UI 全般」) も保証できないため。
  `<audio>` は見せずに再生だけを任せる。
- **`<audio>` は1つだけ置いて使い回し、曲の差し替えと `play()` は押された操作の中で同期的に行う**。
  Safari (iPad・iPhone) は、操作の後に作り直した要素や、非同期に呼んだ `play()` を利用者の操作と見なさず、再生を拒むため。
  同じ要素なら、曲の終わりから次の曲も鳴らせる。
  - 一時停止の表示は要素の play / pause から読む。読み込みに失敗して `play()` を拒まれたら、一時停止の表示に戻す (WebKit は拒んでも `paused` を false のまま残す)。
- **Media Session API に曲名と操作 (再生・一時停止・10秒戻す進む・前後の曲・シーク) を渡す**。
  画面を消した iPad やスマートフォンの、ロック画面やイヤホンのボタンから操作できるようにするため。
- **曲名の行の右端 (閉じるボタンの左) に、小さなスペクトラムアナライザー (周波数ごとの音の大きさを縦の棒で出すもの) を置く**。
  ミュート中 (端末でもプレイヤーでも) に音が出ていると分かり、ミュートを外していきなり鳴って驚かないようにするため。
  - 鳴らしている音を Web Audio の AnalyserNode でその場で分ける。棒は12本で、周波数は対数で等しく分ける (60Hz〜16kHz)。色は primary。
  - プレイヤーのミュートは、AnalyserNode の後ろの GainNode で消す。`<audio>` の muted で消すと、測る側にも無音が届くため。
  - AudioContext は再生の操作の中で作るか再開する。Safari は操作の外では音を出させないため。
    最初に再生するまでと、Web Audio を使えないブラウザーでは棒を出さない。
  - 止めている間は、棒が下りきったら描くのをやめる。`prefers-reduced-motion` では棒を出さない。
  - プレイヤーを閉じたら AudioContext を止める (suspend)。一時停止では止めない。ロック画面からの再生は操作の中と見なされず、再開できないことがあるため。
  - iPad の Safari では、音を Web Audio に通すと、画面を消したときやほかのアプリに移ったときに再生が止まることがある。それは受け入れる。
- 並べ方は、スマートフォン幅で曲名と閉じるボタン / シークバーと時間 / 操作の3段。
  操作は左からシャッフル・前・10秒戻す・再生・10秒進む・次・曲が終わったときの動きで、再生ボタンを中央に大きく置く。
  ミュートは曲名の行 (スペクトラムアナライザーと閉じるボタンの間) に置く。375px 幅の操作の段は 44px のボタン7つで埋まるため。
  シャッフルとリピートを両端に置くのは Spotify・Apple Music と同じ形で、10秒送りをシークバーの両脇へ移す案や、2つをメニューにまとめる案は採らない (前者はシークバーが短くなり、後者は切り替えに2回押すうえ、オンかどうかがボタンだけで分からない)。
  **タブレット以上では、曲名(左)・操作(中央)・ミュートと閉じるボタン(右)の1段目と、全幅のシークバーの2段目にする**
  (前へ・再生・次へを中央に置く一般的な音楽アプリの形)。操作を左に寄せてシークバーを右の狭い領域に押し込めていた
  従来の1段まとめは、シークバーが窮屈になるため採らない。
- **曲名がはみ出す長さなら、左右に流して隠れた部分も読めるようにする**。
  端まで流れたら少し止まり、逆再生ではなく先頭に戻ってまた流れる (Apple Music・CarPlay の曲名表示と同じ動き)。
  タッチデバイスはホバーが無く「ホバーしたときだけ動く」方式だと気づきにくいため、はみ出している間は常時動かす。
  はみ出していない曲名は動かさない。`prefers-reduced-motion` では動きを止める。
- シークは Range 対応 (実装済み) で成立する。
- 画像は「画像のプレビュー」のビューアー、PDF・動画・テキストは「PDF・動画・テキストのビューアー」のビューアーで開く。それ以外 (Office の文書・zip など、ブラウザーが表示できないもの) は新規タブで開く。
- 音声・PDF・動画と、HEIC などビューアーで開く画像は拡張子で見る (`frontend/src/lib/file-kind.ts`)。PhotoSwipe で開く画像はサーバーが大きさを返したか、テキストはサーバーが `isText` を返したかで見る (→ 「画像のプレビュー」「PDF・動画・テキストのビューアー」)。
  種類ごとの登録口は持たない。数個の種類を画面の分岐で書き分けても足りるため。

## アーカイブの一覧画面

- 一覧の表示を使うフォルダーは、見出しの下に「フォルダー」「ライブラリ」の切り替えを出す (→ folders.md「2つの表示」)。押すと画面が移るので、ボタンでなくリンクの組にし、見た目はリストとタイルの切り替えに揃える。

- 軸ごとのドロップダウンを横に並べ、AND で絞り込む。選択肢は archive.md「軸の値の辞書と導出」のとおり
  「見えているアイテムに実際に現れた値」から作り、表示名でまとめる。
- 絞り込みに出さない軸 (→ archive.md「軸の定義」) のドロップダウンは出さない。
- 行はタイトルの下に、補助色で軸の値を並べる (2段目)。
  出すのは、表示タイトルのテンプレートで使っていない軸のうち、絞り込み中でない軸の値。軸の並び順に空白で区切り、表示名で出す。
  未設定の軸は出さず、出す値が無ければ2段目を出さない。
  同じタイトルが年度や回の数だけ並んだとき、見分けられるようにするため。
  絞り込み中の軸は、全行で同じ値になるので出さない。
  出す軸を選ぶ設定は持たない。テンプレートに入れた軸はタイトルで読めるので、残りを出せば足りる。
  テンプレートの軸が未設定でタイトルがファイル名に落ちた行 (→ archive.md「表示タイトル」) は、テンプレートの軸もタイトルで読めないので、2段目に出す。
- 絞り込み状態は URL クエリに持つ (ブラウザーの戻る/進むが効くこと、
  リンクを共有できること)。
- 階層は表に出さない。フラットな一覧のまま。
- アーカイブのアイテムの一覧 (閲覧・検索の結果・管理画面のファイルのタブ) は、画面に見えている所だけを描く (`virtua` の `WindowVirtualizer`)。
  アーカイブは数万件になり、全部の行を描くとブラウザーのメモリが尽きて画面が落ちるため。
  閲覧と管理画面のファイルのタブは、行もサーバーから区切って取る (→ archive.md「画面が見える辺りを取りに行く」)。
  タイルは1段ずつ描くので、1段の枚数を画面の側でも `grid-cols-*` と同じ幅で切り替える (`$lib/list-row.ts`)。
  描いていない行は、ブラウザーのページ内検索では見つからない。探すのは一覧の絞り込みで行う。

## UI 全般

- **作成の入力は必要最小限にする。** 任意の項目は作成後の編集で足す (コンテンツは編集ページへ移る)。
  - 自動で付ける値 (コンテンツのタイトル・共有の名前) が既存と重なって区別しにくいときは、
    エラーにせず `(1)`、`(2)` と連番を付ける。比べるのは、コンテンツは同じ親の兄弟、共有は全体
    (大文字小文字は区別しない)。
  - 自動の元になる値がないもの (group のタイトル、ユーザー名、軸名) だけ入力させる。
  - link のタイトルはサーバーが URL のページから取る (`og:title`、無ければ `<title>`。サイト名を除いた短い題になっていることが多い `og:title` を先に見る)。取れなければ、URL がファイルを指すならファイル名 (→「URL のファイル」)、ほかはホスト名にする。
    ここから外へは公開アドレスにだけ接続する (`src/api/link_title.rs`)。サーバーからの外向きの通信は、ほかに、リンクのカードの情報を取るとき (→「リンクのカード」)、URL のファイルを中継するとき (→「URL のファイル」) だけ。
    TLS は OS の証明書ストア (native-tls) を使う。学校や事務所のプロキシが差し込む証明書も通るため。
  - URL のスキームが省かれていたら、保存時にサーバーが決める。入力欄は `type="text"` にする (`type="url"` だとブラウザーが送る前に弾く)。
    - LAN の相手 (IP がプライベートなど公開アドレスでない、`.local`、または名前を引いた先がすべてそう): 試さずに `http://`。LAN の機器は http でしか応答しないものが多く、LAN へは接続しない決まりで試せないため。
    - それ以外: `https://` で接続を試し、応答が無ければ `http://`。どちらも無ければ `https://`。作成時はタイトルの取得と1回の接続にまとめる。
    - `:` の直後が数字ならポートとみなす (`nas.local:5000`)。

- レスポンシブ。閲覧はタブレット・スマートフォンから、管理は主に PC からだが
  PC 限定にしない。
- デジタル庁デザインシステムβ版を参考資料の一つとして活用する。厳密な準拠は
  求めない。
- ボタンラベルは、押した結果どうなるかを一貫して示す。
  - 末尾に「...」 (例:「エクスポート...」): ダイアログ・モーダルが開く
  - 「〜する」 (例:「保存する」「削除する」「送信する」): 押すと何かが残る。データ・設定・ログインの状態が変わる、入力が失われて戻せない、のどれか。
    「〜する」の付かない動詞は言い切りの形で書く (「戻す」「破棄して移動する」)。
  - 体言止め (例:「コピー」「ダウンロード」「パスワードを表示」): 何度押しても結果が同じで、何も残らない。別ページ・別ビューへの移動もこちら。
    入力欄の中身を書き換えるだけで、保存するまで何も残らないもの (「タイトルを再取得」「既定値に戻す」) も含む。
    体言止めにできない動詞はそのまま書く (「閉じる」「開く」「戻る」)。
  - 「〜する」で、操作の重みの違いを利用者に示す。主な OS やアプリはボタンに「〜する」を付けないが、WebLAV は重い操作にだけ付けて見分けられるようにしている。
  - 「...」は半角ピリオド3つで書き、三点リーダー (U+2026) は使わない。
    BIZ UDPGothic の三点リーダーは点が文字の高さの中央に来て、ベースラインにそろわないため。
    進行中を示す文言 (「読み込んでいます...」) の末尾も同じ。
- 外来語の語末の長音は Microsoft の表記に合わせる。-er・-or・-ar で終わる語は「ー」を付け (「フォルダー」「ブラウザー」「ビューアー」)、-ry で終わる語は付けない (「メモリ」「ライブラリ」)。
  画面の文言・マニュアル・タスクトレイが対象。macOS などは長音を付けない語が多く、書く人の手元の表記に引かれて戻りやすいので、取り違えやすい語は `just lint` (`scripts/check-long-vowel.mjs`) が検出する。
- 括弧は Microsoft の表記に合わせ、半角で書く。外側の和文との間には半角の空白を入れ、内側には入れない (「パスワード (確認)」)。「」や句読点との間には入れない。
  画面の文言・マニュアル・タスクトレイが対象。全角の括弧と、和文に直に接した括弧は `just lint` (`scripts/check-parentheses.mjs`) が検出する。
- 文として読ませる文言 (トースト・説明・注記・入力欄のエラー) は、1文でも末尾に句点を付ける。見出し・ラベル・ボタン・その場の状態を示す短い表示 (「見つかりません」「選択中」) には付けない。
- 画面に出る文に差し込む名前 (タイトル・軸の名前・ユーザー名・パスなど、利用者が付けたもの) は、日本語は「」、英語は “ ” で囲む。名前は空白や「の」「を」を含みうるので、囲まないと境目が分からなくなるため。
  読み上げ用のラベル・見出し・「名前: 中身」の形の項目・数値の設定値・敬称の付くもの (「{creator} さん」) は囲まない。英語の引用符は、文の中でラベルを引くときも含めて曲がった形 (“ ”) に揃える。
- 次の用語は言い換えない。画面の文言とマニュアルで、同じものを別の語で呼ばない。文の中でボタンや項目を引くときは、そのラベルと同じ語にする。

- **外部の要因で起きたエラー (ファイルやフォルダーが無い・読めない、つながらない など) の文言は、起きた事実だけを伝える。**
  考えられる原因・確かめ方・直し方はマニュアル (`docs/manual/`) に書き、画面には載せない。
  例:「フォルダーが見つかりません。」で止め、「移したなら場所を選び直してください」は足さない。
  - ただし、時間をおいて試せば直ることが多いとき (つながらない・混み合っている など) と、利用者にできることがそれしかないときは、「しばらくしてからもう一度お試しください」を添える。
- shadcn component を改変したらコードにコメントを残す (プロジェクトルール)。
- **表示テーマ (ライト/ダーク/システム追従) と表示言語 (日本語/英語) を
  ヘッダーで切り替えられる**。テーマは、教室の暗い部屋や家庭の夜間利用で意味があるため置く。どちらも
  閲覧者に見える必要があるのでヘッダーに置く (実装済み:
  `mode-toggle.svelte` / `language-toggle.svelte`)。
  **範囲はヘッダーのトグル2つに限定する**。設定画面は作らない。選択値を
  アカウントや DB に保存しない (ブラウザー側で完結させる)。ここを起点に設定項目を
  増やさない。前身のアプリでは「個人設定 (言語/テーマ)」がスコープ膨張の起点だったため。
  一覧の並べ方 (リスト/タイル、下の「閲覧側の一覧」) は、並び順と同じく一覧の上で選ぶ表示の操作で、ここで言う設定項目には数えない。
  - **最初に開いたときの言語は、ブラウザーの言語設定 (`navigator.languages`) に合わせる**。
    strategy は `['cookie', 'preferredLanguage', 'baseLocale']` で、
    「cookie > ブラウザーの言語 > 英語」の順になる。
    閲覧者が最初に開くのは LAN のアドレスで、そこには cookie が無い。
    cookie はオリジンごとに保存されるので、サーバーの PC で日本語に切り替えても LAN の端末には効かず、
    日本語の端末にも英語で出ていた。生徒・家族がそのまま読む前提と合わない。
    **これは初期値の決め方であって、選ばせる UI は増やさない** (上の「範囲はヘッダーのトグル2つ」は変えない)。
    - **cookie は「その端末で決まった言語」であって「本人が選んだ言語」ではない**。
      Paraglide は最初に解決した言語をそのまま cookie に焼く (400日)。
      つまり**初回に開いたときのブラウザーの言語でその端末の言語が決まり、以後はトグルで変える**、という動き。
      端末の言語設定を後から変えても追随しない。
    - **cookie の名前は `WEBLAV_LOCALE`**。
    - e2e と仕様書の生成は、実行する PC の言語で結果が変わらないように固定する
      (`playwright.config.ts` は `locale: 'en-US'`、仕様書は `locale: 'ja-JP'` と `WEBLAV_LOCALE` の cookie)。
      cookie が無ければ表示言語がブラウザーの言語で決まり、日時の書式もそれに従うため。
  - **日時と数値の書式も画面の表示言語に従わせる**。ロケールに依る書式は `$lib/format.ts` に集め、
    `toLocaleString` に `getLocale()` を渡す。トグルで英語にすれば日時も `9/16/2026` になる。
    画面の中で言語が食い違わないことを取る。
    英語は米国式に固定されるが、持っている翻訳が `ja` / `en` の2つなので、そこは受け入れる。
  - **表示言語を URL で切り替える案 (Paraglide の URL strategy) は見送った**。
    全画面のパスを言語ごとに持つことになり、`reroute` フックとリンクの組み立ての
    見直しが要るわりに、得られるのは「共有した URL が相手の設定によらず同じ言語で
    開く」ことだけ。閲覧者は同じ教室・同じ家庭にいて、言語の好みもトグルで足りる。
    マニュアルも同じ理由で画面の表示言語に従わせている (→ help.md)。

### 見た目の決めごと

書体・差し色・警告帯の色・中性色のトークンは `frontend/src/routes/layout.css` に適用済み。
一覧の表示形式とスケール (行の最小高・文字サイズ) は、閲覧側・管理画面のテーブル行とも適用済み。
タップ領域の最小 44px も、閲覧側・管理画面とも適用済み。

- **書体は BIZ UDPGothic** (400 / 700 の2ウェイト)。UD 書体を選ぶのは、閲覧者に生徒と
  非技術者が含まれるため。
  パス・件数・日時・ユーザー名も同じ書体で組み、等幅の書体はコード (マニュアルのコードと、ビューアーで開いたソース) にだけ使う。
  欧文の等幅書体は日本語主体の画面で浮くため。日本のデザインシステム (デジタル庁・SmartHR 等) も、数字や ID は本文の書体で扱い、等幅はコードに限っている。
  BIZ UDPGothic は数字の幅をそろえる機能 (`tnum`) を持たないので、桁を縦に見比べる表示が要るときは別に考える。
- **日本語の文は、題・ボタン・ラベルなどの短い文だけを文節の切れ目で折る** (`word-break: auto-phrase`。`layout.css`)。
  説明文・本文などのまとまった文には当てず、右端まで詰める通常の折り返しにする。
  文節で折ると行ごとに右端が空いてでこぼこになり、まとまった文では箱の形に組むほうが読みやすいため。
  CSS の仕様も OS (Android・Apple) も、文節で折るのを見出しやラベルなどの短い文に向けたものとしている。
  `auto-phrase` が効くのは Chrome だけで、Safari は通常の折り返しのまま。
  - 当てるかは部品の種類で決める (CSS では行数で切り替えられないため)。新しい部品が短い文を出すなら、`layout.css` の並びに足す。
  - 打っている欄 (textarea・input・contenteditable) は、通常の折り返しにする。打つたびに行の切れ目が動かないように。
  - 全体に `line-break: strict` を当て、行頭に「ー」や小書きの仮名が来る折れ (「プライバシ／ーポリシー」) を禁則で防ぐ。
  - まとまった文で、語の途中で折れると困る語は、`whitespace-nowrap` の要素で包む。
  - 短い文で文節の判定が外れたときは、`<wbr>` かゼロ幅スペースで折り返し位置を足す。
  - 日本語には `text-wrap: balance`・`pretty` を使わない。balance は右端を空けたまま語の途中で折り返し、pretty は Safari (WKWebView) で段落全体の行の長さを揃えて右端がでこぼこになるため。
    部品 (shadcn-svelte) が説明文に付ける `text-balance`・`text-pretty` も、`layout.css` で日本語のときだけ `text-wrap: wrap` に戻す。
  - 数 (数が入るプレースホルダーを含む) と単位の間 (「3 件」「{count} 件」「1.0 KB」) は、半角の空白の代わりにノーブレークスペース (U+00A0) を置く。普通の空白だと「3／件」と折り返すため。
    見えない文字で書き直すと戻りやすいので、`ja.json` は `messages.spec.ts` で見る。
- **保存する画面で、空のままでは保存できない欄のラベルに赤い＊を付ける** (`Field.FieldLabel` の `required`)。
  パスワードの確認欄のように、保存する値を確かめる欄も含む。ログインのように何も保存しない画面では付けない。
  入力が必須かどうか (HTML の `required`) ではなく、保存するデータとして欠かせないかで決める。
- **入力の誤りと押せない状態は、欄に加えて `Field.Field` にも示す** (`data-invalid`・`data-disabled`)。
  欄だけに付けると、ラベルと説明が普段の見た目のまま残り、どの項目のことかが目で追いにくいため。shadcn-svelte の既定の示し方に揃える。
- **行ごとのスイッチ・チェックボックス・ボタンは、読み上げの名前に行の名前を入れる** (「2024_リスニング.mp3 を公開」)。
  見た目は列の見出しと行の位置で分かるが、Tab で操作だけを渡り歩いたり、読み上げの操作の一覧から選んだりすると、どの行のものか分からないため。
  WCAG は同じ名前の繰り返しを禁じていないが、GOV.UK のデザインシステムは行の操作に項目名を足すよう求めている ([Summary list](https://design-system.service.gov.uk/components/summary-list/))。
  Select のトリガーに名前を付けるときは、選んでいる値も入れる (「admin の権限: 管理者」)。トリガーはボタンなので、名前を付けると見えている値が読み上げられなくなるため。
  アイテムの行の名前はタイトルではなくパスにする。タイトルは同じものが並びやすく、行の見分けはパスに頼るため。
- **説明文 (項目の下の補足・見出しの下の文・ダイアログの本文) は、置かないのを既定にする**。
  部品に説明の枠があっても埋めない。多数派のアプリの説明文は「何をするか」「オンにした結果」「書式」が中心で、仕組みや注意の重ね書きは少数派のため。指針 (GOV.UK・Shopify Polaris・Apple) も、補足は要ると分かってから足すとしている。
  - 置くのは次の場合だけ。どれも1〜2文にする。
    - 取り返しの付かない操作の確認: 題で問い、本文で何が消えるか・戻せないかを書く。
    - 入力の条件: 書式・例・制約。
    - 結果が見えにくい設定 (データを送る・安全に関わる・次の起動から効くなど): オンにした結果を書く。
    - 外へ送るもの: 何をどこへ送るかを書く。経路 (中継のサーバー) は書かない。
  - ほかの設定との関係 (「〜するまでは使えません」) は常に出さず、使えない状態のときだけ、その理由を出す。
  - 書かないもの: 項目名の言い換え、見れば分かること (空のときやオフのときの裏返し、押すと出るものの中身)、仕組みや例外の網羅、念のための注意の重ね書き。仕組みはマニュアルか `docs/<テーマ>.md` に置く。
  - 説明が要ると感じたら、先に項目名や画面の作り (使えないときは押せなくする など) で直せないかを見る。
  - 書くときは、条件を「何を・どうすると」まで書き、目的語を省かない (「登録すると」ではなく「『共有』を登録すると」)。
    起きることは「〜すると、〜ます」で書く (「番号を変えると、ブックマークや配った QR コードでは開けなくなります」)。
  - 設計の文書やコードの語を、そのまま画面に出さない。
- **入力欄・選択の地は面の色 (`#FFFFFF`) にする**。地 (`#F7F7F5`) の上に置いたとき、欄の地が透けて地と同じ色になり、押せない欄に見えたため。
- **桁に上限のある数の欄は、全幅にせず上限の桁が収まる幅にし、単位は欄の枠の中の末尾に置く** (input-group の `inline-end`)。
  全幅だと短い数に大きな箱が並んで間延びし、何を入れる欄かも読み取りにくいため (デジタル庁・SmartHR のデザインシステムも、幅は入れる内容に合わせるとしている)。
  同じ区画に並ぶ欄で桁の差が小さいときは、単位を含めた外側の幅を揃えて右端を一直線にする。単位はラベルに重ねて書かず、読み上げには `aria-describedby` で欄に結ぶ。
  欄は `type="number"` にせず、`inputmode="numeric"` の文字の欄にする (`integer-input.svelte`)。`number` はホイールで値が変わり、上下の矢印が単位との間に割り込むため (GOV.UK のデザインシステムも避けるよう勧めている)。範囲の外の値は、部品がブラウザーの検証に載せて保存を止める。
- **中性色を地に、差し色は1色** (`#146E6B`)。コンテンツ (画像・PDF・音源の
  タイトル) が主役になるよう、UI 自体は後ろに下げる。
  ライトテーマの中性色は面 `#FFFFFF` / 地 `#F7F7F5`、文字が本文 `#1A1A18` /
  副 `#5A5A55` / 補助 `#6B6B64`、罫が `#E4E4DF` (面の境界) と `#EFEFEB` (行の
  区切り)、入力欄・絞り込みの枠が `#CFCFC8`。ダークテーマは同じ役割の対応色を、コントラスト基準を満たす形で
  用意する。
  基準は、文字と背景の組み合わせが 4.5:1 以上、方向を示すグリフなど非テキストの要素が 3:1 以上。ライトでもダークでも
  満たすこと。罫線はこの基準の対象外。
- **閲覧側の一覧は、既定を1列のリストにし、利用者がタイルに切り替えられる**。
  既定のリストは、閲覧者が上から順に目で追う使い方 (授業中に次の音源を選ぶ) のため。
  タイルは、PC や横向きの iPad のように幅の広い画面で、一画面に入る件数を増やすため (リストは1行が端から端まで伸び、横が空く)。
  管理側は情報密度が要るのでテーブルのままにする。
  - リストの行は、アイコン・タイトル・補助テキストを横一列に置き、行同士を罫線で区切る。行の右端には、操作できる人にだけ⋮のメニューを置く。
    遷移を示す「›」は置かない。⋮と並べると、どちらを押すと何が起きるかが紛らわしく、行のどこを押しても開くことは行の作りで分かるため。
    新規タブで開くものだけ、タイトルの文字のすぐ後ろに印 (↗) を置く。右端に置くと⋮と並び、どの行の何の印かが読み取りにくいため。
  - タイルは、上に 16:9 の帯を端まで置き、下にタイトルを2行まで (超えた分は「…」)、その下に補助テキストを2行まで、左寄せで置くカードにする。リンクは補助テキストの代わりに説明とサイト名を1行ずつ置く (→ 「リンクのカード」)。
    リンクは帯に画像を敷き (→ 「リンクのカード」)、ほかは淡い色の帯の中央に縮小画像かアイコンを 72px で置く。リンクと同じ一覧に混ざるので、帯の高さと文字の位置を全部のタイルで揃えるため (Google ドライブのグリッドと同じ形)。
    72px は、縮小画像 (一辺 144px、→ 「画像のプレビュー」) が画面密度2倍でもぼやけない大きさ。帯いっぱいに広げないのも同じ理由。
    列の数は幅で決め、1枚が 170〜230px ほどに収まるようにする (スマートフォンで2列、横向きの iPad で5列)。
    新規タブの印はリストと同じくタイトルの後ろに置き、右上の隅には⋮のメニューを置く。
  - 切り替えは、一覧の上の段の1段目の右端に、リストとタイルのアイコンを並べて置く (Google ドライブのリストとグリッドの切り替えに倣う)。検索の画面も同じ (語の欄の右)。
    上の段は `browse-controls.svelte` で組む。1段目は、どの一覧でも並び順・名前の絞り込み・切り替えの3つで、絞り込みを余りまで伸ばす。アーカイブの軸は2段目に並べる。1段目に混ぜると、軸の数と幅しだいで絞り込みの大きさと段の切れ目が変わり、形が落ち着かないため (絞り込みを上限つきで伸ばして軸と同じ並びに置く形、絞り込みを1段目に単独で置く形と比べて、ユーザーが選んだ)。
    狭い幅では、並び順と切り替えを1段目に、名前の絞り込みを次の段に幅いっぱいで置く。並び順の無い一覧と検索の画面は、語の欄を伸ばして切り替えと1段に収め、検索の範囲は2段目に置く。
    スマートフォンの幅で、段ごとに使い方がばらけず、欄の右に空きを残さないため。表示の操作を一覧の直上の細い段にまとめる形 (スマートフォン版の Google ドライブ) と、「表示」のボタンにたたむ形 (iPhone の「ファイル」) と比べて、ユーザーが選んだ。今の部品のまま変わる所が少なく、PC の幅でも同じ形でいられるため。
    語の欄 (名前の絞り込み・検索の語) は、並び順と同じく枠の中に項目名を置く形にそろえる (`labeled-input-box.svelte`)。
    選んでいる側を淡い差し色で塗る。並び順と違い、2つの印が並ぶ形では、どちらを選んでいるかを塗りで示すしかないため。
    一覧が空のときは、並び順と同じく出さない。
  - 選んだ並べ方は、閲覧側の一覧すべてに効かせ、その端末のブラウザーに覚えさせる。
    画面ごとに覚えると、どこで何を選んだか分からなくなるため。
    ログインしない閲覧者もいるので、アカウントには持たせない。
- **閲覧側の行とタイルは、どこを押してもタイトルのリンク (音声は再生のボタン) が効く**。
  中身はタイトルを包むリンク1つで、押せる範囲だけを行・タイルの枠いっぱいに広げる (コンテンツ管理の表と同じ作り)。
  2段目に別のボタン (検索の結果の場所) を置けるようにするため。リンクの中にボタンを入れ子にはできない。
  キーボードのフォーカスの枠は、行・タイルの枠に出す。新しいタブで開くこと・再生中であることは、読み上げにはリンク・ボタンの名前で渡す。
- **ホームとグループの一覧では、書き換えられる行 (管理者と作成者のもの) の右端に、編集ページへ移るペンを置く** (見出しのペンと同じ絵)。非表示のコンテンツの一覧も同じ。
  **項目が常に1つしかないものは⋮のメニューにしない**。開く手間が増えるだけなので、その操作のボタンを直に置く (ユーザーの編集ページの「パスワードを再設定...」も同じ)。人や種類によって項目の数が変わるもの (共有の中の行・スマートフォンの幅のコンテンツの編集ページの見出しの段) は、1つになる場合があっても⋮にする。同じ場所の形が、人や種類で変わらないようにするため。
  公開範囲 (非表示にする・戻すを含む) も、ほかの項目と同じく編集ページで変える。一部の項目だけを一覧から変える口を持つと、同じ値を変える場所が2つになり、選べる値の判定も2か所で保つことになるため。
- **ホームとグループの画面では、ログインした人に、見出しの段の右に「追加」を置き、「リンク...」「ショートカット...」「グループ...」を選ばせる** (`content-add-menu.svelte`)。見ている場所に足したくなったときに、管理画面へ移って親を選び直さずに済むようにするため。形は共有の画面の「追加」に揃える。
  窓は管理画面の「コンテンツを追加...」と同じもので、種別を選ぶ段を飛ばして入力の段から開き、作ったら同じく編集ページへ移る。グループの画面ではそのグループの中に作る。他人の「作成者のみ」のグループには置けないので出さない (`canAdd`)。
  窓は親を重ねた見え方を出すのに管理用の一覧 (→ access.md「管理用の一覧が `user` に見えること」) を使い、閲覧の応答には祖先の公開範囲が無いので、押したときに取る。
- **ホームの一覧の下に、ログインした人が使える共有を「共有」の区画で並べる**。
  行の2段目には、その人が中でできること (「読み取り専用」「追加のみ」「フルアクセス」) を出す。読み取り専用の共有に追加の口が無い理由を、開く前に分かるようにするため。
  同じ行を並べた画面 (`/shares`) を、共有の中のパンくずの「共有」から開く。
- **共有の中の画面 (`/shares/[id]`) は、フォルダーの画面と同じ一覧に、その人に許された操作を重ねる**。
  パンくずは「ホーム / 共有 / 共有の名前 / …」。そこをホームに載せたコンテンツがあれば、見出しの下に「ホームに「X」として掲載中」と出してそのコンテンツへつなぎ、載せている行には2段目の頭に「掲載中」を置く。消す・名前を変える前に、ホームで見えているものに響くと分かるようにするため。「非表示」のコンテンツはホームに出ないので、掲載中としない。
  - 足せる場所 (追加のみ・フルアクセス) では、見出しの右に「追加」を置き、「アップロード...」「新しいフォルダー...」を選ばせる。行の⋮には「名前の変更...」「移動...」「コピー...」「ダウンロード」(ファイル)「ホームに載せる...」(まだ載せていないフォルダーとファイル)「削除...」のうち、その人ができるものだけを出す。押してから断られる操作を出さないため (書き換えられないコンテンツに編集の入り口を出さないのと同じ)。足すだけの人には、名前の変更・移動・削除を出さない。
  - アップロードはいくつも選べ (スマートフォンでは写真の一覧からも選べる)、ドロップでも足せる。1ファイルずつ送り、ファイルごとに進み具合を出す。同じ名前があれば番号を付けて置き、画像の拡張子が中身と合わなければ直して置くので、そうしたものは置いた名前を添える。上限を超えるファイルは送らずに印を付ける。
  - 移動・コピーの置き先は、足せる共有の一覧から辿って選ぶ。同じ名前があれば「上書きする」「番号を付ける」「飛ばす」を選ばせ、上書きは置き先でフルアクセスの人にだけ出す。上書きで消えるもの・削除するものは、ごみ箱へ送れる場所かで文言を分け、送れなければ「元に戻せません」と書く。削除と上書きの確認には、開けなくなるか中身が変わるホームのコンテンツを並べる。
  - コピー・移動・削除は裏で続く処理にし、1秒たっても終わらなければ画面の右下に進み具合と「中止する」を出す。画面を移っても出し続ける。すぐ終わる処理で欄がちらつかないよう、1秒待つ。
  - フォルダーのコンテンツの画面でも、その場所が共有の中で操作できる人には、同じ「追加」をペンの隣に置き、行の⋮に同じ操作を出す。中のフォルダーがホームに載っているかはこの画面では分からないので、「ホームに載せる...」は共有の画面に任せる。
- **非表示のコンテンツは、ユーザーメニューの「非表示のコンテンツ (件数)」から開く一覧に並べる** (件数が0なら項目を出さない)。
  非表示のものは閲覧の場のどこにも並ばないため。管理者には全員の、ほかの人には自分のものが並ぶ。
  一覧はホームやグループと同じ部品 (`content-list.svelte`) で並べ、並び順・絞り込み・タイルとリストの切り替え・行の⋮も同じにする。行を押すとそれ自体の閲覧画面が開く。見ている場所が違うだけの一覧なので、操作を揃えるため。
- **再生中の音声の行は、淡い差し色で塗り、左端に差し色の線を引き、再生アイコンの丸を塗る**。鳴っている間は丸の中を一時停止のアイコンにし、押すと止まる (下のプレイヤーのボタンと同じ見た目・動き)。
  同じ題の行が並ぶことがあり、どれが鳴っているかを行でも一目で分かるようにするため。差し色の塗りは「今いる場所」の印で、差し色1色の原則の内。
  タイルでは、左端の線の代わりに枠を差し色にする。「再生中」の文字は読み上げにだけ渡す (幅が狭く、タイトルを押し出すため)。
- **公開範囲の項目名は「公開範囲」とする**。値が一列の段階ではないため、「公開レベル」とは呼ばない。
- **`private` の行には「作成者のみ」と出す**。
  閲覧側の一覧では、行の右端 (⋮があればその左) に、補助色の小さな文字で置く。作成者にしか届かない行なので、ほかの人にも見えていると勘違いさせないため。差し色は使わない。
  タイルでは、補助テキストの行の頭に置く。
  管理画面では、誰のものかは公開範囲に添えず、コンテンツ管理の「作成者」で示す (下の「管理画面の表は横スクロールさせない」)。`admin` には全員の `private` が並ぶため。
- **管理画面の一覧の公開範囲の列には、各行の設定だけを出す**。
  親グループによる実際の見え方は添えない。行は木の形に並ぶので、祖先のグループの公開範囲は木の上の行で分かる。
- **親グループによって実際の見え方が設定より厳しいときは、編集フォームの公開範囲の項目の下に実際の見え方を書く**。
  公開範囲を変えようとしている人に、変えても親で絞られることを伝えるため。
- **「作成者のみ」のグループの中に置くときは、公開範囲を「作成者のみ」にし、選択肢もそれだけにする**。
  中に置けるのがグループの作成者の「作成者のみ」だけのため (→ access.md「作成者のみのグループ」)。
  親の欄でそのグループを選んだときも同じで、すぐ下の公開範囲の欄が変わるので、保存した後に黙って変わることにはならない。
  「作成者のみ」のグループは、そのグループの作成者のものにだけ、親の候補・「中に追加...」を出す。
  ほかの人に出すと、押してから断られるため。
- **中にほかのものがあってグループを「作成者のみ」にできないときは、公開範囲の項目の下に理由を出す**。
  保存してから断られるより先に、何を動かせばよいか分かるようにするため。
- **絞り込みのドロップダウンは軸名を常に見せる**。
  絞り込み中の軸は差し色の枠と淡い塗りにして、「すべて」の軸と見分けられるようにする。
  複数の軸を AND で掛けたとき、どの軸で絞っているかを一目で分かるようにするため。
- **並び順のドロップダウンは絞り込みと同じ形にして、一覧の上に左寄せで置く** (→ 「ホーム・グループ・フォルダー・アーカイブの並び順」)。同じ段の右端には、リストとタイルの切り替えを置く。
  上に小さく「並び順」、下に選んでいる値を出す。閲覧画面で値を選ぶ操作はこの2つしかなく、
  同じ形にしておけば画面をまたいでも迷わない。
  **差し色の強調はしない**。絞り込みと違って常に何かが選ばれており、強調すると
  「絞り込み中」の印と見分けが付かなくなるため。
  一覧が空のときは出さない。
- **絞り込みと並び順のドロップダウンは、読み上げで「ボタン」になるが直さない**。
  bits-ui の Select のトリガーは role を持たない `<button aria-haspopup="listbox" aria-expanded>` なので、一覧を開くことと開閉の状態は伝わる。
  shadcn の `select-trigger.svelte` を改変して `combobox` を上書きすると、bits-ui のキー操作 (`aria-activedescendant` で選んでいる選択肢を指す作り) と食い違う恐れがあるため。
- **大きさ・余白・文字サイズは Tailwind の標準の段階から選ぶ**。
  キャンバスの数値がどの段階にも乗らないときは、近い段階に丸める (例: 17px → `text-lg` の 18px)。
  ピクセル単位で合わせた半端な値が画面ごとに増えると、かえって揃わなくなるため。
- **画面の題の大きさは、画面の種類で3段に分ける**。
  - ホーム: 24px、幅 640px (`sm`) 以上で 30px の太字。サイトの顔として題を大きく出す
  - 読み物 (マニュアル・ライセンス): 24px の太字。本文の h2 (20px) より大きくする (→ help.md)
  - 一覧と管理画面 (グループ・フォルダー・アーカイブ・管理): 18px (`pageHeadingTextClass`)。見出しの帯を低くして中身を多く見せる
    1つにそろえると、マニュアルの題が本文の h2 より小さくなるか、一覧の見出しの帯が太くなるため。
- **余白と区切り: 縦の間隔は3段にし、近いものほど詰める**。間隔が1種類だと、どれが組なのかを読み取れないため。
  値はデジタル庁と SmartHR のデザインシステムの余白に合わせた。
  - 組の中 (ラベル・入力欄・その説明、表とその件数): 8px (`gap-2`)
  - 区画の中の組と組: 24px (`gap-6`)。フォームとダイアログの項目の間、画面の見出しの段と中身の間も同じ
  - 区画と区画: 48px 空け、中ほどに罫線を引く (サイト設定は下の「サイト設定の区画」)
  - 区画の見出しは、中のラベルより一段大きくする (`text-base`)
  - 区画の中で性格の違うまとまり (語の候補など) は枠で囲む
- **ダイアログは画面の高さに収め、届いたら見出しと足 (確定・取り消しのボタン) を残して間の本体だけをスクロールさせる** (`Dialog.Body`)。
  ダイアログ全体をスクロールさせると、項目の多いフォームや結果の一覧で、確定のボタンと何のダイアログかが画面の外に出るため。
  確定すると起きることの警告 (置き換わる・消えるなど) は、本体の先頭に置く。末尾に置くと、スクロールしないと見えないまま確定できてしまうため。本体の外に固定すると、スクロールする範囲がその分狭くなる。
  ただし、欄を変えた時点で出る警告は、変えた欄のすぐ下に置き、出たら見える所まで送る。先頭に差し込むと、押した欄が押し下げられて画面の外へ出るため。
- **サイト設定の区画はカード (枠で囲んだ面) にし、幅 1024px (`lg`) 以上で2列、1536px (`2xl`) 以上で3列の石垣に並べる** (`frontend/src/lib/masonry.ts`。class は `page-layout.ts` の `sectionGridClass`・`sectionCardClass`)。コンテンツの編集ページも同じ並べ方にする (→「編集ページの区画」)。それより狭い幅では、1列で 576px までにする。
  区画が6つあり、1列で幅を絞ると PC の広い画面の右半分が空くため。区画ごとに中身の量が大きく違い、高さを揃えた格子にすると短いカードの下が空くので、上から順に短い列へ詰める。
  区画の並ぶ位置は幅と中身の量で変わり、読む順は横にも縦にも揃わない。区画ごとに保存し、互いに関係しない区画なので、読む順よりも一画面に入る量を取った。
  設定の画面の多数派は、本文を1列に絞り、空いた側はそのまま残す形 (2026-10 に 18 件を数えて、区画をカードの格子に並べる例は無かった)。
- **閲覧側と管理側でスケールを変える**。同じ部品のまま、閲覧側は要素を削って
  操作単位を大きく、管理側は情報密度を上げる。
  閲覧側の一覧は、行の最小高とタイトルの文字サイズをトップからフォルダーまで揃える。
  画面を移るたびに文字の大きさが変わると、同じ種類の一覧に見えないため。
  ファイル名がそのまま出るスマートフォン幅のフォルダー一覧だけ、一段小さくする。

  | 一覧                                             | 行の最小高 | タイトル |
  | ------------------------------------------------ | ---------- | -------- |
  | トップ・グループ・アーカイブ一覧・フォルダー一覧 | 72px       | 18px     |
  | フォルダー一覧 (スマートフォン幅。名前が生)      | 64px       | 16px     |

  行の2段目 (ホーム・グループの説明、アーカイブの軸の値、フォルダーのサイズと日時) も
  4つの一覧で揃え、スマートフォン幅では 12px、それ以上では 14px にする。
  タイトルと同じく、画面を移るたびに大きさが変わらないようにするため。

  管理画面のテーブル行は 44px。
  **タップ領域はどの画面でも最小 44px を確保する**。
  主・副の操作のボタン (フォームやダイアログの確定・取り消し、画面の追加ボタン) は、見た目ごと 44px にする。
  見た目が小さいと、押せる範囲を広げていても、正確に押そうとする心理的な負担が大きくなるため。
  特に確定と取り消しが並ぶ場面で、取り消しを押し間違えないよう気を張らせない。
  ヘッダーのボタン、表の行の中の操作、アイコンボタンは見た目の大きさを変えず、押せる範囲だけを広げる。
  管理側の情報密度と、表の行 44px を保つため。
  項目が隣り合うメニュー・選択肢と、折り返すパンくずは広げると重なるので、実際の高さを 44px にする。
  メニューの項目は、右の余白を 16px にする (左は 6px)。メニューの幅は一番長い項目で決まるので、右を詰めると項目の右端が縁に付いて窮屈に見えるため。最低の幅は 128px のまま。
  入力欄 (`::after` を持てない) と、それと並ぶ Select のトリガー・タブも実際の高さを 44px にする。
  表の中の入力欄は、セルの上下に余白を取る。行は 44px を超えてよい。余白を詰めると入力欄が行にぴったりはまり、窮屈に見えるため。
  表の中の Select のトリガーは、行 44px を保つため見た目を小さいまま押せる範囲を広げる。

- **文字のリンクは常に下線を付ける**。ポインタを載せたときだけ下線を出すと、ポインタの無い iPad ではリンクに見えないため。
  デジタル庁デザインシステムも、リンクには常に下線を付けている。
  本文の中のリンク、単独で置いた補助のリンク (ログイン画面の案内、マニュアルの目次の下など)、パンくず、戻るリンクが対象。
  文字のリンクに見せたボタン (shadcn の `link` の形) も同じにする。
  行ごとのリンク (一覧の行・表の行のタイトル)、タブ、ヘッダーの操作は、置き場所と形でリンクと分かるので付けない。
  検索の結果の行の場所 (→ search.md「画面」) も付けず、頭のフォルダーの絵で押せることを示す。どの行にも出るので、常に下線を引くと結果の題より目立つため。
- **ヘッダーの操作には枠を付けない**。
  言語・テーマの切り替えはアイコンだけ、ログインとユーザーメニューはアイコンと文字 (ログイン・ユーザー名) にして、補助色で置く。
  UI を後ろに下げるため。
  スマートフォン幅では、ログインの文字を読み上げにだけ渡してアイコンだけにする。幅 320px では、文字まで並べるとロゴとの間がほとんど残らないため。
  アイコンは言語が地球儀、テーマが今の見た目 (ライトは太陽、ダークは月)、ログインが入口へ入る矢印。
  ロゴ (WebLAV) は下げずに、18px の太字で置く。操作ではなくアプリの名前の顔であり、他のサービスでも左上のロゴは主張させているため。
  ヘッダーの高さと左右の余白は、スマートフォン幅で 52px / 16px、タブレット以上で 56px / 24px。
  右端の操作は文字の端を余白の線に揃え、押せる範囲は余白に食い込ませる。
  操作同士は 2px だけ空けて並べ、**タップ領域 44px の例外として、押せる範囲の横幅が 44px を割ることを許す** (WCAG 2.2 AA の 24px は満たす)。
  押し間違えても別のメニューが開くだけで、選ぶまで何も変わらないため。
  検索の結果の行の場所も同じ例外にし、押せる範囲を行の下の余白の側へ広げるだけにする (高さ 30〜34px)。上へ 44px まで広げると、行のタイトルの押せる範囲を削るため。
- **管理画面は閲覧側と同じヘッダーを使い、その下に画面を切り替えるタブ (コンテンツ・ユーザー・共有・操作の記録・サイト設定) を置く**。
  サイドバーは持たない。
  切り替える画面が数個しかなく、スマートフォン幅ではサイドバーを畳むメニューがヘッダーにもう1つ要るため。
  タブは絵と名前を並べ、選択中を差し色の下線で示す。
  **スマートフォン幅では、選んでいないタブを絵だけにし、選んでいるタブは絵と名前を出す**。
  5つの名前を並べると1行に収まらず、タブの文字が折り返すため。今いる画面は名前で分かるようにする。絵だけのタブも、読み上げ用の名前を持たせる。
  タブと本文の左右の余白は、ヘッダーと同じにする。
  「共有」のタブは、どの端末の管理者にも出す。追加だけがサーバーの PC に限られる (→ folders.md「共有」)。
  ユーザーメニューの「管理」はコンテンツ管理を開く。カードを並べるだけの管理トップは置かない。
  管理画面は `admin` 専用なので、`user` のユーザーメニューには「管理」を出さない (→ access.md「ロールと操作」)。
- **コンテンツの編集ページの戻るリンクは、`admin` にはコンテンツ管理の一覧、`user` には閲覧の場でそのコンテンツが並ぶ所 (親のグループかホーム) を指す**。`user` は閲覧の画面から編集ページへ来て、管理画面を開けないため。削除した後も同じ所へ移る。
  コンテンツの編集ページの中のタブ (設定・分類・ファイル・対象外) は、同じ形で地の色のまま置く。上段と同じ白い帯にすると、タブが2段に重なって見えるため。
- **管理画面の共有の行には、一般ユーザーができること (「読み取り専用」) と例外の人数を出す。行のどこを押しても、その共有の編集ページ (`/admin/roots/[id]`) へ移る**。
  ⋮には「編集」と「削除...」だけを置く。名前・権限・場所はどれも編集ページで変える。
  名前の変更と権限をダイアログに分けていたが、場所の選び直しが加わって操作が4つになり、コンテンツと同じく1件を1ページで直す形にそろえた。
  - 編集ページはコンテンツの編集ページと同じ作り。上に「‹ 共有」の戻るリンク、見出しの下に中のコンテンツの件数と、一覧の行と同じ知らせ (つながらない・見つからない) を出す。
  - 区画は「場所」「名前」「権限」のカードにし、石垣に並べる (→「編集ページの区画」)。名前と権限は区画ごとに保存し、変えるまで保存ボタンを押せない。保存すると、区画の見出しを入れた知らせ (「「名前」を保存しました。」) を出す。
  - 「場所」の区画にはフルパスと「フォルダーを選び直す...」を置く。追加と同じ OS の窓で選び、違うフォルダーなら、中のコンテンツの件数を添えた確認の窓を出してから変える。中のコンテンツの登録先も移るため。同じフォルダーなら何も変えず、知らせも出さない。窓はサーバーの PC にしか出ないので、ほかの端末ではボタンの代わりに案内を出す。
  - 「権限」の区画では、一般ユーザーの既定とユーザーごとの例外を選ぶ。管理者はどの共有でもすべての操作ができるので、選べるのは一般ユーザーの権限だけ。
    例外は、既定と違う人だけを並べる。「例外を追加」で一般ユーザーを選ぶと、その時点の既定で行が増え、行の選択で権限を変える。行の×で外すと既定に戻る。足せる人がいないときは「例外を追加」を出さず、一般ユーザーが1人もいないときは、その旨だけを出す。全員を並べると、既定と違う人が「既定のまま」の行に埋もれるため。Google ドライブや Dropbox の、相手を選んでから権限を決める形に倣った。
  - 「共有を追加...」で追加したら、その共有の編集ページへ移る。コンテンツの追加と同じく、続けて名前や権限を決められるようにするため。
- **管理画面の一覧 (コンテンツ・ユーザー・共有) は、どれも行のどこを押してもその1件の編集ページへ移る**。1件を直す操作は編集ページにまとめ、一覧の⋮には「編集」と「削除...」 (コンテンツは、ほかに「閲覧画面で開く」など) を置く。
- **管理画面のユーザーの一覧の権限は見るだけにし、行を押して開く編集ページ (`/admin/users/[id]`) で変える**。
  一覧の⋮には「編集」と「削除...」だけを置く。
  - 編集ページは共有の編集ページと同じ作り。上に「‹ ユーザー」の戻るリンク、見出しの段の右に「パスワードを再設定...」、見出しの下に作成日を出す。消したら一覧へ戻る。
  - 区画は「ユーザー名」「権限」のカードにし、区画ごとに保存する。変えるまで保存ボタンを押せず、保存すると区画の見出しを入れた知らせを出す。権限は「管理者」「一般ユーザー」の丸ボタンで選ぶ。
  - 共有ごとの権限は、ユーザーの編集ページには出さない。共有の編集ページの「権限」の区画だけで決める。
  - 「ユーザーを追加...」で追加したら、そのユーザーの編集ページへ移る。追加の窓ではユーザー名とパスワードだけを入れ (→「作成の入力は必要最小限にする」)、権限は続けて編集ページで決める。
- **管理画面のユーザーの一覧: 自分の行は、名前に「(あなた)」を添えた押せない行にし、⋮も出さない**。自分の編集ページも開けない (URL を打っても見つからない扱い)。
  自分を直したい人はユーザーメニューの「アカウント」から入るので、一覧の行に入口は要らない。押すと /account へ移す形と比べて、管理画面のタブの外へ出てしまう不便のほうが大きいとユーザーが選んだ。
  押せない行が壊れて見えないよう、自分の行だけは指を重ねても塗らない。自分の降格と削除はほかの管理者がする (→ access.md「ロールと操作」)。
- **アカウントのページ: ユーザー名・パスワード・リカバリコードは `/account` に区画のカードで並べ、区画でじかに直す**。ユーザーメニューには「アカウント」の1項目だけを置く。
  - ユーザーメニューの並びは、見出しの名前・アカウント・管理ページ・非表示のコンテンツ・マニュアル・(線)・ログアウト。自分の設定は名前と結び付くようすぐ下に、押すと画面を出てしまうログアウトは線で離して最後に置く (アカウントのメニューの多くの並び)。
  区画の並べ方と保存の仕方は、ユーザーの編集ページと同じ (→ 「編集ページの区画」)。
  - 区画に「現在のパスワード」の欄は置かない。確定したときにサーバーが求めれば、パスワードのダイアログを出す (→ access.md「操作の前のパスワードの確認」)。区画ごとに欄を置くと同じ欄が3つ並び、どれに打つのか迷うため。
  - リカバリコードの区画には、作ったかどうかと作った日を出す。持っているときのボタンは「作り直す...」で、前のものが使えなくなることを確かめてから作る。作ったコードはダイアログで1回だけ見せる。
  - 項目ごとのページへ移る形 (Google アカウント・bp-carnet の設定)、ページを開くと先に一度だけパスワードを聞く形と比べ、ユーザーが選んだ。
- **パスワードの確かめ直しのダイアログ: 題は「パスワードの確認」、欄は「現在のパスワード」1つ、ボタンは「キャンセル」と「確認する」**。違うときは閉じずに欄の下へ理由を出す。やめたときは、元の操作の失敗として知らせない (自分でやめたため)。
- **「操作の記録」のタブに、操作を新しい順に並べる** (→ operations.md)。続きは「さらに読み込む」で足す。
  タブレットより広い幅では、「日時 (下に IP アドレス)」「ユーザー」「操作」「対象」の列に並べ、いつ・誰が・何を・何にを横に見比べられるようにする。Google Workspace・Microsoft 365 の監査ログも、広い幅では列に並べる。どの列も隠さない (隠すと、その操作が何だったかを読み取れなくなるため)。
  スマートフォンの幅では、1件を数段に積む。4つの列を並べると、どれかを隠すか横に送ることになるため。
  上に「種類」と「ユーザー」の絞り込みを置き、閲覧画面の絞り込みと同じドロップダウンにする。GitHub・Google Workspace の監査ログも、操作の種類と操作した人で絞り込む。絞り込みは URL のクエリに持たせ、戻る操作で前の絞り込みに戻れるようにする。
  編集は、変えた項目を1項目1行で「項目: 前 → 後」と添える。値を残さない長い文の項目は、最後の1行に名前だけを並べる (「変更: 説明、対象のパターン」)。日時の後に、操作した端末の IP アドレスを出す。
- **管理画面の一覧は、本文の余白を越えて端から端までの白い帯に置き、上下に罫を引く**。
  端の列の文字は本文の余白の線に揃える。
  表を地の上にじかに置く画面と帯に置く画面が混ざり、管理画面の一覧の見た目が2通りになっていたため。
  キャンバスのコンテンツ管理は余白の内側の白い枠だが、実装はこちらに揃える。
- **管理画面の各画面の見出し (`h1`) は、タブの名前と同じにする** (「コンテンツ」「ユーザー」「共有」「操作の記録」「サイト設定」)。タブと見出しで呼び名が違うと、同じ画面か迷うため。
  見出しの段 (`adminPageHeaderClass`) と中身の間は 24px。一覧も表も本文の外枠 (`adminPageClass`) の中に置く。一覧が空のときは、同じ外枠の中に「〜はまだありません。」の形で書く (`adminEmptyTextClass`)。
- **編集ページへ移る項目は「編集」と書き、「...」を付けない** (上の「ボタンラベル」の、別ページへの移動)。窓を開く分類の「編集...」とは分ける。
- **名前を変える項目は「名前の変更...」と書く**。窓の見出しは「「X」の名前の変更」、確定は「変更する」。
  開いたら今の名前を選んだ状態にし、打てばそのまま置き換わるようにする。少しだけ直すことも、付け直すこともあるため。変えるまで確定を押せない。
  ほかの入力の窓も、送れる形になるまで確定を押せない (パスワードの再設定は、2つの欄を埋めるまで)。
- **保存していない変更があるまま別の画面へ移ろうとしたら、「変更を破棄しますか？」と確かめる** (`leave-guard.svelte.ts`・`leave-confirm-dialog.svelte`)。
  区画ごとに保存する画面 (コンテンツ・共有・ユーザーの編集ページ・サイト設定) が対象で、どの区画の変更でも出す。区画ごとに保存するので、片方を保存したつもりでもう片方の書きかけを失いやすいため。
  タブを閉じる・再読み込みはブラウザー標準の確認に任せる。保存中に移ろうとしたら、保存が済んで変更が残っていなければそのまま移る。消した・バックアップから戻した後の移動では確かめない (書きかけに意味が無い)。
- **管理画面の表は横スクロールさせない。狭い幅では優先度の低い列から隠す**。
  隠した列の値は、行を編集すれば確かめられる。
  横スクロールさせて操作の列を右端に固定すると、固定した列が
  スクロールしていない状態でも下の列を覆い、狭い幅ほどタイトルが読めなくなるため。
  各画面で常に出す列と、幅が広がる順に足す列:

  | 画面                 | 常に出す                         | 足す順                                  |
  | -------------------- | -------------------------------- | --------------------------------------- |
  | コンテンツ管理       | タイトル・公開範囲・作成者・操作 | 種類 → 親 → 場所                        |
  | ユーザー管理         | ユーザー名・権限・操作           | 作成日                                  |
  | 共有                 | 名前・操作                       | 一般ユーザー・例外・コンテンツ (同時に) |
  | アーカイブのアイテム | 選択・タイトル・公開             | パス → サイズ・更新日                   |

  コンテンツ管理の種類は、狭い幅でもタイトルの前のアイコンで分かるようにする。
  コンテンツ管理は、スマートフォン幅では公開範囲と作成者の列も隠し、タイトルの下の2段目に「公開範囲 · 作成者」と小さく出す。
  列のまま置くと公開範囲が字数ぶんの幅を取り、タイトルが1字しか残らなかったため。
  共有も、スマートフォン幅では隠した列の値を名前の下に小さく出す。
  共有の名前の列には、フルパスと警告も名前の下に置き、「…」で切らずに折り返す。パスは見分ける手がかりで、警告は読めないと困るため。
  狭い幅で表をやめて1件を複数段にするのは、SmartHR (「よくあるリスト」)・Shopify の管理画面に倣った。
  つまみと⋮はスマートフォン幅でも残す。
  短い値の列 (種類・公開範囲・作成者) は中身の幅まで縮め、残りをタイトルに回す。
  長い値の列 (親・場所) も中身の幅まで縮めるが、16rem と画面幅の 15% の小さいほうで打ち切って「…」にする。
  余った幅を長い値の列とタイトルで分けると、短い URL の右が空いたまま、タイトルが PC 幅でも切れたため。
  例外はアイテムのパスで、タイトルと余りの幅を分け合い、収まらなければフォルダーの側を「…」で切ってファイル名を残す。
  アイテムのタイトルはテンプレートで作る短い語の繰り返しになりやすく、行の見分けはパスの末尾に頼るため。
  パスの列を隠すスマートフォン幅では、タイトルの下の2段目にパスを出す。
  作成者はどの行にも出す。他人の `private` にだけ添えると、行によって見える情報が変わり、統一感が無くなるため。
  作成者のユーザーを削除した行 (→ access.md「ユーザーの削除と作成者」) は、空欄にせず補助色で「削除されたユーザー」と出す。空欄だと、無いのか読めなかったのかを見分けられないため。
  説明は表に出さない。列を増やすほど、狭い幅で最初に見たいタイトルが押し出されるため。

- **行の操作は⋮のメニューにまとめる**。ボタンを並べると操作の列が広くなり、
  タイトルに渡せる幅が減るため。
  例外は、その場で値を切り替えるもの (ロールの選択)。
  メニューに入れると、開いて選ぶ2手になるうえ、今の値が見えなくなる。
  アーカイブの値の辞書の行と軸の一覧を並べ替える上下ボタンも例外にする。1行を何段も続けて動かすので、1段ごとにメニューを開かせない。
  軸の一覧の「編集」「削除」も⋮にまとめずに並べる。軸は多くても数個で、左のカラムの幅も並べる前提で取っているため。
  上下ボタンのある2つは、マウス・タッチは行頭のつまみのドラッグ、キーボードは上下ボタンで並べ替える。
  ドラッグは svelte-dnd-action に任せ、掴んだ行をポインターに付けて運び、周りの行をその場で動かして落とす位置を空ける。
  つまみを押しただけで動かしていない間も、行を半透明にする。軸の一覧は枠を付け、値の辞書の表の行は背景を塗る。
  落とす位置を線だけで示す作りは、iPad の実機で「ドラッグが始まったか分からない」と使いにくかったため。
  つまみはどの幅でも出し、上下ボタンは lg 以上だけに出す。キーボードを使うことの少ないスマートフォン・タブレットの幅では、行の幅をつまみと入力欄に回す。
- **コンテンツ管理の一覧は、行頭のつまみをグループの行へドラッグ&ドロップして親を付け替えられる**。
  svelte-dnd-action の dndzone (上記の並べ替え用) はドロップ先を「どのゾーンの何番目か」でしか表せず、
  行の上に落とす操作は持たないので、Pointer Events を直接使う実装にする
  (→ `reparent-drag.svelte.ts`)。ネイティブの HTML5 Drag and Drop (`draggable` + `dragstart`/`drop`)
  は使わない。iPad Safari はポインター・外部トラックパッドからは発火するが、指でのタッチ操作からは
  確実に発火しないため。掴んだ行は元の位置で薄くし、その複製を指 (ポインター) に付けて運ぶ。
  落とし先の行が光るだけだと、iPhone の実機で「ドラッグできない」と受け取られたため。複製は、下で光る落とし先の行が透けて見えるよう半透明にする。ドロップ先は group の行だけで、自分自身・自分の子孫へは落とせない
  (循環参照防止、当てても何も起きない)。「作成者のみ」のグループへは、その作成者の「作成者のみ」の行だけを落とせる (→ access.md「作成者のみのグループ」)。親の付け替えで実際の見える範囲が広がるときは、
  編集ページの保存と同じ確認ダイアログを挟む。
  ルート直下へ戻すときは、グループに入っている行を掴んでいる間だけ、表の見出しの行を落とし先に変えて、そこへ落とす。
  画面の上端に固定した帯では、iPhone の実機で指から遠く、出ていることに気づかれなかった。
  グループでない行に落とすと同じ階層へ移す形は、ルート直下が全部グループだと戻せなくなるので取らない。
  見出しの行は元から場所を取っているので、行を押し下げず、掴んでいる指の下の行もずれない。見出しの文字は幅を保ったまま隠し、列の幅も変えない。
  掴んだまま画面の上下の端 (上は落とし先が見えていればそのすぐ下) に近づくと、一覧が自動でスクロールする。見出しの行がスクロールで隠れていても、上の端で一覧を戻せば出てくる。
  つまみは指でのスクロールを止めているので、画面の外の行へ運ぶにはこれが要る。
  キーボード・読み上げの代わりは編集ページの
  「親グループ」欄 (既存) で、ドラッグと同じ操作をキーボード向けに別途は用意しない
  (任意の行への移動を1操作の並べ替えボタンで表せないため)。
- **コンテンツ管理とユーザー管理の表は、行のどこを押しても編集ページへ移る**。
  ⋮メニューの「編集」だと2手かかり、iPad では小さな⋮を狙う負担も大きいため。
  中身はタイトルのリンク1つで、押せる範囲だけを行いっぱいに広げる。キーボードや読み上げではリンク1つに見える。
  ⋮メニューはその上に重なって、これまでどおり押せる。
  ただし、親を付け替えるつまみの下には広げず、そこだけを空ける。iOS はリンクの上に重ねたつまみを長押ししても、リンクの長押しとしてメニューを出し、ドラッグが始まらないため。リンクの長押しのメニューと、リンクそのもののドラッグも止める。
  ⋮の押せる範囲は、縦 44px、横は操作の列のセルの余白まで (右は画面の端まで。どの幅でも) 広げる。スマートフォンでは親指が⋮より右に当たりやすく、右の余白が行のリンクに当たると、メニューを開くつもりで編集ページへ移ってしまうため。
- **コンテンツの編集ページの見出しの段の右に、「再スキャンする」(ライブラリを書き換えられる人だけ)、「閲覧画面で開く」を置く**。設定・分類・ファイル・対象外のどのタブでも同じ所に出すため。削除は設定のタブの「削除」の区画に置く (→ 「編集ページの区画」)。
  - スマートフォンの幅では、タイトルに幅を残すため、「再スキャンする」と「閲覧画面で開く」をボタンで出さず⋮の中に入れる。見出しの段にはタイトルと⋮だけが残る。どちらも絵だけでは伝わりにくい (「閲覧画面で開く」に合う絵が無い) ため。
    ライブラリでないものは項目が「閲覧画面で開く」の1つになるが、種類で項目の数が変わるので⋮にする (上の「項目が常に1つしかないものは⋮のメニューにしない」)。
  - 再スキャンの進み具合と中止、結果の件数は、見出しの下、タブの上に出し、タブを移っても出したままにする。設定のタブの入力中の値は消さない。
  - 「閲覧画面で開く」は、直した結果を閲覧側でどう見えるか確かめるため。周りと並んだ見え方が分かるよう、そのコンテンツが並ぶ一覧 (入っているグループ、ルート直下ならホーム) を開く。「非表示」と他人の「作成者のみ」は上の一覧に並ばず、ほかに開く道も無いので、それ自体を開く (専用のページが無い前からのファイルは除く)。一覧の⋮にも同じ項目を置く (行を押すと編集ページへ移るので、一覧から閲覧画面へ直接行く道がほかに無い)。
    開き先は閲覧の一覧が行ごとに開く先と同じ (`$lib/content-view-href.ts`)。専用のページが無いファイル (画像・PDF・音声・動画) は、入っているグループ (ルート直下ならホーム) を開く。ファイルだけを開いても、閲覧側での見え方は分からないため。リンクは閲覧側と同じく別のタブで行き先を開く。
  - 逆向きに、閲覧の画面 (グループ・フォルダー・アーカイブ・リンクの一覧のファイル) の見出しの右端に、編集ページへ移るペンを置く (`browse-heading.svelte`)。閲覧側で見て気づいた所を、管理画面の一覧から探し直さずに直しに行けるようにするため。出すのは書き換えられる人 (作成者と `admin`) にだけで、判定はサーバーが応答の `canEdit` で返す。フォルダーの中の階層やリンクの一覧のファイルでは、入っているコンテンツの編集ページを開く。
    一覧の行 (リンク・ファイル) には置かない。編集できる人には大半の行に並んで一覧がうるさくなり、行全体をリンク1つにした作りも崩れるため。1件ずつの編集は、ホームやグループの行のペンか、`admin` は管理画面の一覧から行う。
  - 削除は、設定のタブの「削除」の区画から行う (下の「編集ページ (コンテンツ・ユーザー・共有) の削除」)。押しても確認の窓が開くだけなので、見えるところに置いても誤って消すことはない。消した後は戻り先へ移り、保存していない変更があっても離れるときの確認は出さない (消したものは保存しようがない)。確認ダイアログは一覧の「削除...」と同じ部品 (`content-delete-dialog.svelte`)。
- **アーカイブは、見せるアイテムの数 (「120 件のファイル」) を、コンテンツ管理の一覧のタイトルの下と、編集ページの見出しの下に出す**。ファイルのタブの中には、絞り込んでいるときだけ残る件数を出す (見出しの件数がどのタブでも見えるので、絞り込んでいなければ同じ数が2つ並ぶ)。
- **アーカイブのファイルのタブは、閲覧の画面 (`/archives/[id]`) と同じ部品で並べ、管理の操作を重ねる** (`frontend/src/routes/contents/[id]/items/+page.svelte`)。軸・表示タイトル・パターンを決めたら、管理画面を離れずに閲覧者に見える姿を確かめられるようにするため。
  - 並べ替え・名前の絞り込み・軸の絞り込み・リストとタイル・縮小画像・ビューアーは閲覧の画面と同じ (`archive-view-controls.svelte`・`archive-view-list.svelte`)。
  - 閲覧の画面と違い、2段目に軸の値とパスを出す。
  - 名前の絞り込みは、表示タイトルに加えてパスでも照らす (→ archive.md「見せるアイテム」)。パスは長く、間を空けた当たりを許すとほとんどの行に当たるので、続いた文字列だけで照らす。
    フォルダーには出さない。数えるのにディスクをたどるので重く、件数を持たない決まりのため。グループは一覧の木で子が見えるので出さない。
- **対象外のタブは、パターンで外れて閲覧画面に出ないファイルを、パスを主にした行で並べる** (`frontend/src/routes/contents/[id]/excluded/+page.svelte`)。パターンを直す人が、何が外れているかを確かめるため。
  - 書き換えられる人にだけ出す。ファイルは開かない (外れるものは編集できる人にも見せない)。中身は共有の画面で確かめる。
  - 「名前で絞り込む」は、このタブではパスに当てる。行にタイトルが無いため。パスは長いので、続いた文字列だけで照らす。
  - ドット始まりのファイルとシンボリックリンクは、索引に入らないので並ばない。見出しの「○件のファイル」は見えるものの数のままなので、一覧の上にこの一覧の数を別に出す (「対象外のファイル: ○件」)。
- **パターンに追加: ファイルと対象外のタブで絞り込み中に、書き換えられる人に「パターンに追加...」を出す** (`pattern-add-dialog.svelte`)。パターンと「名前で絞り込む」の記法は別々のまま。見せる範囲の決まりは厳密に、探す操作はあいまいなままにするため。
  - 窓で追加先 (除外か対象) を選び、語から作った候補を直せる。既定は除外。対象外のタブで対象のパターンがあるライブラリだけ、既定を対象にする。対象のパターンに当たらず外れたファイルは、対象に足すと戻るため。除外のパターンで外れたファイルは除外が勝つので足しても戻らず、設定のタブで除外から消すと戻る。対象外のタブの窓にだけ、そう添える。
  - 候補は、語の前後と間に `*` を置き (`jpg` なら `*jpg*`、`英語 2024` なら `*英語*2024*`)、語の中の記号は `[ ]` で包んでその文字として当てる。語に `/` があれば頭に `**/` を付ける (`/` を含むパターンは一番上から見るので、下の階層のパスに当たるように)。
  - 変わる件数を見せ (→ folders.md「見せるものの絞り込み」)、「追加する」でその場で保存する。増減が無ければ足す意味が無いので、押せなくする。絞り込みはタイトルにも当たり、パターンはパスに当たるので、候補が1件も当たらないことがある。窓の件数で気づける。
  - 窓の後ろで一覧が変わるので、知らせ (トースト) は出さない。行の⋮から1件ずつ足す操作は入れない。
  - 設定のタブの書きかけと重ならない。タブを移るときに離れるときの確認が出るので、書きかけを持ったままこの窓を開くことは無く、戻ったときは保存した後の値を読み直す。
- **編集ページの区画: コンテンツの編集ページは、どの種類にもある項目 (基本情報: タイトル・グループ・公開範囲・説明・作成者) と、種類ごとの項目 (リンク先・ファイル・場所と見せ方) を別のカードにし、サイト設定と同じ石垣に並べ、区画ごとに保存する** (→ 「サイト設定の区画」)。グループは種類ごとの項目を持たない。
  種類が変わっても、同じ項目が同じ所にあるようにするため。区画を足すと縦に長くなり、PC や横向きのタブレットで右半分が空くので石垣にする。
  保存を分けるのは、確認がそれぞれの区画の変更にだけ付くため。公開範囲が広がる確認は基本情報の区画、スキャンの件数の確認とパターンで見えるものが変わる確認は場所と見せ方の区画で出る。片方を保存しても、もう一方の書きかけは残る。
- **編集ページ (コンテンツ・ユーザー・共有) の削除は、区画の石垣の下に「削除」の区画として置く** (`delete-section.svelte`)。区画には、消すと何が起きるか (元に戻せない・中のものはグループの外に出る・コンピューターの中のファイルは消えない など) と「削除...」を置く。
  見出しの⋮に入れると、開くまでどこで消すのか分からず、押す前に何が起きるかも書けないため (GitHub・Vercel の設定の画面と同じ形)。
  石垣の中に入れると、幅と中身の量で右上に来ることがあるので、石垣の下に1列目と同じ幅で置く。区画の枠と見出しを危険の色 (`destructive`) にし、ほかの区画と見分けられるようにする (GitHub の Danger Zone と同じ)。「削除...」も、確認の窓の確定のボタンと同じ危険のボタン (`destructive`) にする。
  押せないとき (最後の管理者) は、ボタンを押せなくし、理由を区画の中に書く。コンテンツの編集ページでは、設定のタブにだけ置く。
- **書き換えられないコンテンツ (他人のものを開いた `user` → access.md「ロールと操作」) には、編集の入り口を出さず、編集ページを開いたらそのコンテンツの閲覧画面へ送る** (外へのリンクはホーム)。
  見えているのに押すと 403 になるボタンを出すと、壊れているのか権限が無いのかが分からないため。入り口が無いので、編集ページを見るだけの形にしても、URL を打った人にしか届かない。
  - 一覧の行と閲覧ページの見出しの鉛筆、並べ替えのつまみは出さない。他人のグループの画面の「追加」は出す (自分のコンテンツを他人のグループに入れてよい → access.md「ロールと操作」)。
  - `admin` の基本情報の区画には「作成者」の選択を置く。その区画の保存ボタンで他の項目と一緒に保存する。
- **グループの子は親の行の下に字下げして並べる**。同じ階層の中は登録した順。
  親子の関係は「親」列の文字よりも、行の位置と字下げの方が速く読み取れるため。
  字下げは1段 20px、スマートフォン幅では 12px にして、深い行でもタイトルに幅を残す。
  深さに上限は設けない。
- **マニュアルの本文の表だけは横スクロールを許す**。
  管理画面の表と違い、中身が任意の Markdown で、どの列を隠してよいかを決められないため。
  表ごと独立したスクロール領域に入れ、ページ全体は横に動かさない。
  罫は面の境界の色で引き、見出しの行は淡い塗りと太字にする。
  **スクロールする領域はキーボードでも操作できるようにする** (`tabindex` を持つ領域で包む)。
  表の中に押せる要素が無いため、包まないと見切れた列にキーボードだけで到達できない。
  Chrome は補ってくれるが、Safari と Firefox は補わない。
- **値の辞書の語の候補 (→ archive.md「軸の設定を助ける表示」) は、枠線だけの小さなボタンを折り返して並べ、差し色を使わない**。
  語の後ろに件数を補助色で添える。
  押しても表に行が足されるだけで保存はしないので、確定する操作に見える色にしない。
  見た目は小さいまま押せる範囲を上下に広げ、折り返した行と重ならないよう行の間を空ける。
- **軸のタブの「AI に相談...」は、ダイアログの中で画面を切り替える** (→ archive.md「軸の定義を外部の AI で作る」)。
  プロンプトの画面で答えを貼り、確かめた答えは「インポート後の内容」の画面で見せる。
  プロンプトと結果を1枚に縦に並べると、ダイアログの途中でスクロールする欄にホイールを取られるため。
  - プロンプトの画面は、プロンプトのコピーと答えの貼り付けを同じ画面に置く。行き来しながら頼み直すことがあるため。
    プロンプトの中身は畳んで「プロンプトを表示」で開く。開いたままだと、それ自体がスクロールする欄になるため。
  - 結果の画面の「戻る」で、答えを貼った画面に戻る。画面を替えたら先頭から見せる。
  - 予告の例は、表示タイトルの下に軸ごとの値を出す。答えにテンプレートが無いとタイトルはファイル名のままで、値が読めないため。
  - 今の軸か表示タイトルのテンプレートがあれば、置き換わることを警告の帯で出す。
  - 答えを貼った後は、外側を押しても Esc でも閉じない。長い答えを貼り直させないため。
- **表示タイトルのテンプレートで使える部品も、語の候補と同じ枠線だけのボタンを折り返して並べ、差し色を使わない** (→ archive.md「表示タイトル」)。
  各ボタンは `{軸名}`・`{fileName}` を示し、押すとテンプレート入力欄のカーソル位置 (選択範囲があればその範囲) に挿入する。
  保存はしないので、確定する操作に見える色にしない。
- **警告の表示に差し色を使わない**。差し色で塗ると「良いこと」に見えるため、
  登録前の確認 (→ folders.md「登録前の確認」) のように注意を促す帯は別の色系統にする。
- **ページの中の警告の帯は、上下の中身と同じ 16px ずつ離す**。
  帯の上は本文の余白で空くが、帯の下に続く一覧や文には上の余白が無いので、帯の側に下の余白を付ける (共有の画面)。
  管理画面の上のリカバリコードの帯は、下に続く本文の余白がそのまま 16px になる。
- **サーバーに送るボタンは、処理中にスピナーを出す**。
  ラベルを隠して幅を保ったまま、スピナーを中央に重ねる (`LoadingButton`、確認ダイアログの確定は `LoadingLabel`)。押せなくするだけだと、押せたのかが分からないため。
  選択・スイッチ・並べ替えは押した時点で見た目が変わるので、押せなくするだけでよい。
- **画面を移る途中は、画面の上端に差し色の細いバー (4px) を出す** (`navigation-progress.svelte`)。
  移る先のデータを読み終えるまで前の画面が残るので、何も出さないと押しても何も起きないように見えるため。
  進み具合は分からないので、短い帯を左から右へ繰り返し流す。動きを減らす設定では、動かさず端から端まで塗る。
  0.2秒より早く終わる移動では出さない。一瞬だけ出るちらつきを避けるため。
  上端の細いバーは、GitHub・YouTube など画面を差し替えて移るサイトでよく見る形に倣った。
- **トーストを出さないと処理されたことが分からない操作は、トーストで知らせる**。
  独自の基準にせず、既存のデザインシステムの扱いに揃える。[Atlassian](https://atlassian.design/components/flag/usage) と [Fluent](https://fluent2.microsoft.design/components/web/react/core/toast/usage) は、操作の結果の確認を、見落としても困らない一時的な知らせとして扱う。[Carbon](https://carbondesignsystem.com/patterns/notification-pattern/) は、通知は必要なときだけ出すとしている。
  - 対象: 保存しても入力した値がそのまま残るもの (編集ページの区画・サイト設定・値の辞書・表示タイトルのテンプレート)、窓やメニューが閉じるだけのもの (パスワード・ユーザー名の変更、リンクのコピー)、画面が移って結果が見えないもの (バックアップからの復元)。保存ボタンが押せなくなるだけでは、保存できたと読み取りにくいので、トーストも出す。
  - 出さない: 行が消える・区画がその場で切り替わる・画面が移って結果が見える操作。確認や入力の窓から実行する操作も、窓の後ろで行や区画が変わるなら出さない。
  - 例外: 画面に出ない内容を知らせるとき (同じ名前を飛ばした件数)。
  文言には何を保存したかを書く。1つの画面に保存が2つあっても、どちらが済んだかが分かるようにするため。
  置き場所はヘッダーのすぐ下の中央にする。下端は再生中のプレイヤーや iPad のキーボードに隠れるため。
  地と文字は中性色にして、成功のアイコンだけを差し色にする。
  失敗はトーストにせず、閉じるまで残るエラーダイアログで伝える。自動で消えると、保存できていないことを見落とすため (Atlassian も、重要なエラーを自動で消える知らせにしないとしている)。
  ただしコピーの失敗はトーストで伝える。失われるものが無く、貼り付けるときに気づいてその場で押し直せるので、ダイアログで止めるほどではないため。
- **確認ダイアログは、処理中は開いたままにして閉じさせず、応答を受けて成否によらず閉じてから結果を知らせる**。
  処理中はボタンを押せなくし、確定ボタンに読み込み中を出す。Esc でも閉じない。押せたのか・まだ動いているのかが分かるようにするため。
  失敗しても閉じる。開いたままだと、エラーを閉じた後にもう一度キャンセルさせることになり、同じ理由で失敗する操作が目の前に残るため。押し直すときは開き直す。
  応答の後も続く処理は、進み具合を出す所へ渡す。登録の確認はスキャンの間も窓の中に進み具合と中止を出す。見える内容の確認は保存の応答で閉じ、区画の中に出す。共有の中の削除は、始まった応答で閉じて画面の右下に出す。
- **ホームの一覧の上に、サイト名と見出しを置く** (→ access.md「ロールと操作」・architecture.md「スキーマ」)。
  サイト名は小さく補助色で、見出しは大きく太字で出す。どちらも管理画面のサイト設定で `admin` が決める。
  未設定の行は出さない。見出しが未設定なら、見た目には出さず読み上げ用の `h1`「ホーム」を置く。
  特定の業種に限らず使うので、既定の文言を持たず、設定のラベルや説明にも業種を思わせる語を使わない。
  キャンバスの「みどり教室」「教材と資料」は入力の例にすぎない。
  ヘッダーのロゴとタブのタイトルは WebLAV のままにする。どの画面でも WebLAV のものだと分かるようにするため (→ `page-title.ts`)。
- **サイト設定の画面に「サーバー」の区画を置き、ポート・アップロードの上限・セッションの有効日数を変えられるようにする**。
  `config.toml` を手で書けない管理者でも変えられるように。
  - アップロードの上限は、共有へアップロードするファイル1つあたりの上限。既定は上限なし。共有の中に置くファイルは動画や写真の書き出しなど大きいことが多く、決まった数で断ると共有に置けないため。
  - アップロードの上限とセッションの有効日数は、0 を「上限なし」「期限なし」と読む。切り替えの欄を別に置かず、数の欄1つで済ませるため。0 の意味は欄の下の説明に書く。
  - 値は DB でなく `config.toml` に書く (`src/api/server_settings.rs`)。ポートは DB を開く前に要るうえ、起動できないときは手で直す先が `config.toml` しか無いため。
    書き換えは `toml_edit` で該当の項目だけにし、手で書いたほかの項目やコメントは残す。`config.toml` が読めない形なら上書きせずにエラーにする。
  - 3つとも保存しても次の起動から効く。ポートは動いている間に変えられないので、ほかの2つも扱いをそろえ、画面の説明を1つで済ませる。
  - 保存した値が動いている値と違う項目には「今は {値} で動いています」と添える。起動し直すまで効かないことと、ポートをずらして起動していること (→ distribution.md「常駐 (Windows)」) の両方を、同じ形で伝えるため。
  - 保存は区画ごとに分ける。「ホームの表示」はすぐ効き、「サーバー」は次の起動から効くので、1つのボタンにまとめると、どちらがいつ効くのかが読み取れないため。
  - 既定の値から変えてある項目にだけ、欄の右に「既定値に戻す」を出す。元の数字を覚えていなくても戻せるように。欄を空にしたときも出す。消してから元の数字が分からなくなったときに戻せるように。
    変えてあることを示す印や既定の値の文は足さない。ボタンが出ていること自体で、変えてあると分かるため。
    印と戻す操作は項目ごとに置く。ポートを戻すとブックマークや配った QR コードで開けなくなるので、区画ごとまとめて戻す形にしない。
    戻すのは入力欄の値だけで、保存は区画の保存ボタンで行う。入力欄が保存した値と違う間は、保存ボタンの横に「保存していない変更があります」と出す。
    印を付けるのは「サーバー」の区画だけ。「ホームの表示」は既定が空で、入っていれば変えてあると分かり、「ログ」はスイッチの向きがそのまま既定かどうかを表すため。
- **サイト設定の画面に「ログ」の区画を置き、詳しいログの切り替えとログのダウンロードをできるようにする**。
  不具合を調べるとき、`config.toml` やログの置き場を知らない管理者でも、ログを取って渡せるように。画面の中でログを読む機能は持たない。
  - 詳しいログは、スイッチを切り替えたらすぐ効かせる (`src/logging.rs` の `LogControl`)。保存ボタンは置かない。
    起動時のフィルタの既定の段階だけを `debug` に上げ、`weblav=trace` のように名指しした指定は残す。
    `config.toml` には書かず、起動し直すと起動時のフィルタ (`RUST_LOG` か `log.filter`) に戻る。出しっぱなしでログが膨らむのを避けるため。
  - ダウンロードは、残っている日の分を古い順に1つのテキスト (`weblav-logs.txt`) につなげて返す。渡す相手が1つ開けば済み、zip の依存も要らないため。
    詳しいログは大きくなりうるので、メモリに載せずに流す。
  - ログは14日分を残し、古いものから消す (1日1ファイル)。日数は設定にしない。
  - `log.output = "stdout"` のときは渡すファイルが無いので、ダウンロードを出さず、ターミナルに出していることだけを書く。
- **サイト設定の画面に「バックアップ」の区画を置き、バックアップのダウンロードと、バックアップから戻す操作を置く** (→ access.md「バックアップとリストア」)。
  - 「バックアップから戻す...」はファイルを選ばせ、受け取ったら確認ダイアログに作った日時と版、今のデータが置き換わること、全員がログインし直すことを書く。戻したらトーストで知らせてログインへ送る。
  - セットアップの画面にも、管理者を作るフォームの下に同じ「バックアップから戻す...」を置く (部品は `backup-restore.svelte` で共有)。
- **自動の再スキャンは「しない」「前回から N 時間たったら」「毎日 HH:MM を過ぎたら」の丸ボタンにし、数と時刻の欄は選択肢の文の中に置く** (→ archive.md「スキャン」)。3つの状態が一目で見え、選んだものにだけ値を入れればよいため (OS のメールの新着の確認の設定と同じ形)。

画面ごとの具体はデザインキャンバス (非公開) にある。
ただし**判断の根拠は上の箇条書きで完結させる**。キャンバスは補助であり、
キャンバスを見られなくても本書だけで実装できる状態を保つこと。
ユーザー管理画面はキャンバスに含まれておらず、
一覧は `/admin/contents` の表に、編集ページは共有の編集ページに倣い、上の箇条書きのみを根拠に実装する。

## リンクのカード

`link` コンテンツは、ページの画像・サイトのアイコン・サイト名・最後に更新した日時からの経過を添えて並べる (Google Discover のカードに倣う)。

- **一覧の「タイル」では大きい画像のカードにし、「リスト」ではほかの行と同じ高さのまま、アイコンの位置に画像を縮めて出す**。
  2段目にアイコン・サイト名・経過を出す。説明は登録してあるときだけ、リストでは2段目の末尾に、タイルではタイトルの下に出す。
  ホームやグループではリンクがフォルダーやファイルの行と同じ一覧に混ざるので、リストでリンクの行だけ背を高くすると並びが揃わないため。
- 画像が無ければリンクの絵にする。アイコンを引き伸ばして代わりにしない。サイト名が無ければホスト名、日時が無ければ経過を出さない。
- **押すと、新しいタブで開く前に、ページの上に詳しい表示のダイアログを出す** (`frontend/src/lib/components/link-detail-dialog.svelte`)。`.links.toml` の中のリンクも同じ。
  リストでは画像が小さく、タイルでは題と説明が切れるので、開く前にページの中で全部を確かめられるようにするため (Pinterest のピンや Google 画像検索の、押すとまず詳しい表示が開き、そこからサイトへ移る形に倣う)。
  - 出すのは、題・アイコン・サイト名・経過、幅いっぱいの画像、登録した説明、ページの説明 (`og:description`、無ければ `<meta name="description">`)、URL。ページの説明は、登録した説明と同じなら出さない (登録するときに、ページの説明から埋めることがあるため)。
  - 「新しいタブで開く」を主のボタンにし、開いたらそこにフォーカスを置く。開くだけの人が Enter 1回で済むように。押してもダイアログは閉じない。タブを戻ったとき、続けて前後のリンクを見られるようにするため。
  - 修飾キー付きのクリックと長押しのメニューは、今までどおり直接新しいタブで開く (画像やファイルの行と同じ)。
  - ファイルのビューアーとは別の、普通のダイアログにする。
  - 前後は、開いた一覧に並ぶ、詳しい表示を出すリンクの表示順 (絞り込んでいれば、残った行)。左下の左右のボタンと左右キーで移り、何件目か (`2 / 4`) を題の上に出す (ファイルのビューアーと同じ操作)。ファイル・ビューアーで開くリンク・LAN の URL は飛ばす。
    端に着いて押したボタンが押せなくなったら、フォーカスを「新しいタブで開く」へ移す。フォーカスが外れて左右キーが届かなくならないように。
  - ビューアーで開くもの (動画サイトの動画・URL のファイル) はビューアーで開く。LAN の URL はサーバーが取りに行かず見せるものが無いので、今までどおり直接新しいタブで開く。
  - 詳しい表示を出す行は、ページの中で開くので、新規タブのグリフを付けない (ビューアーで開く行と同じ)。
- **画像とアイコンはサーバーが取って縮め、サーバーから配る** (`src/api/link_preview.rs`)。見る側の端末を外のサイトにつながせないため。
  - 取るのはページの `og:image` (無ければ `twitter:image`)、`og:description` (無ければ `<meta name="description">`)、`og:site_name`、日時、`<link rel="icon">` (SVG は縮められないので飛ばし、無ければ `apple-touch-icon`、それも無ければ `/favicon.ico`)。
  - 日時は、ページが日時を伝えるための標準の書き方から読む (`src/api/page_dates.rs`)。更新した日時 (schema.org の `dateModified`・OGP の `article:modified_time`・Dublin Core の `dcterms.modified` など) を先に、無ければ公開した日時 (`datePublished`・`article:published_time`・`dcterms.issued`・`<meta name="date">` など) を使う。
    どちらも無ければ HTTP の `Last-Modified` を使う。ただし応答の `Date` とほぼ同じなら使わない。その場で組み立てるページは、作った時刻を送ってくるため。
    本文の文字から日付らしいものは拾わない。関連の記事やコメントの日付を取り違えるため。
  - 画像は長い辺 1200px、アイコンは 64px に縮める。画像は詳しい表示で幅いっぱいに出すので、`og:image` の推奨の大きさ (1200×630) を縮めずに残す。配る URL は中身のハッシュなので、ブラウザーには取り直させない。
- **一覧は覚えている情報ですぐに出し、画面がその後でサーバーに取り直しを頼み、答えで差し替える** (`POST /link-previews/refresh`)。
  - 頼むときは URL でなくコンテンツの id (一覧のファイルなら、そのファイルの指し方) を渡す。サーバーは見る権限を確かめた分だけ取りに行く。誰でも任意の URL を取らせられないようにするため。
  - 答えは、確かめ終えた順に1件ずつ1行の JSON (NDJSON) で流し、画面は届いたカードから差し替える。いちばん遅いページを待って全部を一斉に差し替えると、初めて開く一覧ではカードがしばらく空のままになるため。閲覧する側が途中で閉じても、取りに行った分は最後まで取って覚える。
  - 取り直す時期は HTTP のキャッシュの決まり (RFC 9111) に従う。`max-age` (無ければ `Expires`、それも無ければ `Last-Modified` からの経過の1割) の間は使い回し、過ぎたら `ETag`・`Last-Modified` で条件付きで確かめる。`no-cache`・`no-store` は毎回確かめる。
  - 同じ URL を確かめに行くのは、前回 (取れなかったときも含む) から5分たってから。
  - 覚えた画像とアイコンは全体で100MBまで。超えたら、最後に一覧に出たのが古い順に消す。
  - 覚えた情報 (`link_previews` の表と、データの置き場の `link-previews/`) はバックアップから戻すときに戻さず、今のものを残す。画像の実体はバックアップに入らないため。

## URL のファイル

`link` コンテンツの URL が、開き方の決まるファイル (音声・PDF・動画・Office・画像・テキスト) を指すときは、リンクのカードでなくファイルの行で出し、ファイルと同じプレイヤー・ビューアーで開く (`src/api/remote_file.rs`・`frontend/src/lib/file-kind.ts` の `remoteFile`)。
URL を登録しただけの PDF などを、フォルダーのファイルと同じように見られるようにするため。

- **WebLAV のサーバーが取ってきて流す** (`GET /contents/{id}/remote`)。閲覧する端末は外のサイトにつながない。リンクのカードと同じ考え方で、CORS を許さないサイトの PDF・テキストも開ける。
  - 頼むのはコンテンツの id で、閲覧の権限を確かめてから取りに行く。誰でも任意の URL を取らせられないようにするため。
  - 返す型は、下の決め方で決めたファイル名の拡張子から決め、相手の `Content-Type` をそのまま渡さない。インラインで出すかもファイルの配信と同じ判定にする。相手の返す HTML を、このアプリのオリジンでスクリプトの動くページとして出さないため。
  - 動画の早送りのため、`Range` を相手へ渡し、206 の応答をそのまま流す。保存はせず、閲覧側が読む速さで受け取る。
  - 同時に中継する数に上限を置き、超えたら待たせずに断る (429)。中継は流し終えるまでスレッドを1本持つため。
- **種類は、まず URL のパスの最後の部分の拡張子で決める**。クエリにある拡張子 (`?file=a.pdf`) では決めない。画像も PhotoSwipe でなくビューアーで開く。大きさを読まないため。
- **拡張子で決まらなければ、リンクのカードの情報を取るときの相手の応答で決める** (`remote_file::file_name_from_response`)。拡張子の無いダウンロードの口 (`/download?id=1`) も、ファイルと同じように見られるようにするため。
  - `Content-Disposition` のファイル名か、リダイレクトを辿った後の URL の拡張子で決まれば、その名前にする。決まらなければ、`Content-Type` が対象の種類 (PDF・動画・音声・画像・Office・`text/plain`・`text/markdown`・`text/csv`) なら、その名前に型の拡張子を足す。HTML・SVG・XML は対象にしない。
  - テキストは、ビューアーが読める大きさ (2MB) を超えると分かっていれば対象にしない。URL の拡張子だけではテキストにしない。フォルダーのファイルも、拡張子でなく中身で決めているため。
  - 決めた名前はカードの情報と一緒に覚え (`link_previews.file_name`)、一覧と中継の口が使う。初めて開く一覧では、取り直しの答えが届いてからカードがファイルの行に変わる。
- **LAN の URL (IP が公開アドレスでない・`.local`・ドットの無い名前) は中継せず、リンクのカードのまま新しいタブで開く**。サーバーは公開アドレスにだけつなぐ決まりのため (→「UI 全般」)。LAN の機器は閲覧する端末から直接開ける。
  名前を引くと LAN を指すものは画面では見分けられない。ビューアーと音声のプレイヤーは読めなかった案内と元の URL へのリンクを出す。行の直リンク (修飾キーのクリック・長押し) とビューアーの「新しいタブで開く」も、中継でなく元の URL を開く。
- `.links.toml` の中のリンクも同じく開く (→「リンクの一覧のファイル」)。

## ページの共有

ヘッダーの共有のボタンで、開いているページのアドレスをほかの端末へ渡す (`frontend/src/lib/components/share-button.svelte`)。
授業で「このフォルダーを開いて」と渡すため。
トップページへのつなぎ方の案内も、このボタンが兼ねる (トップページで押せばそのアドレスになる)。別のボタンを並べると、どちらを押せばよいか迷わせ、ヘッダーも狭くなるため。

- メニューは「QRコードを表示...」と、OS の共有シートを呼べるときは「ほかのアプリで共有...」。
  - アドレスのコピーは、QR コードの画面のコピーのボタンで行う。メニューに同じコピーを並べない。
  - 共有シート (AirDrop・メッセージなど) をページから呼べるのは、HTTPS か `localhost` で開いたときだけ (Web Share API の制約)。LAN の HTTP で開いた端末では、ブラウザー自身の共有ボタンは使える。
  - 共有シートを閉じたときは何もしない。ほかの失敗は QR コードの画面を出す。
  - LINE・X などのボタンは置かない。LAN のアドレスは学校の外からは開けないため。
- 渡すのはアドレスのパスとクエリまで。ほかの端末から開いているならそのアドレスを、PC の前 (`localhost`) で開いているなら PC の名前とサーバーのポートに置き換えたものを渡す。置き換えられないときは、QR コードの画面に理由を出す。
- QR コードの画面のアドレスは、PC の名前のものと LAN の IP アドレスのものから選べる (→ architecture.md「LAN からの到達性」)。名前を引けない端末へ、その場で IP で渡すため。
  - 選ぶと、QR コード・コピー・共有シートに渡すアドレスが全部替わる。
  - 既定は名前 (ほかの端末から開いているなら、そのアドレス)。選んだホストを端末に覚え、次もそれを選ぶ。名前を引けないネットワークで、毎回切り替えずに済むため。覚えたホストが候補に無くなっていれば既定に戻す。
  - 候補が1つなら、選ぶ欄にせず今のアドレスを見せる。選ぶ欄でも、選んだアドレスは全文を折り返して見せる。候補の一覧はホストだけを並べる (候補どうしで違うのはホストだけで、全文では狭い画面からはみ出すため)。
  - IP を併記せず選ばせるのは、授業で見せる画面のアドレスを1つにし、どちらを読むか迷わせないため。

## 動画サイトの埋め込み

`link` コンテンツの URL が YouTube の動画を指すときは、リンクのカードのまま置き、押すと「PDF・動画・テキストのビューアー」の中にそのサイトの埋め込みプレイヤーを出す (`frontend/src/lib/video-embed.ts`)。
授業で動画を見せるたびに別のタブへ移らずに済ませるため。

- サーバーは中継しない。動画サイトの規約は、そのサイトのページか埋め込みプレイヤーで見ることを求めているため。閲覧する端末が動画サイトにつながるのは、新しいタブで開くときと変わらない。
- カードのサムネイルと題名は、今までどおりサーバーが取ったものを出す。行の末尾のグリフは付けず、修飾キーのクリック・長押しは元の URL を新しいタブで開く。
- YouTube は Cookie を置かない `youtube-nocookie.com` の口で埋め込む。URL の `t` は始める位置として渡す。
- YouTube はリファラーの届かない埋め込みを断るので、プレイヤーにはオリジンを渡す (`referrerpolicy="strict-origin-when-cross-origin"`)。
- 投稿者が埋め込みを止めた動画は、プレイヤーの中に YouTube の案内が出る。ビューアーの「新しいタブで開く」で元のページへ行ける。
- 開いた時点で、音声のプレイヤーを止める。埋め込みの中で再生を始めたかは、こちらから見えないため。
- 対応するサイトは、求められたものから足す。`.links.toml` の中のリンクも同じく開く。

## リンクの一覧のファイル

名前が `.links.toml` で終わるファイルは、開くと中のリンクを「リンクのカード」と同じ形で並べる (`/links/[id]`、`src/api/links_file.rs`)。
自動の収集や手で、リンクをまとめて見せるため。

- フォルダーの中 (`?path=`)・アーカイブのアイテム (`?item=`)・ショートカット (id だけ) のどれも、この1つの画面で開く。
  一覧の行は、ビューアーより先にこの画面への遷移に振り分ける (テキストとしてビューアーに出さない)。
- パンくずは、フォルダー・アーカイブの画面の続きとして、祖先のグループ・フォルダーかアーカイブ・途中のディレクトリ・ファイル名を並べる。ショートカットは、ファイル名でなく一覧に出ている登録したタイトルにする。題はファイルの `title` (省けばファイル名)。
  - 開いた一覧の並び順・絞り込みを `from` に入れて持ち回し、パンくずの戻り先に付ける。戻ったときに選び直さずに済むようにするため。
- 中身は UTF-8 の TOML。`title` と、`[[links]]` ごとの `url`・`note` を読む。
  - 並びは書いた順。並び順の選択は出さない。リストとタイルの切り替えは、ほかの一覧と同じく効く。
  - `http`・`https` 以外の URL の行と、`url` の無い行は飛ばす。一覧全体は読めなくしない。手で書いた1行の誤りで、ほかのリンクまで見えなくなるため。
  - カードのタイトルはページのタイトル (無ければホスト名)、説明は `note`。
  - TOML として読めないもの・1MB を超えるものは、読めなかった旨と、ファイルを新しいタブで開くリンクを出す。
- 中のリンクのカードの取り直しは、取り直しの API にファイルの指し方を渡して頼む。サーバーはファイルを読み直し、中の URL を取りに行く。件数の上限 (200) を超えた分は断らずに取り直さない。手やジョブが書くファイルなので、件数で画面ごと失敗させないため。
- 中のリンクが URL のファイルや動画サイトの動画を指すときは、一覧のコンテンツと同じくファイルの行・ビューアーで開く (→「URL のファイル」「動画サイトの埋め込み」)。中継は `GET /contents/{id}/links/remote` で、閲覧できる一覧に書かれた URL だけを取りに行く。行の題は、覚えているページのタイトル、無ければファイル名。

## 一覧の絞り込み

ホーム・グループ・フォルダー・アーカイブ・リンクの一覧の画面に、並び順と同じ段で、名前で行を絞る入力欄を置く。一覧が多いときに、数を減らして見つけやすくするため。
ヘッダーの検索 (→ search.md) と違い、今の一覧の行だけを絞る。アーカイブはサーバーで照らし (手元に全件が無いため。→ archive.md「一覧の API を区切って返す」)、ほかの一覧はその場で絞る。

- 当たり方は fuzzy。打った文字がその順に名前の中に現れれば当たり (間に別の文字が挟まってよい)。続きのまま含まれていればそこに当てる。空白で区切った語は、どれも当たる行に絞る。
  - 全角と半角・大文字と小文字は区別しない (ヘッダーの検索と同じ揃え方)。打ち間違いは許さない。日本語では近い文字という考え方が効かないため。
- 照らすのは行のタイトル (画面に出ている名前) だけ。説明・2段目は照らさない。
- 残った行は、選んでいる並び順のまま。当たりの良い順には並べ替えない。並びが変わらないので、どこに何があるかの見当が崩れないため。音声を続けて鳴らすのとビューアーの前後も、残った行だけ。
- 欄の名前は「名前で絞り込み」。アーカイブでは軸の絞り込みと並ぶので、名前だけに当てることが分かるようにするため。
- 当たった文字を太字の差し色で強調する。間を空けて当たった行も、なぜ残ったか読み取れるようにするため。
- 語は URL の `filter` に持ち、履歴は shallow routing で置き換える (打つたびに読み込み直さず、戻るの段も増やさない)。行はその場で絞り、URL に写すのは打ち止めて 0.3 秒後にする (Safari は短い間に何度も履歴を書き換えると例外を投げるため)。並び順・軸を選び直しても語は残す。フォルダーの階層を移ると、別の一覧なので引き継がない。
  - shallow routing は `page.url` を変えないので、語は `page.state` にも持ち、そちらを先に読む。戻る・進むでは `page.state` が戻る。
  - アーカイブでは軸の絞り込みと重ねて効き、件数は「残った数 / 全体の数」にする。「絞り込みを解除」は軸だけを解除し、名前の語は残す。画面の URL では軸の名前をそのままキーにするので、同じ名前の軸は作れない (`sort`・`preview` と同じく予約する)。
- 絞り込み中は、軸の絞り込みと同じく差し色で欄を強調する。当たる行が無ければ、その旨を出す。

## ホーム・グループ・フォルダー・アーカイブの並び順

- コンテンツは表示順を持たない。並びは閲覧用の一覧 API
  (`list_contents` / `browse_group` / `browse_folder`) がクエリ `sort` で受ける。
  - `title` (既定): タイトルの昇順。英字の大文字小文字は区別せず、数字の並びは数値として比べる (「第2回」を「第10回」より前にする)。
  - `new`: 追加した日時 (フォルダーの中はファイルの更新日時) の降順。
  - どちらも、同じ値なら `id` (フォルダーの中は `title_cmp` によるタイブレーク) で決める。
  - 知らない値は既定として扱い、422 にしない。共有されたリンクを壊さないため (archive.md「エンドポイント一覧」の絞り込みのクエリと同じ考え方)。
- 数字を数値として比べるため、並べ替えは SQL ではなくアプリケーション側で行う。1つの一覧は数十件規模であり、コストは問題にならない。
- 画面は選んだ並び順を URL クエリに持つ。ブラウザーの戻る/進むが効き、リンクを共有できる (「アーカイブの一覧画面」の絞り込みと同じ)。
  既定 (`title`) のときはクエリを付けない。
- 選択 UI の見た目と置き場所は「見た目の決めごと」に書いた。
- 漢字は読みの順には並ばない (文字コードの順になる)。読み仮名を持つ仕組みは作らない。
- **フォルダーの中は、ディレクトリを常に先に置く固定の並びは変えない**。その中の
  2段目のキーだけ `title` / `new` を切り替える。ファイルとディレクトリを混ぜて
  日付順に並べると閲覧感が大きく変わるため。
- **アーカイブのアイテムは3択** (`axis` (既定) / `title` / `new`)。
  `axis` は軸の並び順のまま変えない (→ archive.md「エンドポイント一覧」)。`title` / `new` の意味論は
  ホーム/グループ/フォルダーと同じ。既定のクエリなし・共有リンクでの見え方は変わらない。

## 画像のプレビュー

- **画像の行は、押すとページの上に重ねて大きく表示する**。拡大・スワイプ・キーボード操作は PhotoSwipe に任せる
  (`frontend/src/lib/image-viewer.ts`)。本体と CSS は開くときに読み込む。
  - 前後は、開いた一覧に並ぶ、ページ内で開くもの (画像と「PDF・動画・テキストのビューアー」で開くファイル) の表示順 (アーカイブなら絞り込んだ後の並び)。隣がファイルなら、そのビューアーへ移る (→ 「PDF・動画・テキストのビューアー」)。
  - 拡大はピンチ・ダブルタップ・クリック。上部のバーに、何枚目か (`2 / 4`) と題名を出す。
  - **元の画像を読み終えてから開く** (待つのは1秒まで)。PhotoSwipe は開くアニメーションの間、仮の表示 (行の縮小画像) を引き伸ばして見せ、元の画像はアニメーションの後に差し替える。
    読み終えていれば仮の表示にも元の画像を使い、粗い画像から切り替わって見えないようにする。
    1秒を過ぎたら縮小画像で開き、読み終わり次第差し替える。大きな画像や遅い回線で、押しても開かないように見えないため。待つ間は押した行の末尾 (ファイルのビューアーから移るときはそのバー) に読み込み中の印を出す。
    前後の画像は PhotoSwipe が先読みするので、スワイプでは待たない。
  - 背景は不透明の黒にする。PhotoSwipe の既定 (0.8) では、後ろのヘッダーの文字がバーの数字や題名と重なって透ける。
  - 上部のバーには半透明の黒の地を敷き、画像はバーの下から置く。拡大した画像がバーの下に回っても、数字・題名・ボタンが明るい画像に負けないように。
    ボタンの絵は PhotoSwipe の既定を使わず、PDF のビューアーと同じ lucide の線の絵にする (→ 「PDF・動画・テキストのビューアー」)。
  - 行は元の画像への直リンクのまま置き、修飾キーなしのクリックだけをビューアーに回す。修飾キー付きのクリックや長押しのメニューでは、これまでどおり新しいタブで開ける。
  - 行の末尾にはグリフを付けない。音声の行と同じく、ページの中で開くので、遷移のグリフも新規タブのグリフも合わない。
- **振り分けはサーバーが決める**。一覧の API は、画像の行に表示するときの大きさ (`image`、EXIF の向きを当てた後の縦横) を付ける。
  画面は `image` のある行だけを画像の行にし、拡張子を見ない。
  ビューアーは開く前に大きさを知っている必要があり、それを読むのはサーバーなので、読めたかどうかで決める。
  - 対象の拡張子は jpg・jpeg・png・gif・webp・bmp。どのブラウザーも表示でき、`image` crate で縮小画像を作れる形式に絞る。
    HEIC (iPhone の既定の形式)・TIFF・AVIF は、「PDF・動画・テキストのビューアー」のビューアーで開く。
  - 大きさはファイルの先頭 256KB から読む。写真の並ぶ一覧で、1枚ずつ全体を読まないため。
- **行の先頭のアイコンを、サーバーが作る縮小画像に替える** (`/contents/{id}/thumbnail`・`/contents/{id}/items/{item_id}/thumbnail`、見える条件はそれぞれのダウンロードと同じ)。
  - 一辺 144px の正方形で、中央を切り抜く。行の枠 (最大 44px) を、画面密度3倍の端末でもぼやけずに埋める大きさ。タイルの枠 (72px、→ 「UI 全般」) は画面密度2倍までなら埋められる。透過のある画像は PNG、ほかは JPEG。
  - 縮小画像を作れない画像 (デコードに 256MB を超えるメモリが要る巨大な画像など) は 404 を返し、行はファイルのアイコンに戻る。ビューアーでは元の画像を開ける。
  - 同時に作るのは CPU のコア数の半分まで。教室の端末が一斉に同じフォルダーを開いても、配信や他の操作を止めないため。
- **作った縮小画像はデータフォルダーの `thumbnails/` に置き、元のファイルが変わるまで使い回す**。
  キーは元のファイルのパス・大きさ・更新日時と作り方の版から作る。どれかが変われば作り直す。
  ブラウザーには ETag で毎回問い合わせさせる (`Cache-Control: private, no-cache`)。公開範囲で見えるかが変わるため。
  - 古いキーのものは消さない。1枚数 KB で、元のファイルから作り直せるので、ディレクトリごと消してもよい。
- **画像でないファイル (動画・PDF・Office の文書・HEIC・AVIF・TIFF) の縮小画像は、OS に作らせる** (`src/os_thumbnail`)。
  macOS は Quick Look (`QLThumbnailGenerator`)、Windows はエクスプローラーと同じ Shell の仕組み (`IShellItemImageFactory`) を呼ぶ。
  動画や PDF を読み解く部品 (ffmpeg・pdfium) を配る物に入れずに済み、特許やライセンスの絡む部品も持たないため。
  - 一覧の API は、この種類の行に `thumbnail` を付ける。作れるかは OS とその PC に入っているアプリしだいで、作ってみるまで分からないので、作れなければ画像と同じく 404 を返し、行はアイコンに戻る。
    Windows では、PDF は縮小画像を作るアプリを入れたときだけ、Word・Excel はファイルに縮小画像が含まれているときだけ作れる (PowerPoint は既定で含める)。
    作れなかったことも同じキーで置いておき、元のファイルが変わるまで OS を呼び直さない。時間内に返らなかったときだけは置かず、次に見たときに頼み直す。
  - Linux には共通の仕組みが無いので作らない。一覧にも `thumbnail` を付けない。
  - 大きさ・置き場・キャッシュは画像の縮小画像と同じ。文書は、正方形に切り抜くとき真ん中でなく上を残す。題が上にあるため。
  - OS が返す縮小画像は透過の無いものでも RGBA なので、透過する画素があるときだけ PNG にする。

## PDF・動画・テキストのビューアー

- **PDF・動画・テキスト・Office のファイルと、上の「画像のプレビュー」で開けない画像の行は、押すとページの上に重ねて表示する** (`frontend/src/lib/components/file-viewer.svelte`)。
  見せ方は Google ドライブ・Dropbox のプレビューに倣い、「画像のプレビュー」の画像のビューアーと揃える。
  - 地は不透明の黒。上部のバーに、何件目か (`2 / 4`)・題名・「新しいタブで開く」・閉じるを置く。PDF には拡大・縮小も置く。
  - 前後は、開いた一覧に並ぶ、ページ内で開くもの (このビューアーで開くファイルと「画像のプレビュー」で開く画像) の表示順。音声・ほかのファイルの行は飛ばす。左右の端のボタンとキーボードの左右キーで移る。
    種類で前後を分けると、一覧の並びのとおりに見ていけないため (Google ドライブ・Dropbox のプレビューも種類を問わず移る)。
  - ビューアーは画像 (PhotoSwipe) とこれの2つのまま、隣が別の種類なら相手のビューアーへ渡す (`frontend/src/lib/viewer-items.ts`)。1つにまとめないのは、PhotoSwipe の拡大・スワイプを作り直さずに済ませるため。
    画像のビューアーに渡すのは隣り合う画像の連なりだけで、スワイプは連なりの中だけで効く。連なりの端からファイルへは、端のボタンとキーで移る。
    このボタンは、PhotoSwipe が矢印を隠すタッチの端末と画像1枚のときにも出す。スワイプではファイルへ移れないため。
  - 何件目か (`2 / 4`) は、画像とファイルを合わせた並びで数える。
  - 行は画像と同じく、元のファイルへの直リンクのまま置き、修飾キーなしのクリックだけをビューアーに回す。行の末尾にはグリフを付けない。
  - 読めなかったときは、その旨と「新しいタブで開く」を出す。ブラウザーの標準表示に任せれば開けることがあるため。
  - 画面を移ったら閉じる。
  - **開いているものを URL の `preview` に持つ** (`frontend/src/lib/preview-url.svelte.ts`。画像のビューアーも同じ)。読み込み直しても開いたままにし、ファイルを書き換えた後に開き直さずに済ませるため。共有したリンクでも同じものが開く (Dropbox のプレビューと同じ)。
    - 値は一覧の中で重ならず、読み込み直しても変わらないもの: フォルダー・共有の中はパス、コンテンツの一覧は番号、リンクの一覧は URL、検索の結果のファイルはフォルダーの番号とパス。アーカイブは並びの位置とファイルの番号 (`12-345`)。手元に全部の行が無いので、位置の区切りを取ってから番号で探す。
    - 開くと履歴を1段足し (shallow routing)、閉じると戻る。ブラウザーの戻るでも閉じ、ページは移らない。進むで開き直す。
    - 前後に移ったら、段を足さずに置き換える。前後に送るたびに戻るの段が増えると、一覧へ戻るのに何度も押すことになるため。止まってから 0.3 秒後に写す (Safari は短い間に何度も履歴を書き換えると例外を投げ、左右キーを押し続けると移るたびに書くことになるため。→ 「一覧の絞り込み」)。
    - 読み込み直したときは、一覧から探して、行から開いたときと同じ前後で開く。見つからなければ (消えた・絞り込みで外れた) 開かずに `preview` を外し、一覧をそのまま見せる。
    - 読み込み直した後に開いたものには、足した段が無いので、閉じたら `preview` を外して置き換える。戻るは前の段 (一覧) へ移る。
    - アーカイブの画面の URL では、`preview` を軸の絞り込みとして読まない。同じ名前の軸は作れない (`sort`・`filter` と同じく予約する)。
- **対象**
  - PDF: pdf
  - 動画: mp4・m4v・webm・mov。
  - 画像: heic・heif・avif・tif・tiff。
  - Office: docx・xlsx・pptx。旧形式 (doc・xls・ppt) は新規タブで開く。
  - テキスト: 上と音声・画像の拡張子でなく、リンクの一覧のファイル (`.links.toml`) でもないファイルのうち、サーバーが一覧を返すときに先頭 8000 バイトを読み、NUL のバイトが無いもの (git がバイナリかを決めるのと同じ考え方)。
    設定・データ・ソースなどテキストの形のファイルは拡張子の種類が多く、一覧では追いつかないため。
    2MB を超えるファイルは読まずに外す。UTF-16 のテキストは NUL を含むので外れ、新規タブで開く。
    HTML・SVG もソースを見せる。新規タブではスクリプトを動かさないよう、表示せずダウンロードになるため。
  - mov・HEIC・TIFF などは、表示できるかがブラウザーによる (Safari だけが表示できる、など)。表示できなければ、読めなかったときの案内を出す。
    wmv・avi のように、どのブラウザーでも表示できない形式は対象にせず、新規タブで開く。
- **PDF は PDF.js (pdfjs-dist) で描く**。ブラウザーの標準表示を `<iframe>` で埋め込む形は採らない。
  iPad の Safari は、埋め込んだ PDF の1ページ目しか出さないため。
  - legacy の版を使う。modern の版は最新のブラウザーにしか無い API を補わずに呼ぶので、OS を更新できない iPad では開けない。
  - 本体と worker は、PDF を開くときに読み込む。一覧の画面は重くならない。
  - ページは縦に並べ、幅に合わせる (広い画面では 896px まで)。拡大は 1・1.5・2・3 倍の段階で、ボタンで切り替える。
  - 描くのは見えているページと、その前後の画面1つ分だけ。離れたページは描いた分を捨てる。iPad の Safari はキャンバスの画素数とメモリに上限があり、全ページを描いたままにすると描けなくなるため。
  - 日本語の PDF はフォントを埋め込んでいないことが多いので、CMap を配る物に入れる。画像の展開用の wasm・ICC も入れる (`frontend/scripts/pdfjs-assets.ts`)。
    標準フォントは入れない。Liberation が GPL-2.0 で配れないため。埋め込まれていない標準フォントは、ブラウザーのフォントで描く。
  - 配る物は 3.9MB ほど増える (worker 1.3MB・本体 0.5MB・CMap 1.6MB・wasm 0.4MB)。
- **Office のファイルは @silurus/ooxml でブラウザーの中で Canvas に描く** (`frontend/src/lib/components/office-view.svelte`)。
  サーバーで PDF に変える形は採らない。Windows の Office の自動操作は Microsoft が無人の利用をサポートせず、LibreOffice は利用者に別に入れてもらう必要があるため。
  - Word と PowerPoint は、ページ・スライドを縦に並べて送る。Excel はシートの表と、下のシートの切り替えを出す。
  - 本体と WASM は開くときに読み込む。WASM は形式ごとに gzip 後で 0.7MB ほど。
  - 0.x で変更が速い部品なので、版を固定する。
  - 日本語は閲覧する端末のフォントで描く。iPad に MS 明朝・MS ゴシックは無いので、行送りやページの切れ目が元とずれることがある。
  - Excel の表は左右キーでセルを移るので、ビューアーの前後の移動に回さない。
- **動画の操作部分は `<video>` の標準コントロールを使わずに自前で作る** (`frontend/src/lib/components/video-player.svelte`)。
  音声のプレイヤーと同じく、標準の見た目と操作はブラウザーごとに違い (iPad の Safari には繰り返し再生が無い)、タップ領域 44px も保証できないため。
  - 操作は再生・一時停止・シーク・10秒戻す・10秒進む・繰り返し再生・ミュート・全画面。画面の下に1段 (スマートフォン幅ではシークバーと操作の2段) で常に出す。
  - 動画を押しても再生・一時停止する。止まっている間は、動画の中央に再生ボタンを出す。
  - 動画の中の左右キーは10秒戻す・進むに使い、ビューアーの前後の移動に回さない。標準の操作部品と同じで、全画面で見ている間にファイルが替わらないようにするため。
  - **ほかのキーは YouTube に揃え、画面にボタンのある操作にだけ割り当てる** (`frontend/src/lib/video-keys.ts`)。スペースと K で再生・一時停止、J・L で10秒戻す・進む、M でミュート、F で全画面、Home・End・0〜9 で先頭・末尾・全体の 0〜90% へ移る。動画サイトに慣れた人が、いつものキーで操作できるようにするため。
    - 音量 (上下キー) と速さ (Shift + < >) は割り当てない。画面に操作が無く、今の値が見えないため。
    - 左右キーと違い、ビューアーのどこにフォーカスがあっても効かせる。開いた直後のフォーカスは「新しいタブで開く」にあり、動画の中だけで受けると押しても効かないため。ボタンの上のスペースは、そのボタンに任せる。
    - F で全画面にするときは、フォーカスを動画に移す。全画面にする要素の外にフォーカスがあると、body に落ちて左右キーが届かなくなるため。
  - 繰り返し再生は最初はオフ。切り替えた状態は `localStorage` に置き、その端末で覚える (音声の「続けて再生」と同じ)。
  - 全画面は、動画と操作をまとめて全画面にする。iPhone は要素の全画面が無いので、動画だけを OS の全画面にし、そこでは OS の操作になる。
  - 再生を始めたら、ページ内の音声のプレイヤーを止める。
- **テキストは中身を取ってきて表示する**。UTF-8 として読めなければ Shift_JIS で読む。Windows のメモ帳が古くから保存してきた日本語のテキストに多いため。
- **ソース (.yml・.json・.ts・.py など) は、等幅の書体で、言語に合わせた色を付ける** (`frontend/src/lib/code-highlight.ts`)。地の文 (txt・log・csv など) は本文の書体のまま色を付けない。
  - 言語は拡張子で決める。中身から言語を当てることはしない。外れが多いため。
  - highlight.js を使う。本体 9KB・言語ごとに 1〜5KB (gzip 後) で、Shiki (本体 58KB、言語によっては 180KB 超) より軽いため。PDF.js と同じく開くときに読み込み、言語の定義も使う分だけ読む。
  - 色は GitHub の配色 (Primer) を元に、ライト・ダークとも地とのコントラストが 4.5:1 以上のものだけを使う。
  - 256KB を超えるテキストは色を付けない。2MB の JSON は Mac でも色付けに 0.8 秒かかり、iPad では画面が固まるため。
- **Markdown (.md) は、組んだプレビューで開き、上部のバーでソースに切り替えられる**。GitHub のファイルの表示 (「Preview / Code」) に倣う。
  - 変換はマニュアルと同じ marked。日本語の行の間の改行もマニュアルと同じく詰める。コードの塊には、言語の指定 (` ```yaml `) に合わせてソースと同じ色を付ける。
  - **組んだ HTML は DOMPurify で無害化してから出す**。利用者のフォルダーの .md は外から来た中身で、中の HTML やスクリプトがログインの Cookie と同じオリジンで動いてしまうため。
    残すのは Markdown が出す要素と属性だけにする。DOMPurify の既定は `<style>`・`<form>`・`style` 属性も通し、画面を覆う偽の入力欄なども作れるため。`class` も、コードの塊の言語の指定のほかは外す (アプリの class で画面を覆えるため)。
  - 256KB を超える .md は組まずにソースで見せる。色付けと同じく、iPad で画面を固めないため。
  - リンクは http・https・mailto を別のタブで開く。画像は http・https を読み込む。
  - **相対パスの画像とリンクは、その .md のある場所から解決する** (`frontend/src/lib/content-location.ts`)。そのまま渡すと、このページの URL から解決されて別のものを指すため。
    解決できるのはフォルダーとアーカイブのファイルで、同じコンテンツの中を指すものだけ。ファイル1つのコンテンツ・登録先の外を指すもの・`/` で始まるものは解決せず、リンクを外し、画像は代わりの文字にする。解決した先が読めなかった画像も、壊れた画像の印を出さずに代わりの文字にする。`/` で始まるものはリポジトリの根から書かれていることが多く、登録先の根と一致しないため。
    相対パスのリンクは、押すとリンク先をこのビューアーで開く。開いた一覧にあればそこへ移り、前後もそのまま送れる。一覧に無ければそのファイルだけを開き、ビューアーで開けない種類は別のタブで開く。
