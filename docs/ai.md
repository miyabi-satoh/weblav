# AI の機能

WebLAV は AI のキーを持たず、運営者のサーバー (窓口。→ account-server.md) を通して AI を呼ぶ。使った分は、管理者が窓口のアカウントに前払いした残りから引かれる。
この文書は WebLAV の側 (`src/ai.rs`・`src/api/ai.rs`・`src/api/ai_links.rs`) を書く。窓口の側の約束は account-server.md にある。

画面では、窓口を「WebLAV のアカウント」、結ぶ・外すを「PC を登録・登録を解除」と呼ぶ (→ account-server.md「作り」)。

## PC の登録

設置した PC を窓口のアカウントに登録すると、その設置で AI を使えるようになる。操作できるのは管理者だけ。

- 状態は、データの置き場の `ai-account.json` に持つ。ファイルが無ければ未登録 (`unlinked`)、登録の途中 (`pending`) は検証用の値と始めた時刻、登録済み (`linked`) はアプリ用のトークンを持つ。
  - ファイルは所有者だけが読める権限で作る。トークンがあれば、その設置の残りを使えるため。
  - バックアップには入れない。この PC と窓口のアカウントを結ぶものであり、別の PC に戻したバックアップが同じトークンを使うと、窓口で PC ごとに登録を外せなくなるため。バックアップに入るのは DB と blob だけ (→ access.md「バックアップとリストア」) なので、入れないための処理は無い。
- 登録は、窓口の画面で認めた印を WebLAV が問い合わせる流れにする (→ account-server.md「PC をアカウントに登録する」)。
  1. `POST /admin/ai/link` で検証用の値を作って保存し、窓口の画面の URL と確認コードを返す。URL には検証用の値の SHA-256・サイト名・PC の名前 (OS が mDNS で名乗る名前) を付ける。確認コードは、その SHA-256 の頭の6桁を大文字にしたもので、窓口の画面にも同じものが出る。
  2. 管理者がその URL を開いて認める間、画面が数秒おきに `POST /admin/ai/link/poll` を呼ぶ。WebLAV は検証用の値を窓口へ送り、トークンが返れば保存して登録済みにする。
  - 登録の途中にもう一度始めても、同じ検証用の値を使う。窓口の画面を開いた後に押し直しても、開いてある画面で認められるようにするため。
  - **登録の途中は、始めてから 30 分で未登録に戻す**。状態を読むとき・始めるとき・問い合わせるときに確かめ、過ぎていれば保存した検証用の値を消す。始め直すと新しい値になる。窓口でサインインして認めるのに足り、漏れた URL が使える時間は短くするため。
  - 途中の取り消しは `DELETE /admin/ai/link`。問い合わせの最中に取り消されたら、受け取ったトークンは保存せず、窓口でも外す。
- 解除 (`DELETE /admin/ai`) は、手元のトークンを消してから窓口に外すよう頼む。窓口につながらなくても、この PC の側は未登録に戻る。
- **窓口がトークンを断ったら (401)、手元のトークンを消して未登録に戻す**。管理者が窓口のアカウントの画面で登録を外したときに当たる。
- `GET /admin/ai` は状態と、登録済みなら窓口で見たメールアドレスと残りの割合を返す。窓口につながらないときは、登録済みのまま残りを空にし、`accountUnreachable` を立てる。
- つなぐ窓口はビルドに埋め込む (`ai::ACCOUNT_SERVER_URL`)。開発版は手元で動かす窓口 (`just dev-account-server`) につなぐ。本番の残りを開発で減らさないため。

## 誰が使えるか

残りは設置で1つを共有するので、使わせる人を管理者が選ぶ。

- 管理者は常に使える。編集者 (`user`) は、`users.ai_allowed` の印が付いた人だけが使える。既定は使えない。ログインしていない人は使えない。
- 印は、ユーザー管理の `PUT /admin/users/{id}/ai-allowed` で付け外しし、ユーザーの一覧の `aiAllowed` で返す。
- `GET /ai/availability` は、登録済みで、その人が使えるかを返す。画面が AI のボタンを出すかを決めるのに使う。窓口には問い合わせないので、残りが無いことは使ったときに分かる。

## 窓口の呼び出しと、使った量の記録

AI を使う機能は、`ai::generate` を通して窓口の `POST /v1/ai` を、`ai::search` を通して窓口の `POST /v1/search` (Web の検索) を呼ぶ。使えるか・登録済みか・長さを確かめ、答えを取り出し、使った量を記録するまでをここにまとめる。

- 窓口の呼び出しと登録の状態のファイルの読み書きは同期なので `run_blocking` に載せる。登録済みかどうかだけはメモリの値を見るので、非同期のハンドラからそのまま読める。
- 窓口を呼ぶ ureq の `Agent` は、待つ上限ごとに1つ作って使い回す。作るたびに OS の証明書ストアを読むため。
- AI の返事は 60 秒まで待つ。窓口が 50 秒で諦めるので、それより長く待って、使った量の付いた窓口の返事を受け取る。
- 指示文と文の合計が 20万文字 (UTF-16 の単位。窓口の上限) を超えるものは、窓口へ送らずに断る。
- 答えは、返事の `steps` のうち `type` が `model_output` のものの `content[].text` をつなげたもの。文が無い返事は AI の側の失敗として扱う。
- **使った量は `ai_usage` に、呼び出しごとに1行残す**。窓口は誰が使ったかを知らないので、内訳は WebLAV にだけある。
  - 量は、窓口が `x-weblav-used` ヘッダーで返した値 (1回の購入で付く量を 1,000,000 とした整数) をそのまま入れる。失敗の返事でも、ヘッダーがあれば記録する。残りは引かれているため。
  - ユーザーを消すと `user_id` は NULL になり、使った時点のユーザー名 (`username`) が残る。
  - 記録に失敗しても、届いた答えは返す。
- `GET /admin/ai/usage` は、ユーザーごとの回数・量の合計・最後に使った日時を返す。量は整数のまま返し、画面が割合に直す。

この口を使うのは、アーカイブの軸の定義 (→ archive.md「軸の定義を外部の AI で作る」) と、AI が集めるリンク (下の節)。

## AI が集めるリンク

グループに付ける機能。関心の言葉で Web を検索し、AI が選んだページを、グループの中身の下にリンクのカードで並べる (`src/api/ai_links.rs`)。
新しいコンテンツの種類にはしない。手で足すだけなら、グループとリンクで同じことができるため。

- **設定は `ai_link_groups` に、グループごとに1行持つ** (`PUT /contents/{id}/ai-links/settings`)。書き換えられるのは、そのグループを書き換えられる人 (→ access.md「ロールと操作」)。
  - 関心の言葉は、1行が1つの検索の語。5行まで・1行 200文字 (UTF-16 の単位) まで。窓口が1回の検索で受ける語の数と長さに合わせる。
  - `contents` に列を足さないのは、コンテンツの更新 (完全上書きの PUT) と切り離して書き換えるため。
  - 外すと、集めたリンクも消える。関心の言葉を変えても、集めたリンクは次に集め直すまで残る。
- **集め直すのは、人が押したときだけ** (`POST /contents/{id}/ai-links/refresh`)。定期の更新は持たない。誰も見ていない間に残りが減るのを避けるため。
  - 押せるのは、AI を使えて、そのグループを見られる人。
  - 1回の集め直しで、検索を2回 (絞らない・1年以内) と、AI を1回呼ぶ。定番のページと新しい記事の両方を候補にするため。1か月以内では絞らない (量産の記事が多く混じる)。
  - 検索は、画面の表示言語のページに絞る。国で絞るのは日本語のときだけ (言語だけでは国が決まらないため)。
  - AI には、候補に番号を振って渡し、番号の並びだけを答えさせる。URL を書かせると、実在しない URL が混じるため。選ぶのは 12 件まで。
  - 答えに番号の並びが無ければ `ai_upstream` にし、前に集めたリンクを残す。
  - 同じグループを集めている最中の集め直しは `ai_rate_limited` で断る。残りを二重に使わないため。
  - 使った量は、3回の呼び出しごとに `ai_usage` に `links` として残す。
- **持つのは URL とタイトルだけ** (`ai_links`)。検索の抜粋は AI が選ぶためだけに使い、保存しない。カードの説明と画像は、ほかのリンクと同じく WebLAV が行き先から取る (→ ui.md「リンクのカード」)。
  - カードの取り直しは、取り直しの API にグループの id を渡して頼む (`aiLinksGroup`)。サーバーは見る権限を確かめ、集めたリンクの URL だけを取りに行く。
- **グループに登録してあるリンクと同じ URL は、並べない** (`GET /contents/{id}/ai-links`)。候補からも外す。
  - 残したいリンクは、詳しい表示の「このグループに登録する」で、ふつうの `link` コンテンツにする。集め直しても残り、外すのはリンクの削除。
- 集め直す操作は、グループの画面の AI の分の見出しの段と、コンテンツ管理の一覧の行のメニューに置く。ホームやグループの一覧の行には置かない。開かずに押せると、どれだけ古いかを見ないまま残りを使うため。
- リンクの一覧のファイル (`.links.toml` → ui.md「リンクの一覧のファイル」) は、別の機能として残す。窓口を使わず、ファイルを書き出せる人が自分で集めたリンクを見せる。

## エラーの code

窓口の断り方ごとに `code` を分け、画面が何をすればよいかを伝えられるようにする (→ architecture.md「エラーの契約と表示言語」)。

| code | 状態 | 起きること |
| --- | --- | --- |
| `ai_not_allowed` | 403 | 印の付いていない編集者が使おうとした |
| `ai_not_linked` | 409 | PC を登録していない。窓口がトークンを断った (401) ときも、未登録に戻してこれを返す |
| `ai_no_credit` | 402 | 残りが無い (窓口の 402) |
| `ai_rate_limited` | 429 | 短い間に呼びすぎた (窓口の 429)・同じグループのリンクを集めている最中 |
| `ai_too_large` | 413 | 送る文が上限を超える (送る前に分かったものと、窓口の 413) |
| `ai_upstream` | 502 | AI か検索の側の失敗 (窓口の 502)・答えの文が無い返事・リンクを選ぶ答えに番号の並びが無い |
| `account_server_unavailable` | 502 | 窓口につながらない・窓口が想定外の返事をした |

- 窓口の 502 は、本文の `error` が `upstream` のときだけ `ai_upstream` にする。窓口の手前 (CDN など) が返す 502 は、つながらないのと同じに扱う。
