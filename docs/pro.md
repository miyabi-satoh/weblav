# Free と Pro

Pro を売り、Pro かどうかを WebLAV が確かめる仕組みは、次の3つに分かれる。

- WebLAV の中で上限を数えて止める (→ 「上限を数えて止める」)
- WebLAV の設置を窓口のアカウントに結び、窓口が出す期限付きの「許可」を WebLAV が手元に持って自分で確かめる (→ 「結び付きと許可」・「結ぶ・確かめる・外す (WebLAV の側)」)
- アカウント・販売 (サブスク)・許可の発行を受け持つ窓口 (→ 「アカウントと販売の窓口」)。Cloudflare Workers の無料枠に置く

この文書とコードの語は、画面 (WebLAV・窓口・メール・マニュアル・規約類) では次のように呼ぶ。利用者に仕組みの語を見せないため。

| この文書 | 画面 |
|---|---|
| 結ぶ・結び直す・外す | (PC を) 登録・登録し直す・登録を解除 (英語は link・link again・unlink) |
| 結んでいる WebLAV | 登録している PC |
| 返しのコード | 登録コード |
| 窓口 | WebLAV のアカウント (のページ・サービス) |

## 上限を数えて止める

- **足す操作の中で数える**。数えてから足すまでの間に別の要求が割り込まないよう、コンテンツは `contents_write_lock`、ユーザーは `users_write_lock` を持つ間に数える。
    SQLite の DEFERRED トランザクションは数えた時点では書き込みの鍵を取らず、トランザクションだけでは2つの要求が同時に通るため (最後の admin の確認 (→ access.md「admin の最後の1人」) と同じ理由)。
    アップロードとリンクは、鍵を取る前にも1度数える。上限に当たっているのに、大きいファイルを受け取り切ってから、またはリンク先へ接続してから断らないため。
  - コンテンツ: `type` ごとの件数。作成者・公開範囲・親を問わない。
  - ユーザー: `role` ごとの件数。ユーザーの作成と、ロールの変更 (`user` → `admin`、`admin` → `user`) の両方で数える。
  - 最初の管理者を作るセットアップ (→ access.md「初回セットアップ」)・リストア (→ access.md「バックアップとリストア」)・`weblav-cli --create-user` では数えない。どれも止めると戻れなくなるため (CLI は管理者のパスワードを忘れたときの戻り道)。
- **断るときは 409 `free_limit_reached`**。`detail` に `{ kind: "freeLimit", target, limit }` を添える (`target` は `archive`・`admin` など)。
  画面が「Free では〜は N 個まで」と出すのに、どれに当たったかと上限の数が要るため (→ architecture.md「エラーの契約と表示言語」の「値を見せないと直しようがない」)。
- **上限の数はバックエンドだけが持つ**。画面は、管理画面で使うために今の件数と上限を API から受け取る。
- **画面では、サイト設定の「Pro」の区画に、対象ごとの今の件数と上限を出す** (→ 「結ぶ・確かめる・外す (WebLAV の側)」)。上限に近いことを、ほかの画面では知らせない。
  当たったときは、断る文言が Pro で外れることを伝える。

## 結び付きと許可

**WebLAV の設置を、管理者が窓口のアカウントに結ぶ**。WebLAV のログインはローカルのまま (→ access.md)。
リモートのアカウントでログインさせると、ネットや窓口が止まったときに管理画面に入れなくなるため。
結んだ WebLAV は、窓口が出す期限付きの「許可」を手元に持ち、自分で確かめる。

- **秘密**: 結ぶたびに WebLAV が使い捨ての X25519 の鍵を作り、窓口の X25519 の公開鍵と組み合わせて秘密 (32バイト) を導く。窓口は WebLAV の公開鍵だけを D1 に持ち、秘密は要るたびに自分の秘密鍵から導き直す (D1 だけが漏れても秘密は分からない)。
  - 用途ごとに別の値を使う。どれも HMAC-SHA256 の出力の先頭から切る。比べるのは定数時間で。
  - ADR: `pro.json` ごと別の PC に写すと、窓口からは1台に見える。確かめのたびに秘密を進めれば塞げるが、確かめの途中で切れたときに結び付きを失わない作りが要り、重い。写すのは PC の移し替えのような正当な使い方が多いので、この弱さを受け入れる。
- **申し込み**: 版 (1バイト、今は `1`)・`link_kid` (1バイト)・作った日時 (UNIX 分、4バイト、ビッグエンディアン)・WebLAV の公開鍵 (32バイト) を Crockford の base32 にしたもの。同じ WebLAV の結び直しでは、後ろに前の結び付きの id (8バイト) と、前の秘密で作った結び直しの符号 (8バイト) を足す。窓口はこれで同じ枠を使い直し、台数を増やさない。
  - 窓口は作ってから24時間を過ぎた申し込みを受け付けない。古い QR コードを後から読んで、使われない枠を作らないように。同じ公開鍵の申し込みを2度通しても、同じ結び付きのまま返しのコードを出し直すだけ。
  - 外した結び付きの公開鍵は、申し込みの期限 (24時間) が過ぎるまで覚えておき、同じ申し込みでは結ばない。外した後に古い QR コードを読み直して、WebLAV が捨てた秘密の枠を作らないように。
  - WebLAV で「やめる」を押した申し込みは、窓口には伝わらない (ネットにつながらない WebLAV もあるため)。24時間のうちに窓口で結ばれると使われない枠ができるが、一覧に出るので外せる。

- **許可は2種類**。どちらも中身はプラン・発行日・期限。
  - **署名付きの証明**: `{ v: 2, proof_kid, account, installation, plan, issued_at, expires_at }` の JSON に Ed25519 の署名を付け、`base64url(中身).base64url(署名)` にしたもの (時刻は UNIX 秒)。ネットにつながる WebLAV が窓口から直に受け取る。持ち主にも作れない。
  - **返しのコード**: プラン・発行日 (2026-01-01 (UTC) からの日数)・発行日から期限までの日数と、秘密で作った49ビットの符号 (→ 「符号の作り方」)。15文字 (`XXXXX-XXXXX-XXXXX`)。ネットにつながらない WebLAV に、人が打ち込む。期限はその日の終わり (UTC)。
    - ADR: 署名を入れると打ち込める長さに収まらない (Ed25519 で約105文字)。秘密は WebLAV の手元にあるので、道具を使えば作れてしまう。それでも偽造した WebLAV は、窓口への通信を止めない限り次の確かめで Free に戻る。オフラインはまれな使い方なので、この弱さを受け入れる。
- **期限**: 許可を出す時点で有効なサブスクの「払い終えた期間の終わり」に猶予を足した日 (カードは7日、組織向けは請求書の支払い期日の30日)。払い終えた期間の終わりは、払われた請求書の期間の終わりで、窓口がサブスクごとに `subscriptions` に持つ (→ 「売り方」)。
  - 有効なサブスクは、打ち切られていない (下記) で、払い終えた期間の終わり + 猶予が今より後のもの。アカウントの Pro は、有効なサブスクのうち組織向けがあれば組織向け (期限はそのうち最も遅いもの)、無ければ個人向け (同じ) にする。どちらかが切れても、もう片方が有効なら Pro のまま。知らせはサブスクの行を直すだけで、Pro はいつも全部の行から求める。
  - ネットで受け取る証明は、発行から45日までに切る。年額の期限まで延ばすと、壊れて確かめに来ない PC を外しても、その枠が最長1年空かないため。30日おきに確かめるので、つながる PC は切れる前に延びる。
  - 支払いが遅れている (`past_due`) 間は延ばさない。猶予の中で払われれば、次の確かめで延びる。
  - 終わった (`canceled`) サブスクには猶予を足さない。もう払われないので、期間の終わりで切れ、すぐ申し込み直せる。
  - 解約・返金・不審請求で Pro が無くなると、窓口はそれ以後の許可を出さない (`no_plan`)。もう出した許可は取り消せないので、ネットにつながる WebLAV は次の確かめで、つながらない WebLAV はその許可の期限で Free に戻る。
- **時計**: WebLAV は PC の時計で期限を見る。時計を戻して期限を延ばせないよう、次の2つで止める。
  - 発行日より前の時計 (1日まで許す) では、許可を受け取らない。
  - 見た最も新しい時刻を覚えておき、時計がそれより1日を超えて戻っていれば Free として動く (ログに残す)。時計を直せば戻る。
- **公開鍵は WebLAV に埋め込む**。Ed25519 (証明の確かめ。`proof_kid` は文字列) と X25519 (秘密を導く。`link_kid` は 0〜255 の数) の公開鍵を、それぞれの `kid` ごとに持つ。鍵を替えるときは新しい `kid` を足した版を出す。古い `kid` を残す限り、前の証明・結び付きも使える。
  - 開発版 (debug ビルド) だけは `dev-local` の鍵を信じる。手元で動かす窓口 (→ 「アカウントと販売の窓口」) が使い、配る版では通らないので、秘密鍵をリポジトリ (`account-server/dev.vars.example`) に置いている。テストもこの鍵で証明を作る。
- **置き場所は、設定とデータの置き場の `pro.json`**。DB には入れない。
  - 結び付き (id・`link_kid`・秘密)・許可・結んだアカウントのメールアドレス (分かっていれば)・最後に確かめた日時・見た最も新しい時刻・結びかけの申し込み (秘密) を持つ。
  - バックアップ (→ access.md「バックアップとリストア」) に入れないため。データを別の PC に戻したときは、そちらで結び直す。
  - 結びかけの申し込みを残すのは、QR コードを読んでから返しのコードを打ち込むまでの間に、WebLAV を起動し直しても続けられるように。
  - 起動したときに読み、確かめられない許可は無いものとして動いてログに残す。

### 符号の作り方

窓口と WebLAV で同じ値を出すための規格。文字列はすべて UTF-8 のバイト列。

| 値 | 作り方 |
|---|---|
| 共有の値 | X25519(WebLAV の秘密鍵, 窓口の公開鍵) (RFC 7748)。全部 0 なら断る |
| 秘密 | HKDF-SHA256 (RFC 5869)。salt = `"weblav-link-v1"`、IKM = 共有の値、info = `link_kid` (1バイト) ‖ WebLAV の公開鍵 ‖ 窓口の公開鍵、長さ 32 |
| 結び付きの id | HMAC(秘密, `"weblav-installation-id"`) の先頭8バイト。16進で持つ |
| 確かめの認証 | HMAC(秘密, `"weblav-check"`) の全32バイト。16進で送る |
| 結び直しの符号 | HMAC(前の秘密, `"weblav-relink"` ‖ 新しい公開鍵) の先頭8バイト |
| 返しのコード | 上位から プラン (1ビット。0 = 個人向け、1 = 組織向け)・発行日 (16ビット)・日数 (9ビット) を並べた26ビットを、上を 0 で埋めて4バイトにする (ビッグエンディアン)。符号 = HMAC(秘密, `"weblav-grant"` ‖ その4バイト) の先頭49ビット。26ビット ‖ 49ビットの75ビットを、上から5ビットずつ Crockford の base32 にする |
| 外した証し | 結び付きの id (8バイト) ‖ HMAC(秘密, `"weblav-release"`) の先頭6バイト。14バイトを、末尾を 0 で埋めて5ビットずつ Crockford の base32 にする (23文字) |

- Crockford の base32 の読み取りは、区切り (`-`)・空白を除き、大文字にそろえ、`O`→`0`・`I`/`L`→`1` に読み替えてからにする。
- 返しのコードは、同じ秘密のままなら何度打ち込んでも同じ許可になるだけ。外した証しも、2度目からは何もしない。

## 結ぶ・確かめる・外す (WebLAV の側)

### 結ぶ

1. 管理者がサイト設定の「Pro」の区画で「Pro にする」(画面の語。結ぶ操作) を押す (`POST /api/v1/admin/pro/link`)。サーバーは新しい秘密を作って `pro.json` に結びかけとして残し、窓口の結ぶ画面の URL (`/account/link?r=<申し込み>&name=<サイト名>&pc=<PC の名前>&lang=<言語>`) を返す。
   区画は設定の画面の最後に置く。タブを増やすほどの中身が無く、ほかの設定と同じく `admin` だけが触るため。
2. 画面は、その URL の QR コード・「ブラウザーで開く」のボタン (新しいタブ)・返しのコードの入力欄を出す。
3. 管理者は窓口 (スマートフォンで QR コードを読むか、ボタンで開く) でサインインし、「この PC を登録」を押す。Pro が無ければ料金ページへ案内し、申し込んで払った後にこの画面へ戻る (→ 「売り方」)。
4. **ネットにつながる WebLAV**: 画面を開いている間、画面は3秒おきに `POST /api/v1/admin/pro/link/poll` を呼び、サーバーは5秒より短くない間隔で窓口に確かめる (下の `check`)。結ばれていれば証明を受け取って書き、Pro になる。打ち込みは要らない。
5. **ネットにつながらない WebLAV**: 窓口の画面とメールに出た返しのコードを入力欄に打ち込む (`POST /api/v1/admin/pro/link/code`)。サーバーは結びかけの秘密で符号を確かめてから書く。

- 確認コードを見比べる手順は無い。そのため、他人から届いたリンクで「結ぶ」を押すと、リンクを作った他人の WebLAV が自分の Pro で Pro になる。
  - 窓口の結ぶ画面には、結ぶ WebLAV の名前と「自分の WebLAV の画面から開いたのでなければ押さない」旨を出す。
  - 結んでしまっても、窓口の一覧に名前が出るので外せる。外した後も、その WebLAV が次に確かめるまで (最長30日) は Pro のまま残り、枠も空かない。確かめに来ない WebLAV の枠は、許可の期限に空く (一覧にその日を出す)。
  - ADR: 見比べる手順は、QR コードを読む・打ち込むたびに1手間増やす。押させるには相手をだまして窓口でサインインまでさせる必要があり、得られるのも1台分の Pro だけなので、手間を増やすほどではないと見る。
- 「やめる」で結びかけを捨てる。結んである WebLAV の結び直しでは、新しい許可を受け取るまで今の許可を使い続ける。

### 確かめる

**結んである WebLAV は、次のどれかに当たってから使われたときに、サーバーが自分で窓口へつなぐ** (`POST /v1/installations/check`)。

- 許可があり、前の確かめから30日たった、または期限まで7日を切った (このときは前の確かめから1時間はつながない。更新の支払いを待つ間、要求のたびにつながないように)。
- 許可が無い (`no_plan`・`over_limit` を受けた後や、期限が切れた後)。買い直す・ほかを外すと、次に使われたときに Pro に戻る。前の確かめから1時間はつながない。

- 使われたときは、どの HTTP の要求でもよい (ログインしていない閲覧も含む)。応答は待たせず、裏で確かめる。誰も使っていない間は通信しない。
- 失敗したら1時間は試し直さない。窓口が止まっている間、要求のたびにつながりに行かないように。
- 窓口の答えで手元を合わせる:
  - `ok`: 新しい証明を確かめて書く。返しのコードで結んだ WebLAV も、ここで証明に切り替わる。
  - `no_plan` (アカウントに Pro が無い。解約・返金など)・`over_limit` (台数の上限を超えた分): 許可を消して Free にする。結び付きは残す。区画には、アカウントのページで買う・外すと戻ることと、「今すぐ確かめる」を出す。
  - `unbound` (窓口で外された・窓口が知らない): `pro.json` を消して Free にする。
- 「今すぐ確かめる」(`POST /api/v1/admin/pro/check`) は、条件によらずその場で確かめ、結果を待って返す。買った直後・外した直後に合わせるため。
- ネットにつながらない WebLAV は、期限まで7日を切ると区画に知らせを出す。管理者は「登録し直す」を通す (同じ枠のまま、新しい返しのコードを受け取る)。

### 外す

**「この WebLAV をアカウントから外す」は、`pro.json` を消して Free にし、「外した証し」を窓口へ渡す**。PC を人に譲るとき・台数を空けるとき用。

- 外した証し: → 「符号の作り方」。
- サーバーが窓口へ直に送る (`POST /v1/installations/release`)。届かなければ、画面に外した証しの QR コード (`/account/release?c=…`) と文字列を出し、スマートフォンで読んでもらう。読まれなくても手元は外れている (窓口の枠が許可の期限まで空かないだけ)。

### 窓口との形

JSON。`account-server/` はこれに合わせる。

- `POST /v1/installations/check` に `{ installation, auth, name, pc }` (`auth` は確かめの認証。→ 「符号の作り方」) → `{ status: "ok", proof, email }`・`{ status: "no_plan", email }`・`{ status: "over_limit", email }`・`{ status: "unbound" }`
  - 時刻は入れない。時計のずれた PC が確かめに失敗し続けないように。盗み見た要求を送り直されても、その WebLAV でしか使えない証明が返るだけ。
- `POST /v1/installations/release` に `{ code }` → 204 (知らない・外し済みでも 204)

- **手元で試す**: `just dev-account-server` で窓口を手元で動かし、開発版の WebLAV はこの手元の窓口 (`http://127.0.0.1:8787`) を使う。開発版は本番の鍵を信じないため。
  メールは送らず、サインインのリンクと返しのコードを窓口のログに出す。Pro は `just dev-account-grant <メールアドレス>` で付ける。
- **外へ送るのは、結び付きの id・認証の符号・サイト名・PC の名前だけ**。コンテンツ・利用者の情報は送らない。PC の名前は mDNS のホスト名から `.local` を除いたもので (→ architecture.md「LAN からの到達性」)、窓口の一覧で見分けるためだけに使う。サイト名を付けていない WebLAV はどれも `WebLAV` になり、名前だけでは見分けられないため。結んでいない WebLAV は一度も窓口へつながらない。
- 窓口の URL はビルドに埋め込み、`config.toml` には置かない。利用者が変える場面が無いため。開発版 (debug ビルド) は手元の窓口の URL を埋め込む。

## アカウントと販売の窓口

**Cloudflare Workers の無料枠に置き、データは D1 に持つ**。
無料枠は1リクエストの CPU が 10ms までなので、パスワード (わざと重いハッシュ) は持たない ([Workers Limits](https://developers.cloudflare.com/workers/platform/limits/))。

- **置き場所**: このリポジトリの `account-server/` (TypeScript・wrangler・Hono)。許可の形を WebLAV と一緒に変えるため。`just ci` から `just account-server-check` (整形・生成した型・型検査・テスト) を流す。
  ホスト名は `weblav.amiiby.com`。
  ルートに紹介、`/pricing/` に料金、`/terms/`・`/privacy/` に規約類、`/account/` に窓口の画面を置く。
  - 紹介と規約類は `site/` (Astro) に置き、ビルドしたものを窓口の Worker が静的なアセットとして出す。`/account`・`/v1/` だけを Worker が受ける (`account-server/wrangler.jsonc`)。
- **アカウントは WebLAV の Pro 専用**。
  - メールのリンクを必ず置き、外部のサインインは Google と Apple にする。どちらも、秘密の値がそろったときだけボタンを出す。
  - Google: OpenID Connect の Authorization Code + PKCE + `state`・`nonce`。往復の間の値は Cookie に持ち、認証の要らない D1 の書き込みを増やさない。
    - ID トークンは client secret でトークンのエンドポイントから直接受け取るので、署名は確かめず、発行元・宛先・期限・nonce を確かめる (Google の OpenID Connect の資料)。
    - Google の識別子 (`sub`) → 同じメールアドレスのアカウント → 新しいアカウント、の順で結ぶ。
    - Google が持ち主を確かだと言えるメール (Gmail か、`email_verified` が true で `hd` がある Google Workspace のもの) だけを受け付け、ほかは断ってメールのリンクへ案内する。ほかのメールは Google アカウントを作ったときに確かめただけで、今の持ち主かは分からない (Google の資料「Verify the Google ID token on your server side」)。受け付けると、他人のメールで作った Google アカウントから、そのメールのアカウントに入れてしまう。
    - 同じアカウントに別の Google アカウントがもう結ばれていれば結ばず、メールのリンクか前の Google アカウントで入ってもらう。
  - Apple: Sign in with Apple の REST API の Authorization Code + `state`・`nonce` (Apple のエンドポイントに PKCE の項目が無い)。トークンと引き換える client secret は、Apple の秘密鍵 (.p8) で署名した ES256 の JWT を呼ぶたびに作る。結び方・確かめる項目・結ばないときは Google と同じで、`email_verified` が true のメールだけを受け付ける。
    - 戻りは Apple のサイトからの POST (`form_post`)。往復の値の Cookie は `SameSite=None` にし、戻り先 (`/account/login/apple/callback`) だけは `Origin` を確かめず、`state` の照らし合わせで守る。言語の Cookie はこの POST に付かないので、言語も往復の値に持つ。そのため https でしか通らず、手元では試せない。確かめる環境 (`env.staging`) で試す。
    - 「メールを非公開」を選んだ人は、Apple の転送用アドレス (`@privaterelay.appleid.com`、2026 年の後半からの新しいアドレスは `@private.icloud.com`) のアカウントになる。転送用アドレスには、Apple の開発者のページに登録した送り元のメールしか届かない。窓口が送るメールのドメインは登録しておき、Stripe の Checkout にはメールを渡さず、支払いの画面で入れてもらう。
  - メールのリンク: 1回きり・15分で切れるトークンを D1 にハッシュで持ち、Resend で送る。
    - リンクを開いただけではサインインせず、開いた画面のボタン (POST) で使い切る。メールのサービスがリンクを先に開いて確かめることがあり、そこで使い切られないように。
    - 同じアドレスへは1時間に5通まで。他人のアドレスへ送りつけるのに使われないように。
  - セッションは D1 (`sessions`) に id のハッシュを持ち、30日で切れる。Cookie は https で `__Host-` を付ける。
    `SameSite` は `Lax` にする。WebLAV の画面やメールのリンク (よそのサイトからの移動) で開いたときに、サインインが見えなくならないように。フォームの送信は `Origin` を確かめて守る。
  - 同じメールアドレスなら、どの方法で入っても同じアカウント。Google・Apple で入ったあと、そちらのメールアドレスが変わっても、識別子で同じアカウントに入る。
  - **消す**: 削除の請求は問い合わせで受け、運営者が `account-server/scripts/delete-account.mjs` で消す。先にサブスクをその場で解約する (D1 の行に無い組織向けのサブスクも、Stripe で metadata の `account_email` から探して解約する)。結び付き・サインインの状態・Google・Apple の結び付きは消え、`subscriptions` の行は結び付きだけを外して残す (後から届く知らせで Pro を付け直したり、アカウントを作り直したりしないように)。購入の台帳は結び付きだけを外して7年残す。過ぎたものは、Stripe の知らせを受けるたびに消す。
- **結ぶ** (`/account/link`。→ 「結ぶ」):
  - サインインした後、結ぶ WebLAV の名前・今の台数と上限を出し、「この PC を登録」で結ぶ。結んだら返しのコードを画面に出し、メールでも送る (QR コードを読んだスマートフォンと、打ち込む PC の画面が離れていても見られるように)。
  - **台数の上限は、個人向け3台・組織向け10台** (両方持っていれば組織向け)。上限に当たっていれば結ばず、結んでいる WebLAV の一覧から外せるようにする。
  - 上限は確かめのたびにも比べる。超えていれば、古く結んだ順に上限の台数までだけ許可を出し、残りには `over_limit` を返す。組織向けから個人向けに下げて台数を保つ抜け道を作らないため。アカウントのページに「上限を超えています」と出す。
  - 外した結び付きは、WebLAV がそれを受け取った時点 (外した証しが届いた・確かめに `unbound` を返した) で消し、枠を空ける。受け取らないまま (オフラインの WebLAV を窓口だけで外した) なら、最後に出した許可の期限まで台数に数える。外して付け替えるだけで台数を超えて使えないように。
  - 申し込みの結び直しの部分 (前の id と符号) が、このアカウントの結び付きと合えば同じ行の公開鍵を入れ替える。合わなければ新しく結ぶ。
  - 名前が空 (サイト名を付けていない) なら `WebLAV` にする。確かめで空の名前が届いたときは、前の名前のままにする。
  - 一覧・結ぶ画面・メールでは、PC の名前を添えて「サイト名 (PC の名前)」と出す。PC の名前が読めなかった WebLAV からは空で届くので、サイト名だけを出す。確かめで空が届いたときは、前の値のままにする。
- **アカウントのページ**: Pro の種類と次の更新日・支払いの管理 (Stripe のカスタマーポータル)・月額と年額の切り替え (個人向け)・結んでいる WebLAV の一覧 (名前・最後に確かめた日)・外す操作を出す。PC が壊れたときは、ここから外す。
- **送り主ごとの上限** (Workers の Rate Limiting の binding。数え方はおおよそ): 認証の要らない書き込みで、D1 の書き込みの枠やメールを使い切られないように。
  - 確かめと外す (`/v1/installations/`): IP ごとに1分10回。1台の WebLAV が試し直しても当たらない数。
  - 結ぶ: アカウントごとに1分10回。返しのコードのメールも送るため。
  - メールのリンクを送る: IP ごとに1分5通。宛先を変えての送りつけを止める。
  - Workers の無料プランでも使える。
- **表**: `accounts` (id・メールアドレス)、`identities` (provider・subject → account)、`email_logins`、`sessions`、`subscriptions` (Pro。account・plan・Stripe のサブスクの id・払い終えた期間の終わり・状態。サブスクの id ごとに1行で、知らせはこの行で持ち主を引く)、`purchases` (払われた請求書ごとの台帳。請求書と支払いの id・額・通貨・MP の取引か・カードの発行国・日時・取り消した日時)、`installations` (結んでいる WebLAV。account・`link_kid`・WebLAV の公開鍵・名前・PC の名前・結んだ日時・最後に確かめた日時・外した日時・最後に出した許可の期限)、`checkouts` (支払いの画面の予約)。
  - 台帳を Pro と分けるのは、移すと Pro の持ち主が変わり、消すと Pro だけが消えるため。返金・不審請求でも台帳の行は消さず、取り消した日時を入れる。
- **売り方**: サブスク。払うのをやめたら、許可の期限で Free に戻る。
  - **個人向け**: 月額 480円・年額 4,800円。Stripe Checkout のサブスク (`mode=subscription`)。**Pro を付ける・延ばすのは webhook だけ**。戻り先の画面では付けない。
    - 日本からの買い手には直接売り、ほかの国からの買い手には Managed Payments (MP。Link が販売の代理になる) で売る。
      - 国は、Checkout Session を作るときのアクセス元の IP の国 (Workers の `request.cf.country`) で決める。分からなければ MP にする。カードの発行国は台帳に残すだけで、振り分けや返金には使わない。
      - Product と Price (月額・年額) は共用し、分けるのは Session の作り方だけ。
      - 国内の Session: カードだけ。項目に手動の税率「消費税 10%・税込み」を付け、明細の表記は、サブスクの支払いでは Session で指定できないので、商品の `statement_descriptor` に `WEBLAV PRO` を付ける。領収書は Stripe の領収書メールに任せる。
      - MP の Session: 払い方・税・明細の表記・領収書は MP が決める (指定すると断られる)。
    - プランを選ぶのは、紹介サイトの料金ページ (`/pricing/`。ログイン不要) だけ。選ぶと窓口の最終確認の画面 (`GET /account/buy?plan=`) へ進み、サインインしていなければサインインしてから戻る。最終確認の画面は特定商取引法 12条の6 の最終確認画面で、条件を申し込むボタンより上に畳まずに出す。料金ページは申し込むボタンがあるので 11条の広告に当たり、価格・支払い・解約と返金を料金表の近くに出す。
    - 料金ページへの入口は、アカウントのページ (Pro が無いとき)・Pro の無いアカウントで結ぼうとした画面・WebLAV の管理画面の Pro の区画 (Free のとき)。結ぼうとした画面からは戻り先 (`next`) を料金ページ経由で最終確認の画面へ渡し、払った後にその画面へ戻る。持っているアカウントには売らない。
    - 月額と年額は、窓口の切り替えの画面 (`/account/plan`) で切り替える。カスタマーポータルのプランの変更は使わない (確かめの画面の事項を、申し込みの最終確認の画面にそろえるため)。
      - 年額へは今すぐ。月額の使わなかった分を日割りで差し引いた額をその場で払い、払えたときだけ切り替える (`payment_behavior=pending_if_incomplete`。払えなかった保留の請求書は無効にする)。確かめの画面で見せた額のまま払うよう、見込みと切り替えに同じ `proration_date` を渡す。請求書には月額の使わなかった分 (マイナスの日割り) と年額の分が並び、払い終えた期間は年額の項目の期間の終わりまで延びる。
      - 月額へは年額の期間の終わりに。サブスクのスケジュールで、今の期間 (年額) の次に1か月 (月額) を置いて予約し、取り消せる。予約中にカスタマーポータルで解約すると、Stripe がスケジュールを外す。
    - 戻り先の画面は、webhook が届くのを3秒おきに30秒ほど待ち、付いたら元の画面 (結ぶ画面など) へ進む。付かなければ「もう一度確かめる」を出す。
    - 支払いの画面 (期限35分) が開いている間は、買うボタンを押し直しても同じ画面へ送る。同時に押されても画面が1つになるよう、Stripe に頼む前にアカウントごとの予約を取り、予約から作った Idempotency-Key を付けて頼む。
  - **組織向け**: 年額 14,800円。運営者がダッシュボードでサブスクを作る。請求書を送る払い方 (`collection_method=send_invoice`・`days_until_due=30`) で、払い方は銀行振込 (`customer_balance`)。年ごとの請求書と入金の消し込みは Stripe に任せる ([銀行振込によるサブスクリプション](https://docs.stripe.com/billing/subscriptions/bank-transfer))。
    - 付ける先は、そのサブスクの行がまだ無いときだけ、サブスクの metadata の `account_email` のアカウント (無ければ作る) にする。行ができた後は、行の持ち主に付ける (移した後に metadata の古いアドレスへ戻らないように)。Stripe の Customer は請求書の宛先 (経理の窓口など) で、WebLAV を使う人と同じとは限らないため、アカウントとは結ばない。
    - 請求書には手動の税率「消費税 10%・税込み」を付ける。
    - 付けられないとき (metadata が無い・項目の誤り) は、運営者へメールで知らせ、知らせを失敗として記録する。metadata を直して Stripe のダッシュボードから知らせを送り直すと付く。
  - **知らせ**: 同じ Stripe のアカウントのほかの製品の知らせも届くので、metadata の印 (`product: weblav-pro`・`weblav-org`) と Price で見分ける。
    - `invoice.paid`: 台帳に残し、サブスクを Stripe から取り直して、払い終えた期間の終わりを、その請求書の期間の終わりまで延ばす (知らせの本文だけを信じない。遅れて届いた古い請求書で縮めない)。行が無ければ作って Pro を付ける。ただし取り直したサブスクが終わっている (`canceled`) か、持ち主のアカウントが無い (個人向けで消した後) なら、行を作らず台帳にだけ残す。行があっても持ち主が無い (アカウントを消した) なら、台帳にだけ残す。削除と最初の知らせが逆の順に届いても、Pro やアカウントを作り直さないように (削除のときにサブスクを解約しているので、後から届く知らせは終わったサブスクのもの)。
    - 個人向けの持ち主は、Checkout Session の metadata のアカウントの id。
    - `customer.subscription.updated`・`customer.subscription.deleted`: サブスクを Stripe から取り直して状態を合わせる (知らせの順は決まっていないので、本文の状態で巻き戻さない)。終わった (`canceled`)・打ち切った行は、後から戻さない。期間の終わりでの解約は、払い終えた期間の終わりまで有効なまま (延ばさない・縮めない)。
    - `charge.refunded` (全額)・`charge.dispute.created`: サブスクをその場で解約し、行を「打ち切った」にする。打ち切った行は、後から `invoice.paid` が届いても延ばさず、台帳にだけ残す。知らせの届く順は決まっていないので、取り消した支払いも覚えておき、その支払いの `invoice.paid` が後から届いても延ばさない。
    - 知らせは id で記録し、処理し終えたものは送り直されても処理し直さない。失敗したら 500 を返し、Stripe の送り直しで処理し直す。
  - 利用者の都合では返金しない。二重の請求・決済の誤り・支払いが済んだのに Pro が付かなかったときは、その分を、ダッシュボードから返金する (規約の第2条)。MP の取引も同じ。MP の取引は、ほかに購入から60日以内なら Link が自分の決まりで返金することがある (MP の規約 3.3)。解約は、アカウントのページからカスタマーポータルで行う。
- **移す**: アカウントのページで、移し先のメールアドレスを入れる。Pro (サブスク) と結んでいる WebLAV をそのアカウントへ移し (無ければ作る)、両方にメールで知らせる。担当が替わっても、PC を結び直さずに済むように。
  - Stripe の Customer (請求の宛先・支払い方法) は変えない。移し先がカスタマーポータルで直す。
  - 持っている Pro はすべて移す。移す前に移し先を見せて確かめる (打ち間違えたアドレスへ移さないように)。
  - 知らせのメールが送れなくても、移したことは取り消さない。メールを2通送るので、メールのリンクと同じ送り主ごとの上限で絞る。
- **画面とメールの言語** (日本語・英語): 「リンクの `lang` > cookie > ブラウザーの言語 > 英語」で決める。`lang` を除けば WebLAV の画面と同じ (→ ui.md「UI 全般」)。
  - `lang` は `ja` か `en` だけを受け付け、付いていれば cookie に残す。
  - WebLAV の画面から開くリンクには、WebLAV で選んでいる言語を付ける。メールのリンクにも送ったときの言語を付ける (別のブラウザーで開いても同じ言語になるように)。
- **鍵**: 証明の署名 (Ed25519) と秘密を導く鍵 (X25519) は、Workers の Web Crypto で扱う ([Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/))。秘密鍵 (JWK) と鍵の識別子は Workers の secret (`PROOF_SIGNING_KEY`・`PROOF_KID`・`LINK_KEY`・`LINK_KID`) に置く。
  - 秘密鍵の控えは持たない。作ってそのまま secret に入れ、ディスクに残さない (`account-server/scripts/new-proof-key.mjs`・`new-link-key.mjs`)。漏れうる所を Cloudflare だけにするため。
    失ったら新しい `proof_kid`・`link_kid` の版を出す。X25519 の鍵を失うと、それで結んだ WebLAV は確かめられなくなり、結び直してもらうことになる。
- **メールの送り主**: `WebLAV <noreply@weblav.amiiby.com>`。Resend で、送り主のドメインを確かめてから使う。
  Cloudflare の Email Service は、任意の宛先へ送るのに有料プラン (Workers Paid) が要るので使わない ([Pricing](https://developers.cloudflare.com/email-service/platform/pricing/))。
- **規約類**: 規約とプライバシーポリシーは `site/` (`/terms/`・`/privacy/`) に置く。
  特定商取引法に基づく表記は運営者の全製品で共通のページ (`https://amiiby.com/tokushoho/`) にあり、価格・動作環境と WebLAV に限った条件は料金のページ (`/pricing/`) に書く。
  `/tokushoho/` は共通のページへ 301 で送る (`site/public/_redirects`)。
  - 同意は、サインインの画面のボタンの下の一文で取る。買うボタンの手前には、価格・引き渡し・返金と規約類へのリンクを出し、国内の Session は、Checkout の支払いのボタンの下 (`custom_text.submit`) にも引き渡しと返金を出す (MP の Session では `custom_text` を使えない)。
