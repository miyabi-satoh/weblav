# 共有の中のファイル操作

共有 (→ folders.md「共有」) の中を、ログインした人が画面から見る・足す・名前を変える・動かす・コピーする・消す仕組み。コードは `src/api/shares/`。画面の決めごとは ui.md の「共有の中の画面」の項。

## できること

一般ユーザー (`user`) が共有の中でできることは、4段のどれか (`ShareAccess`)。管理者はどの共有でもすべての操作ができ、値を持たない。

| 値 | 画面の表記 (管理画面 / 本人) | できること |
|---|---|---|
| `none` | アクセス不可 | 見えない。一覧にも出ず、中を指すと 404 |
| `read` | 読み取り専用 | 見る・ダウンロード・縮小画像・コピーの元・ホームに載せる |
| `add` | 追加のみ | `read` に加えて、アップロード・新しいフォルダー・コピーで入れる |
| `all` | フルアクセス | `add` に加えて、名前の変更・移動・削除・上書き |

- 共有ごとの既定 (`roots.editor_access`) と、ユーザーごとの例外 (`root_user_access`) で決める。例外があればそちらを使う。既定は `read`。共有の中を選んでコンテンツに登録することは、この仕組みの前から一般ユーザーにできたので、できることを減らさない。
- `add` で上書き・名前の変更・移動・削除を許さないのは、今あるものを消したり見失わせたりできないようにするため。名前が重なれば、番号を付けるか飛ばすだけを選べる。
- 設定は管理画面の共有の編集ページの「権限」の区画 (`PUT /api/v1/admin/roots/{id}/access`)。知らないユーザーは 422。
- 見られない (`none`) 共有の中は、コンテンツの登録先を選ぶ口 (ディレクトリの一覧・ファイル数・フォルダーの登録先) でも共有の外と同じに扱う (→ folders.md「一覧 API」)。

### 入れ子の共有

共有が入れ子のときは、その場所を含む共有のうち一番強いものを使う。外側で見られるものは、内側の共有の扱いに関わらず外側から辿れば見られるため。内側を弱くしても守れないので、強い方に揃える。

- 共有のいちばん上で見られるか (`read` 以上か) は、その共有を含む登録中の共有のパスの文字列で決め、ファイルシステムに触る前に確かめる。触ってから弾くと、応答までの時間から中のものの有無を推し量れるため。
- 中の場所でできることは、解決した実体のパスを含む共有すべての中で一番強いもの。
- `GET /api/v1/shares` は、ログインした人が見られる共有と、そのいちばん上でできることを名前の順に返す。つながらない NAS の共有も出す (開いたときに、つながらないと伝える)。

## 場所の解決

要求は「共有の id と、共有からの相対パス (`/` 区切り)」で場所を指す (`shares::paths::resolve_existing`)。画面に共有の外のフルパスを出さないため。

- `..` などの辿り直し・共有の外へ出るリンク・一覧に出さないもの (ドット始まり・シンボリックリンク・Windows の隠し属性)・WebLAV 自身の置き場は、どれも存在を伏せて 404。コンテンツの配信 (`contents::resolve_path`) と同じ規則 (→ folders.md「判定はパスを使う操作すべてに掛ける」)。
- 見られる (`read` 以上) が足りない操作は 403、見られなければ 404。
- 新しく作る名前は `paths::validate_name` で確かめ、NFC にそろえる。macOS から届く NFD の名前とほかの端末の NFC の名前が、見た目は同じなのに別のファイルになるのを避けるため。拒むのは、空・`.`・`..`・区切り文字・NUL・ドット始まり (作れても一覧に出ない)・255 バイトを超えるもの・Windows で動いているときは、Windows で作れない名前 (使えない記号、末尾のドットと空白、`CON` などの予約名) も拒む。作ると黙って別の名前になるか失敗するため。
- 共有そのもの・中に別の共有か WebLAV のデータを含むものは、名前の変更・移動・削除・上書きをできない (422 `entryProtected`)。動かすと、共有の登録や WebLAV 自身がその場所を見失うため。WebLAV のデータを含むものはコピーの元にもできない。データ (DB・セッション鍵) を共有の中へ写し出さないため。
- シンボリックリンクは辿らない。コピーではリンクを飛ばし、削除ではリンクそのものだけを消す。リンクの先にある共有の外のものを巻き込まないため。

### 確かめてから操作するまでの間 (残る隙間)

場所は canonicalize して確かめてから操作するので、その間にファイルシステムが変わると、確かめた結果と違うものを触りうる。次の手当てで、WebLAV の画面からの操作どうしでは起きないようにしている。

- 作るものは、置き先が無いときだけ成り立つ方法で作る (新しいフォルダー、作業用のファイルの `create_new`、アップロードを置くハードリンク)。
- 同じフォルダーへのアップロードは、フォルダーごとの鍵 (`state.share_dir_locks`) で順に置く。

残る隙間は次のとおりで、受け入れている。どれも、確かめと操作の間に、共有に書ける人が同じ場所を変えたときだけ起きる。

- 名前の変更は、同じ名前が無いことを確かめてから OS の rename を呼ぶ。その間に同じ名前のファイルが作られると、rename が置き換える (OS の rename は置き先のファイルを置き換えるため)。
- ハードリンクを作れないファイルシステム (FAT・一部の NAS) では、アップロードを置くときも、確かめてから名前を変える。
- 解決した後に、WebLAV の外 (エクスプローラーや NAS の別の端末) でフォルダーをリンクに差し替えられると、差し替えた先を触りうる。共有のフォルダーに直接書ける人は、もともと中のものを好きに変えられる。

## 口の一覧

どれも `AuthUser`。画面は `/shares` (共有の一覧) と `/shares/[id]` (共有の中)。

| 口 | 要るもの | 内容 |
|---|---|---|
| `GET /shares` | ログイン | 見られる共有とできること |
| `GET /shares/{id}/browse?path=&sort=` | `read` | 中の一覧、その場所でできること、載せているコンテンツ、アップロードの上限、ホームに載せられるか、ごみ箱を使えるか |
| `GET /shares/{id}/download?path=`・`/thumbnail?path=` | `read` | ダウンロードと縮小画像 |
| `GET /shares/{id}/dirs?path=` | `read` | フォルダーだけの一覧 (移動・コピーの先を選ぶ) |
| `POST /shares/{id}/upload?path=` | `add` | アップロード (multipart、いくつでも) |
| `POST /shares/{id}/folders` | `add` | 新しいフォルダー。同じ名前があれば 422 `entryNameTaken` |
| `POST /shares/{id}/rename` | `all` | 名前の変更。大文字・小文字だけの変更もできる |
| `POST /shares/{id}/list-on-home` | `read` | 中のフォルダーかファイルをショートカットとしてホームに載せる。タイトルは名前 |
| `POST /shares/{id}/rename/check` | `all` | 名前を変えると開けなくなるファイルのショートカット (→ 「場所の付け替え」) |
| `POST /shares/transfer/check`・`/shares/transfer` | 元で `read` (移動は `all`)、置き先で `add` (上書きは `all`) | コピー・移動 |
| `POST /shares/{id}/delete/check`・`/delete` | `all` | 削除 |
| `GET /shares/jobs`・`GET` / `DELETE /shares/jobs/{id}` | 自分の処理 | 進み具合と中止 |

- フォルダーのコンテンツの画面 (`browse_folder`) は、見ている場所が見られる共有の中なら、共有の中の場所とできること・ごみ箱を使えるかを `share` で返す。画面は、そこから同じ操作の口を呼ぶ。
- 共有の中のリンクの一覧のファイルは、リンクの一覧の画面ではなく、ほかのテキストのファイルと同じくビューアーで開く。リンクの一覧の画面はコンテンツに結びついているため。

## 操作ごとの決まり

### アップロード

1. 要求の大きさ (`Content-Length`) で置き先の空きを見積もる。置いた後にも 100MB は残るようにする (`fsops::ensure_space`)。足りなければ 507 `insufficient_storage`。ちょうど使い切ると、OS やほかのアプリが書けなくなって止まるため。
2. ファイルごとに、置き先と同じフォルダーに一覧に出ない作業用の名前 (`.weblav-upload-<乱数>.part`) で、無いときだけ作って受け取る。同じディスクの中なら、置くときに写し直さずに済むため。
3. 受け取りながら1つのファイルの上限 (`[upload] max_size_mb`、無ければ上限なし) を確かめ、超えたら 413。
4. 頭のバイトで画像の種類を見分け、拡張子が画像のものか無いときだけ、中身に合わせて拡張子を直す (`fsops::fixed_extension`)。iPhone の写真が JPEG に変換されたのに `.HEIC` のまま届くときなど、拡張子で種類を決める画面 (プレビュー・縮小画像) で開けるようにするため。ほかの拡張子 (`.pdf` など) は利用者が意図して付けたものとして触らない。
5. フォルダーごとの鍵を取り、同じ名前があれば `名前 (1).拡張子` のように番号を付けた最初の空きを選んで、ハードリンクで置く (→「確かめてから操作するまでの間」)。上書きはしない。フォルダーの名前には拡張子を考えない (`2026.04` が `2026 (1).04` にならないように)。
6. 応答には、ファイルごとに置いた名前と、番号を付けたか・拡張子を直したかを返す。画面はそれを添えて出す。

- 画面は1ファイルずつ送り、ファイルごとに進み具合を出す。1つの要求でいくつも送って途中で失敗したら、それまでに置いたものは残る。
- 上限が無いときは、要求の大きさの上限 (axum の既定は 2MB) をこの口でだけ外す (`DefaultBodyLimit::disable`)。上限があるときは、上限に multipart の区切りの分を足した値にする。ほかの口に掛からないよう、別のルーターに分けてから merge する。
- 途中で止まった受け取りとコピーの作業用の残りは、1日たったものを、そのフォルダーへの次のアップロードのときに消す。今まさに受け取っている大きなファイル (遅い回線で数時間かかりうる) を消さないよう、1日にする。

### 名前の変更・新しいフォルダー

- 名前の変更は、同じフォルダーに同じ名前があれば 422 `entryNameTaken`。大文字・小文字だけの変更は、大文字小文字を区別しないファイルシステムでも同じものと見分けて通す。
- Windows で、ほかのアプリが開いているために触れなければ 409 `entry_in_use`。書き込みを許されていない場所 (EPERM・EACCES、macOS の読むだけの許可など) は 409 `share_read_only`。

### コピー・移動

- 元と置き先は別の共有でもよい。選んだものはどれも同じ共有の中。
- `.../check` で、置き先にある同じ名前のもの・動かすファイルの大きさの合計・置き先の空き・上書きで消えるものをごみ箱へ送れるか・上書きで響くコンテンツ (フォルダーの登録先かショートカットの先が、同じ名前のものかその中。他人の「作成者のみ」は含めない)・移動で開けなくなるファイルのショートカット (`unlinked`) を返す (何も変えない)。画面は同じ名前があれば「上書きする」「番号を付ける」「飛ばす」を選ばせ、`onConflict` で渡す。
- 同じ名前を比べるのは選んだもの (置き先の直下) だけ。フォルダーの中身を混ぜ合わせることはしない。
- 上書きは、今あるものをごみ箱へ送って (ごみ箱を使えない場所では完全に消して) 置く。置き先で `all` が要り (無ければ 403)、上書きされるものが共有か共有を含むもの、または動かす元を含むもの (消すと元も消える) なら 422。
- 上書きで今あるものを消すのは、新しいものを用意できてから。ごみ箱の無い NAS では、消した後に中止や失敗をすると、何も残らないため。
  - コピーと別のディスクへの移動は、置き先のフォルダーの作業用の名前に写し終えてから、今あるものを消して名前を付ける。中止・失敗では作業用のものを消す。別のディスクへの移動は、その後で元を消す。
  - 同じディスクの中の移動は、先に元を置き先のフォルダーの作業用の名前に動かしてから、今あるものを消して名前を付ける。ほかのアプリが開いているものは、今あるものに触る前に `entry_in_use` で失敗する。消すか名前を付けるのに失敗したら、元の場所へ戻す。
  - 用意できてから置く間のものは `.weblav-place-` の名前で持ち、古い作業用の残りの片付けの対象にしない。動かしてきたものは更新日時が古いので、対象にすると片付けで消えるため。
  - ごみ箱を使えない場所では、今あるものを `.weblav-place-` の名前へ除けてから置き、置けなかったら戻す。完全に消すのは置けた後。ごみ箱へ送れる場所では先に送るので、置くのに失敗すると今あるものはごみ箱にある。除けている間や置く前に WebLAV が止まると、`.weblav-place-` の名前のものが置き先のフォルダーに残る。
- 同じフォルダーの中へのコピーは、番号を付けた名前で写す。同じフォルダーの中への移動は何もしない。フォルダーをそれ自身やその中へ動かす・写すのは 422 `transferIntoItself`。
- コピーは一覧に出ない作業用の名前 (`.weblav-copy-`) に写してから名前を付ける。途中で止まったり失敗したりしても、半端なものが本来の名前で残らないようにするため。
- 移動は、同じディスクの中なら名前を付け替えるだけ。別のディスクへは写してから元を消す (写し終えるまでは元を消さないので、途中で止まっても元は残る)。
- コピーは始める前に置き先の空きを確かめ、足りなければ 507。

### 削除

- `.../check` で、消すものがどれもごみ箱へ送れるかと、消すと開けなくなるコンテンツ (フォルダーの登録先かショートカットの先が、消すものかその中) を返す。他人の「作成者のみ」は含めない。
- `permanent: false` で送るのに、ごみ箱を使えない場所なら 409 `trash_unavailable`。黙って完全に消さない。画面は、ごみ箱を使えない場所では「元に戻せません」と書いた確認から `permanent: true` で送る。

### ごみ箱を使えるか

確かに送れると分かる場所だけ、ごみ箱を使えるとする (`fsops::trash_available`)。送れない場所で送ろうとすると、OS によっては黙って完全に消すため (Windows のネットワークのドライブなど)。

- Windows: ネットワーク上の場所 (UNC・`DRIVE_REMOTE` のドライブ) でなければ使える。
- macOS: この Mac のディスク (`MNT_LOCAL`) なら使える。送るのは Finder と同じ `NSFileManager` の方法で、Finder の「戻す」が効く。
- そのほか (Linux など): ホームフォルダーと同じディスクなら使える。ほかのディスクのごみ箱 (`.Trash-<uid>`) は、作れるか・デスクトップから見えるかがディスクによって違うため。

テストは利用者のごみ箱へ本物のファイルを送らないよう、`build_app` に渡す `TrashPolicy` で、決まったフォルダーへ動かすか、ごみ箱の無い場所として扱う。

### ホームに載せる

共有の中のフォルダーかファイルを、それを指すショートカットとして作る (→ folders.md「呼び分け」)。コンテンツの作成と同じく、見られる場所なら載せられる (`read`)。公開範囲は選べ、省略すると既定値。

- 共有の一覧の行と見出しには、その場所を載せているコンテンツを「掲載中」として添える (他人の「作成者のみ」と、ホームに出ない「非表示」は出さない。同じ場所をいくつも載せていれば、先に作ったものを採る)。消す・名前を変える前に、ホームで見えているものに響くと分かるようにするため。
- 「非表示」しか無い場所もまた載せられる。閲覧者が戻せる (作成者か、作成者のみ以外を選んだ管理者) 非表示のコンテンツがあれば、新しく作らずにそれを選んだ公開範囲で戻す。新しく作ると対象と除外のパターンが空の2つ目のコンテンツができ、外していたファイルが見えてしまうため。

## 裏で続く処理

コピー・移動・削除は、大きなフォルダーで数分かかりうるので、要求はすぐに 202 と `jobId` で返し、画面が進み具合を読みに来る (`shares::jobs`)。

- 処理はメモリの中にだけ持ち、起動し直すと消える。続きはしない。操作の記録は始めたときに `running` で書き、起動したときに残っていれば `failed` にする。
- ユーザーは自分の処理だけを見られ、中止できる。中止しても済んだ分はそのまま残り、写しかけのものは残さない。上書きの途中で中止したときは、置き換える前なら今あるものはそのまま残る。
- 終わった処理は 10 分残す。画面を閉じて開き直しても、結果を出せる長さ。
- 処理の記録を閉じてから、終わったことにする。終わったのを見て記録を読みに行く画面が、途中のままの記録を読まないため。
- 画面は 1 秒たっても終わらない処理だけ、右下に進み具合と中止を出す (→ ui.md)。

## 場所の付け替え

フォルダーを指すコンテンツは、登録先を実体のパスで (`contents.path`)、一覧の表示の索引を登録先からの相対パスで (`archive_items.rel_path`・`archive_dirs.rel_path`) 持つ。どれも綴りで照らすので、画面から動かしたものを追いかけないと、登録先が見つからなくなったり、索引の行が残ったりする。名前の変更・移動・上書き・削除のたびに `shares::repoint` で DB に映す (`contents_write_lock` の中で)。

- 登録先 (かその上) を動かしたら、登録先を新しい場所に変える。中の相対パスは変わらない。
- コンテンツの中で動かしたら、相対パスの頭を付け替える。コンテンツの外へ出したら、その分の行を消す。
- 置き先に前からあった行は、先に消す。
- 消したら、中の索引を消す。登録先そのものを消しても、コンテンツは残す。ごみ箱から戻せばまた開けるようにするため (消す前に、開けなくなるコンテンツを画面で伝える)。
- 上書きで消したものが登録先かその中なら、そのコンテンツの索引も消す。登録先ごと別のものになるため (確かめの画面で伝える)。一覧の表示を使うものは、更新日時の分からない根だけを索引のフォルダーに入れ、次の読み直しで置き換わった中身を読ませる。
- 上書きで消したものが登録先の中なら、その分の索引の行だけ消し、読み直させる。置けなかったときは、ふつうの削除と同じに扱う。
- 頭の一致は `substr` で照らす。`LIKE` だと `a` と `ab` や、大文字・小文字の違う綴りを取り違えるため。
- 一覧の表示の索引を走査している最中のコンテンツは、索引に触らない。索引は走査が書き直すため (ここで直しても、走査が前に読んだ中身で上書きする)。
- ファイルはもう動かしてあるので、映すのに失敗してもログに残すだけにする。操作を失敗に見せると、済んだ操作をもう一度させることになるため。
- 置いた・動かしたものは、一覧の表示を使うフォルダーの索引に、次の再スキャンを待たずに入れる (→ archive.md「スキャン」)。

**ファイルを指すショートカットは追いかけない**。WebLAV の外で動かされると追えず、動きが2通りになるため。代わりに、移動・名前の変更の前の確かめ (`/shares/transfer/check` の `unlinked`・`/shares/{id}/rename/check`) で開けなくなるものを伝える。削除と上書きの確かめ (`listed`) にも入る。共有の場所の選び直しでは、共有ごと動かしたので一緒に付け替える (`roots::rebase_contents`)。

フォルダーを指すものは、画面から動かしたときは今までどおり追いかける。WebLAV の外 (エクスプローラーなど) で動かしたものは追いかけない。索引は次の再スキャンで直る。パターンは名前で当たるので、動かした先の名前で当たり直す (→ folders.md「見せるものの絞り込み」)。

## 操作の記録

共有の中を書き換えた操作を `share_operations` に残し、管理画面の「操作の記録」で新しい順に見せる (`GET /api/v1/admin/share-operations?before=&limit=`、`AdminUser`)。誰がいつ何を動かし・消したかを、後から確かめるため。

- 残すのは、アップロード (ファイルごとに1行)・新しいフォルダー・名前の変更・移動・コピー・削除・ホームに載せる。コピー・移動・削除は選んだものをまとめて1行にする。見るだけの操作 (一覧・ダウンロード) は残さない。
- コピー・移動の上書きで消したものは、置き先の共有の削除として1つずつ別の行に残す。誰が何を消したかを、削除の行で辿れるようにするため。
- 件数と大きさ (`item_count`・`byte_count`) は実際に置いた・消した分。飛ばしたものや、中止・失敗で置かなかったものは数えない。進み具合の表示は、飛ばしたものも済んだものとして全体まで進める。
- 場所は、共有からの相対パスの JSON の配列 (`paths`) と、置き先 (`dest_path`) で持つ。選んだものだけを並べ、中のファイルまでは並べない。
- ユーザーや共有を消した後も残るよう、外部キーは張らず、ユーザー名と共有の名前はそのときの値を写して持つ。
- 記録に失敗しても操作そのものは止めない。記録のために、済んだ操作を失敗に見せないため。
- 365 日より古い行は、起動したときと 1 日ごとに消す。1年前の同じ時期の出来事 (年度替わりの整理など) まで遡れるようにするため。
- 一覧は `before` (前の応答の `nextBefore`) で続きを読む。既定 100 件、上限 1000 件。

## 共有の場所の選び直し

`PUT /api/v1/admin/roots/{id}/path` (`LocalRequest` + `AdminUser`) で、共有の場所を、窓で選び直したフォルダーに付け替える。フォルダーを別のディスクや NAS へ移した・ドライブの文字が変わったときに、共有を消して追加し直さずに済むようにするため (消して追加し直すと、権限の設定を選び直すことになる)。画面は編集ページの「フォルダーを選び直す...」から、追加と同じ窓 (`POST /admin/roots/pick`) で選ばせ、返ったパスを送る。

- 選んだ場所には、追加と同じ検証を掛ける (存在しない・ディレクトリでない・WebLAV 自身の置き場の中は 422)。ほかの共有と同じ場所なら 422 `rootAlreadyRegistered`。入れ子は許す。
- 名前と権限 (`roots.editor_access`・`root_user_access`) は共有の id に付いているので、そのまま残る。
- 1つのトランザクションで、`roots.path` と、前の場所の中に登録先があるフォルダーのコンテンツとショートカットの `contents.path` を、新しい場所の同じ相対パスへ書き換える (`contents_write_lock` の中で)。フォルダーごと動かした先を選び直す使い方なので、中の並びは同じとみなす。
  - 中の一覧の表示の索引 (`archive_items`・`archive_dirs`) は登録先からの相対パスなので、書き換えない。登録先の書き換えで索引の版 (`archive_versions`) が上がり、配る側の使い回しは捨てられる。
  - 一覧の表示を使うコンテンツは、続けて中身の変わったフォルダーを読み直す (`repoint::refresh_after_change`、→ archive.md「スキャン」)。写した先ではフォルダーの更新日時が変わっているので、変わった分が読み直される。
  - 操作の記録 (`share_operations`) は共有からの相対パスで持つので、書き換えない。
  - 同じパスを持つ削除済みの共有の行は消す (`path` は UNIQUE)。その行は残ったコンテンツの場所を出すためだけのもので、そのコンテンツは付け替えた共有の中に入る。
- 今と同じフォルダーを選んだときは何も書き換えず、書き込みの許可だけを取り直す (下の「macOS の書き込みの許可」)。

## macOS の書き込みの許可

macOS のサンドボックスでは、共有の中を書き換えるのに、窓で選んだときの書き込みの許可が要る。読むだけの許可で作った前の版のブックマークは、利用者が窓で選び直すしかない (→ distribution.md「ビルド・配布の方法」)。

- 共有の一覧の応答に書き込めるか (`writable`) を添え、管理画面は書き込めない共有を知らせる。
- 取り直すのは、編集ページの「フォルダーを選び直す...」で同じフォルダーを選ぶ (上の「共有の場所の選び直し」)。窓で選んだときにブックマークを書き込みの許可で作り直し (`pick_root`)、`PUT .../path` が許可を戻し直す。
- 書き込めない場所への操作は 409 `share_read_only`。

## 関連する閲覧側の仕組み

共有の仕組みと同時に入れた、閲覧側の公開範囲を扱う仕組み。権限の詳細は access.md。

- ホームとグループの行の公開範囲の変更・非表示 (`PUT /api/v1/contents/{id}/visibility`) と、非表示のコンテンツの一覧・表示に戻す口 (→ access.md「非表示のコンテンツ」)。
