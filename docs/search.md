# 検索

閲覧の場で、コンテンツとアーカイブのファイルをタイトルの文字列で探す。
入口はヘッダーの虫眼鏡で、`/search?q=…` の画面を開く。API は `GET /api/v1/search?q=…` の1つ。

## 何を照らすか

| 対象 | 照らす文字列 |
|---|---|
| コンテンツ (グループ・フォルダ・ファイル・リンク・アーカイブ) | タイトルと説明 |
| アーカイブのファイル | 表示タイトルと、軸の値の表示名 |

- DB に入っている文字列と、そこから導出した文字列だけを照らし、照らすときにディスクは読まない。
  フォルダの中のファイル・ファイルの中身・`.links.toml` の中のリンクは探さない。探すたびに開いて読むことになるため。
- アーカイブのファイルは、導出したタイトルで照らし、元のファイル名では照らさない。テンプレートで組んだタイトルが画面に出ている名前で、ファイル名は利用者に見えないため。
- 結果の行に出す情報 (画像の大きさ・テキストか) は、一覧と同じく、出す行 (区画ごとに最大 100 件) のファイルだけを読む。
- アーカイブの表示タイトルは保存していないので、閲覧用の一覧と同じ導出 (`archive::derive_item`) を検索のたびに回す。
  索引の表は持たない。数千件の規模なら、1回の検索で全部を導出しても足りる。

## 一致のしかた

- 空白 (全角を含む) で区切った語が、どれもどこかの文字列に含まれていれば当たり (部分一致の AND)。
- 比べる前に、どちらも NFKC で揃えて英字を小文字にする。全角と半角、大文字と小文字を区別しない。
- ひらがなとカタカナは区別する。漢字の読み・ローマ字・打ち間違いでは当てない。
- 語が空なら探さず、空の結果を返す。

## 見える範囲

結果に出すのは、その人がホームからたどって一覧で見られるものだけ。検索で初めて存在が分かるものを作らない。

- コンテンツは、自分と祖先のグループすべてが `can_list` を通るもの (→ access.md「匿名閲覧の受け口」「祖先のグループを辿る」)。
  一覧は親を開けることを確かめてから子を並べるが、検索は全体から拾うので、行ごとに祖先まで判定する。
  全行を一度に読み、メモリ上で親子を辿る (`contents::listable_ids`)。
- `hidden` のグループの中は、ログイン済みの人にも出さない。管理画面からは開けるが、閲覧の場のどこにも並ばないため。
- アーカイブのファイルは、アーカイブが上の条件を通り、かつ公開 (`published`) のものだけ。軸の値で当てるのも公開のアイテムの値だけなので、非公開のアイテムのフォルダ名は漏れない。

## 結果の並びと上限

- 「コンテンツ」と「アーカイブのファイル」の2つに分け、それぞれタイトル順 (並び順の `title` と同じ比べ方) に並べる。
  同じタイトルのアーカイブのファイルは、アーカイブごとに、その一覧の既定の並び (軸の順) にする。
- 区画ごとに 100 件で打ち切り、打ち切ったかを返す。1文字だけ打ったときに数千件を並べないため。

## 画面

- 打ちながら探す。打ち止めて 0.3 秒で問い合わせる。Enter ですぐ探す。
- 語は URL の `q` に持ち、履歴は置き換えで更新する。戻ると検索を開く前の画面へ戻り、リンクを共有できる。
- 行は閲覧の一覧と同じ部品で描き、押したときの動きも元の一覧と同じにする。2段目には、どこにあるかを出す。
  - コンテンツ: 親のグループの名前 (ルート直下なら「ホーム」)。説明だけで当たったものは、何で当たったか分かるよう説明を添える。
  - アーカイブのファイル: アーカイブの名前と、タイトルに入っていない軸の値。
- 音声を続けて鳴らすのは、結果の中の音声。
- リストとタイルの切り替えはほかの一覧と同じく効かせる。並び順の選択は出さない。
