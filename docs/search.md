# 検索

閲覧の場で、コンテンツ・アーカイブのファイル・フォルダーの中・リンクの一覧のファイルの中のリンクを、タイトルの文字列で探す。
この文書の「アーカイブ」は一覧の表示を使うフォルダーを指す (→ archive.md)。一覧の表示を使うフォルダーの中は索引から探し (「アーカイブのファイル」)、使わないフォルダーの中と、フォルダーの表示の中の階層に絞ったときは、その場で辿って探す (「フォルダーの中」)。
入口はヘッダーの虫眼鏡で、`/search?q=…` の画面を開く。API は `GET /api/v1/search?q=…` の1つ。

## 範囲

閲覧ページ (グループ・フォルダー・アーカイブ・リンクの一覧) から開いたときは、そのページの中を範囲にし、全体との切り替えを出す。
Windows のエクスプローラーと同じく、今いる場所の中を最初に選んでおく。ホームから開いたときは、もともと全体なので切り替えを出さない。

| 開いたページ | 範囲 |
|---|---|
| グループ | その子孫すべて (中のフォルダー・アーカイブの中身も含む) |
| フォルダー | 開いている階層から下。コンテンツの区画は探さない |
| アーカイブ | そのアーカイブのファイルと、その中のリンクの一覧。絞り込みは範囲に入れない (切り替えの名前で条件まで表せないため) |
| リンクの一覧 | その一覧のファイルを入れているフォルダーの階層かアーカイブ。`file` コンテンツの一覧は範囲を持たない |

- 範囲は URL の `within` (コンテンツの id) と `path` (フォルダーの中の階層) に持ち、全体を選んでいるときは `all=1` を足す。全体を選んでも範囲を持ち続けるので、切り替えはそのまま出る。API は `within`・`path`・`all` (`true`/`false`) で受け、範囲のコンテンツのタイトル (`scopeTitle`) を返す。
- フォルダーの中の階層の切り替えの名前は「フォルダー名 / 2025 / 2」のように、最後の2段までを付ける。同じ名前の階層 (`2`) を見分けるため。3段以上なら、それより上は「…」に詰める。
- 幅が足りないときは、フォルダーの名前だけを縮める。階層は見分けるのに要るので縮めず、スマートフォンの幅でだけ上限を決めて、超えた分を切り詰める。末尾から切り詰めると、見分けるのに要る階層が先に消えるため。
- 範囲の場所が開けない (消えた・ログインが切れた) ときは、画面は範囲を外して全体を探す。範囲を持ったままでは、どの語でも失敗し続けるため。
- 範囲の場所は、その画面を開くのと同じく、自分と祖先を開けること (`can_open`) を確かめる。開けなければ 401/404。
- 範囲のグループの中は、範囲から下へたどって一覧に出るもの (`can_list`) だけを探す。範囲自身と祖先は問わないので、`hidden` のグループを開いているときは、その中を探せる。

## 何を照らすか

照らす文字列は3種類に分ける。種類によって、当て方と並びでの重さが変わる (→ 「一致のしかた」)。

| 対象 | 自身の名前 | 説明 | 場所の名前 |
|---|---|---|---|
| コンテンツ (グループ・フォルダー・ファイル・リンク・アーカイブ) | タイトル | 説明 | 上のグループ |
| アーカイブのファイル | 表示タイトル | 軸の値の表示名 | アーカイブと上のグループ |
| フォルダーの中のファイルとディレクトリ | 名前 | — | 途中のフォルダー・フォルダーのコンテンツ・上のグループ |
| リンクの一覧のファイル (`.links.toml`) の中のリンク | 題 (カードと同じ。覚えているページのタイトル、無ければファイル名かホスト名) | `note` | 一覧のファイルの題・入れているコンテンツ・上のグループ |

- 場所の名前を照らすのは、「mugenp review mp4」のように、入っている場所の語を添えて絞れるようにするため。
- ファイルの中身は探さない。
- アーカイブのファイルは、導出したタイトルで照らし、元のファイル名と途中のフォルダー名では照らさない。テンプレートで組んだタイトルが画面に出ている名前で、ファイル名と階層は利用者に見えないため (→ archive.md)。階層の語は軸の値が代わりになる。
- 結果の行に出す情報 (画像の大きさ・テキストか) は、一覧と同じく、出す行 (区画ごとに最大 100 件) のファイルだけを読む。
- アーカイブの表示タイトルは保存していないので、閲覧用の一覧と同じ導出 (`archive::derive_item`) を検索のたびに回す。
  索引の表は持たない。数千件の規模なら、1回の検索で全部を導出しても足りる。

## フォルダーの中

- 索引を持たず、検索のたびにフォルダーの登録先の下を辿る。フォルダーは開くたびにディスクをそのまま並べる作りで (→ folders.md「フォルダー (ブラウズ型)」)、索引を持つと、いつ作り直すかを決めることになるため。
- 辿り方と除外は一覧と同じ (ドット始まり・シンボリックリンク・Windows の隠し属性・WebLAV 自身の置き場。→ archive.md「スキャン」)。読めない場所は読み飛ばす。
- 公開できるフォルダーの外になったフォルダーは辿らない (配信と同じ。→ folders.md「公開できるフォルダー」)。
- 1つのフォルダーで辿るのは 20,000 件まで。打つたびに辿るので、巨大なツリーで検索ごと遅くならないようにするため。
  超えたら打ち切り、辿りきれなかったことを、区画の 100 件の打ち切りとは分けて返す。その先は探していないので、語を足しても広がらないため。画面は結果の下に、途中までしか探していない旨を出す。
- 結果の行の情報 (大きさ・日時・画像か) は、出す行 (最大 100 件) のファイルだけを読む。

## リンクの一覧のファイルの中

- リンクのコンテンツをタイトルと説明で照らすのと同じ扱いで、題と `note` で照らす。題はカードと同じ (→ ui.md「リンクの一覧のファイル」)。
- 読む一覧のファイルは、見られるフォルダーの中のもの、見られるアーカイブの公開アイテム、見られる `file` コンテンツ。
- 一覧のファイルは検索のたびに読む。題に使うページのタイトルは、覚えている分 (`link_previews`) だけを使い、取りに行かない。

## 一致のしかた

最近の多くのアプリの検索と同じく、fzf 型のあいまい検索 (文字が順に含まれれば当てる。`revew` → review) にする (`src/api/search.rs`)。あいまいな照合は `frizbee` (blink.cmp・atuin・skim が使う、fzf と同じ方式の照合) に任せ、照らす文字列の種類・当てる条件・並べ方をこちらで決める。

- 空白 (全角を含む) で区切った語が、どれもどこかの文字列に当たれば当たり (AND)。ただし、少なくとも1語は場所の名前でない文字列 (自身の名前か説明) に当たること。場所の語1つで、その下の物が全部当たり、場所そのものが埋もれないようにするため。
- 比べる前に、どちらも NFKC で揃えて英字を小文字にする。全角と半角、大文字と小文字を区別しない。
- 1語の当たり方は、よい順に次のとおり。
  1. 文字列の全体と同じ。「mugenp」で、mugenp のフォルダーを、名前に mugenp を含むほかの物より先に出すため
  2. 語の頭 (先頭か、英数字でない文字の直後) からそのまま含む
  3. どこかにそのまま含む
  4. あいまい (`frizbee`)。文字が順に含まれる (`rvwunit` → review-units)。この段の中の順は `frizbee` の点数 (詰まって並ぶ・語の頭から当たるほど高い) に任せる。
- あいまいに当てる条件は、`frizbee` に渡す設定と、その結果に掛ける絞りで決める。
  - 3文字以上の語だけ。1〜2文字では、ほとんど何にでも当たるため。
  - 打ち間違い (文字が足りない・入れ替わっている) は許さない (`frizbee` の `max_typos` を 0)。fzf と同じく、文字が順に含まれるかだけで決まる単純な決まりにするため。
  - 当たった文字の間に挟まる文字は、語の長さの2倍まで。`frizbee` は間の広さを点数で下げるだけなので、長い名前に散らばった文字にまで当てないため。
- 打ち間違いと飛ばし打ちは、自身の名前にだけ効かせる。説明と場所の名前は長いか数が多く、ゆるく照らすと関係ない物まで当たるため。
- ひらがなとカタカナは区別する。漢字の読み・ローマ字では当てない (辞書が要るため)。
- 語が空なら探さず、空の結果を返す。

## 見える範囲

結果に出すのは、その人がホームからたどって一覧で見られるものだけ。検索で初めて存在が分かるものを作らない。

- コンテンツは、自分と祖先のグループすべてが `can_list` を通るもの (→ access.md「匿名閲覧の受け口」「祖先のグループを辿る」)。
  一覧は親を開けることを確かめてから子を並べるが、検索は全体から拾うので、行ごとに祖先まで判定する。
  全行を一度に読み、メモリ上で親子を辿る (`contents::listable_ids`)。
- フォルダーの中とリンクの一覧のファイルの中は、上の条件を通るフォルダー・アーカイブ・`file` コンテンツの中だけを探す。
- `hidden` のグループの中は、ログイン済みの人にも出さない。管理画面からは開けるが、閲覧の場のどこにも並ばないため。
- アーカイブのファイルは、アーカイブが上の条件を通り、かつ公開 (→ folders.md「公開と非公開」) のものだけ。軸の値で当てるのも公開のアイテムの値だけなので、非公開のアイテムのフォルダー名は漏れない。

## 結果の並びと上限

- 「コンテンツ」「アーカイブのファイル」「フォルダーの中」「リンクの一覧の中」の4つに分け、それぞれ当たりのよい順に並べる。あいまいに当てると当たる物が増えるので、タイトル順のままでは、ゆるく当たった物が上に混ざるため。
  - 語ごとに、照らした文字列の種類 (自身の名前 > 説明 > 場所の名前) を当たり方より重く数え、全部の語の分を足す。飛ばし打ちは、間に挟まる文字が少ないほうを先にする。
  - 同じ程度なら、タイトル順 (並び順の `title` と同じ比べ方。フォルダーの中は名前、リンクは題)。同じタイトルのアーカイブのファイルは、アーカイブごとに、その一覧の既定の並び (軸の順) にする。
- 区画ごとに 100 件で打ち切り、打ち切ったかを返す。1文字だけ打ったときに数千件を並べないため。

## 画面

- 打ちながら探す。打ち止めて 0.3 秒で問い合わせる。Enter ですぐ探す。
- 語は URL の `q` に持ち、履歴は置き換えで更新する。戻ると検索を開く前の画面へ戻り、リンクを共有できる。
- 行は閲覧の一覧と同じ部品で描き、押したときの動きも元の一覧と同じにする。2段目には、どこにあるかを出す。
  どの区画も、上のグループから順に書く (`高1 / 教材 / 2024`)。区画によって起点が違うと、同じ名前のフォルダーやアーカイブを別々のグループに置いたときに見分けられないため。
  - コンテンツ: 上のグループの名前 (ルート直下なら「ホーム」)。説明で当たった語があるものは、何で当たったか分かるよう説明を添える。
  - アーカイブのファイル: 上のグループとアーカイブの名前、タイトルに入っていない軸の値。
  - フォルダーの中: 上のグループとフォルダーの名前、その中のどこにあるか。
  - リンクの一覧の中: 上のグループ、フォルダー (とその中の階層) かアーカイブの名前、一覧のファイルの題。`note` で当たった語があるものは `note` を添える。
- **場所は押せる。押すと階層を上から順に並べ、選んだ段の画面を開く** (`frontend/src/lib/components/row-location.svelte`。Google ドライブの検索結果の「場所」に倣う)。
  同じ名前の当たりを場所で見分けたあと、その親を開きたいことがあるため。行の本体を押したときの動きは変えない。
  - 1行に収めるタイルでは、収まらなければ親より上を「…」で切り、親を残す。同じ名前の当たりは、親で見分けることが多いため。
    リストでは切らずに折り返す。
  - グループかフォルダーの階層を範囲にして探している間は、行には範囲から下だけを出す。範囲より上はどの行も同じため。押して出る階層には、上の段も出す。
  - 場所の頭にフォルダーの絵を付け、ポインターを載せたときだけ下線を出す (→ ui.md「見た目の決めごと」)。
- 音声を続けて鳴らすのは、結果の中の音声。
- リストとタイルの切り替えはほかの一覧と同じく効かせる。並び順の選択は出さない。
