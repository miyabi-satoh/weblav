# アーカイブ (索引型)

## スキャン

- `POST /api/v1/contents/{id}/rescan`。権限は `AuthUser`。`user` は自分のアーカイブだけ (→ access.md「ロールと操作」)。
- 再スキャンは管理画面のボタンで手動で行う。起動時の自動スキャンもファイルの変更監視もしない。
- **作成と場所の変更の直後は、画面が続けてこの口を呼ぶ**。空のアーカイブが残ると、次に何を押せばよいか迷うため。作成・更新の API には
  スキャンを含めない。スキャンだけが失敗しても作成・保存は済んでいるので、
  「保存はできた・スキャンはできなかった・再スキャンして」と分けて伝える
  (`$lib/archive-scan.ts`)。
- `walkdir` で `contents.path` 配下を再帰的に走査する。`follow_links = false`。
  ドット始まりのファイル・ディレクトリは常に除外する。
  **Windows では隠し属性の付いたものも除外する** (`AppData` のように名前が
  ドットで始まらない隠しディレクトリがあるため)。
- **シンボリックリンク自体を索引対象から除外する** (`file_type().is_symlink()`)。
  `follow_links = false` は「リンク先のディレクトリへ再帰しない」だけで、
  リンクをエントリとして拾わない意味ではない。`folder` のブラウズが既に
  同じ除外をしている (実装済み: `browse_folder`) ので揃える。除外しなくても
  配信時の `resolve_path` が外部への脱出を防ぐが、辿れないアイテムが一覧に
  並び、リンク名が露出する。
- **除外の規則は、一覧・数え上げ・索引と配信で揃える** (`fs::is_visible_entry` と `fs::has_hidden_component`)。
  索引に出ないアイテムを `rel_path` で直接求められても配信しない (→ folders.md「公開できるフォルダ」)。
  WebLAV 自身の置き場 (設定とデータ) の中も同じく外す (→ folders.md「公開できるフォルダ」)。
- `contents.extensions` (カンマ区切りのテキスト、空なら全ファイル) で絞る。
  比較は小文字化して行う。
- ディスクI/Oは `spawn_blocking` で行い、収集後に1トランザクションで DB を更新する。
- **読めない場所が1つでもあれば同期せず、422 で断る** (内訳 `archiveFolderUnreadable`、最初に読めなかった場所の相対パスを添える)。
  読めなかった分は走査の結果から欠けるので、同期すると「消えた」と見なされて公開フラグごと消えるため。
  登録前の確認 (→ folders.md「登録前の確認」) は、読めた分だけを数え、最初に読めなかった場所を添える。確認ダイアログはそれを出す。
  作成・場所の変更の直後のスキャンがこれで失敗したときは、「再スキャンして」を添えない。直すまで同じ失敗になるため。登録先が無いときも同じ。
- **登録先のフォルダが無ければ、422 の内訳 `archiveFolderMissing` で断る**。
  ルートの外を1つの文言に寄せる決まり (→ folders.md「ルートの外は理由を1つに寄せる」) より先に見分ける。
  見るのは登録済みのパスだけなので、任意のパスの有無を探る道具にはならない。
- 同期の内容:
  - 見つかった `rel_path` のうち `archive_items` に無いものを
    `published = 0` で INSERT する。新しく見つかったアイテムは既定で非公開にし、再スキャンで勝手に何かが公開されないようにする。
  - 既にある行はそのまま残す (公開フラグを保持する)。
  - 見つからなかった `rel_path` の行を DELETE する。
- **行を消すことが「一度対象から外れたら公開フラグを復元しない」の実装**になる。
  墓標 (tombstone) 行は持たない。次に同じパスが現れたら新規 INSERT され、
  非公開から始まる。
- **アーカイブの `path` を変更したら、そのアーカイブの `archive_items` を
  全削除する** (更新と同じトランザクション内で)。`rel_path` は登録先フォルダを
  起点とする相対パスなので、起点が変われば同じ `rel_path` が別のファイルを
  指す。行を残すと、変更前に公開していたフラグが変更後の無関係なファイルへ
  引き継がれ、意図しない公開が起きる。削除後は、保存に続くスキャンで全件が
  非公開から作り直される。管理画面の確認ダイアログで、公開設定がやり直しに
  なる旨を伝える。
- 拡張子フィルタ (`extensions`) の変更では行を消さない。索引対象であり続けた
  アイテムは公開フラグを保つ
  (対象から外れた行は次のスキャンで削除される)。
- 同じアーカイブに対する再スキャンは、プロセス内の per-archive な排他
  (`AppState` が持つ実行中 id の集合) で直列化する。二重クリックで同じ走査が
  二重に走らないようにするため。実行中の再要求は 409 を返す。
  **この排他はアーカイブの更新・削除にも掛ける**。走査中にパスが変わると、
  古いパスを基準に集めた `rel_path` を新しいパスの索引として書き込んでしまう。
  加えて、DB 更新の直前に `path` が走査開始時と同じであることを確認し、
  変わっていればスキャンを破棄してやり直させる (排他の取り漏らしに対する
  最終防御)。
- `rel_path` はパス区切りを `/` に正規化して保存する。Windows と
  他プラットフォームで同じ値になるようにするため。
- スキャン結果 (新規◯件・削除◯件・合計◯件) をレスポンスで返し、管理画面に表示する。
- **スキャンは時点観測**である。走査から次の再スキャンまでの間にファイルが
  消えることはありうる。配信時 (→ 「アイテムの配信」) は必ず実体を確認し、無ければ 404 を返す。
  索引に行があることを実体の存在保証として扱わない。

## 軸の定義

`archive_axes` の `source` は2値。

| `source` | 使うカラム | 値の集まり方 |
|---|---|---|
| `dir_level` | `dir_level` (1始まり) | スキャン時に自動収集 |
| `filename_word` | (なし) | 管理者が語を登録する |

- `dir_level` は**アーカイブの登録先フォルダを起点**に数える。
  `rel_path` を `/` で分割した `dir_level - 1` 番目の要素がディレクトリ名に
  当たる場合のみ値になる (最後の要素はファイル名なので対象外)。階層が足りなければ
  「未設定」。
- `filename_word` は、拡張子を除いたファイル名に対する**部分一致**で判定する。
  英字の大文字小文字は区別しない。
  複数一致した場合は、語がいちばん長いものを採る (長さは文字数で比べる)。同じ長さならリストの上にあるもの (`position` が小さいもの。`position` も同じなら `id` が小さいもの)。
- 正規表現は一切受け付けない。軸は技術者でない管理者が定義するため。
- `filename_word` 軸の照合語は、行ごとに照合する位置 (`archive_axis_values.match_position`) を持つ。`anywhere` (既定)・`word_start`・`end`。
  同じ軸の中でも、ファイル名の付け方によって語を当てたい位置が違うため。
  画面の選択肢は「どこでも」「先頭か区切りの直後」「末尾」。`word_start` はファイル名の先頭だけではないので「先頭」とは呼ばない。
  - `word_start` は、ファイル名の先頭か、直前の文字が ASCII の英数字でない位置 (日本語・記号・空白の直後を含む)。
    文字種の変わり目は含めない。英検の `1kyu` の `kyu` に当たるため。
  - `end` は拡張子を除いたファイル名の末尾。
  - 位置で候補を絞ってから最長一致を採る。
  - `dir_level` 軸の行は `anywhere` だけを受け付ける (422)。
- 軸ごとに、閲覧側の絞り込みに出すか (`filterable`、既定は出す) を持つ。
  管理画面の軸の追加・編集ダイアログで切り替え、`POST` / `PUT /contents/{id}/axes` のリクエストと軸の一覧・取得のレスポンスに `filterable` として載せる。リクエストで省略したら出す。
  出さない軸も、表示タイトル (→ 「表示タイトル」) とアイテムの並び順 (→ 「エンドポイント一覧」) には使う。
  閲覧用 API (`GET /contents/{id}/archive`) の軸の定義と選択肢には含めない。閲覧側に選ばせない軸の値を返す理由が無いため。
  出さない軸の名前をクエリキーにした絞り込みは、軸名に一致しないキーと同じく無視する (→ 「エンドポイント一覧」)。
- 軸の `name` は前後の空白を落とし、アーカイブ内で一意、`{` と `}` を含めない
  (表示タイトルのテンプレートでプレースホルダーとして参照するため。→ 「表示タイトル」)。

## 軸の定義を外部の AI で作る

軸の定義は、技術者でない管理者には意外と難しい。そこで、管理者が自分で使っている外部の AI のサービスに考えてもらえるようにする。
WebLAV は AI につながらない。画面がプロンプトを作り、管理者が AI に貼り付け、答えを貼り戻す。

- プロンプトは、軸の決まり (この節の上と「表示タイトル」)、アーカイブの構造、答えの形 (JSON) と例からなる。
  構造は「軸の設定を助ける表示」の階層ごとの値と語の候補 (既定で隠すものを除く40語)、アイテムの相対パス (全体から間を空けて150件) から組む。全部を載せると、大きいアーカイブで貼り付けが重くなるため。
  - 文章は画面の表示言語で、言語ごとの Markdown (`frontend/src/lib/axes-ai-prompt/`) に置く。
- 答えは、AI が前後に付けた説明やコードブロックの囲みを除き、最初の `{` から最後の `}` までを JSON として読む。
- 答えの形は、軸の追加と値の辞書の更新の要求ボディを1つにまとめたもの (`axes` の各要素が `name`・`source`・`dirLevel`・`optionalInTitle`・`filterable`・`values`) と `titleTemplate`。
- `POST /contents/{id}/axes/import/preview` で、取り込む前に全アイテムを導出して、軸ごとに値が決まる件数と、アイテムの例 (全体から間を空けて10件) の表示タイトルと値を返す。書き込まない。
- `PUT /contents/{id}/axes` で、今の軸・値の辞書・表示タイトルのテンプレートを1つのトランザクションで置き換える。権限は軸の追加と同じ。
- 確かめる決まりは、軸の追加・値の辞書の更新・テンプレートの保存と同じ関数を通す。予告で通った答えが取り込みでも通り、取り込んだ後の結果が予告と食い違わないため。
  答えの軸の中で名前が重なれば、軸の追加と同じ内訳 (`axisNameTaken`) を返す。階層の番号・値の空や重複など内訳の無い決まりは、どの軸かだけを添える (`importAxisInvalid`)。直すのは AI に頼み直すことになり、軸が分かれば足りるため。
- 外へ出るのはファイルのパスの名前だけで、管理者が自分で貼る。パスに人の名前などが入っていることはあるので、プロンプトを出す画面に、AI のサービスに送られることを一言出す。

## 軸の値の辞書と導出

`archive_axis_values` が両方の `source` を兼ねるが、意味が違う。

- `dir_level` 軸: **辞書は表示のための上書きにすぎない**。値そのものは
  `rel_path` の第N階層の文字列であり、辞書に行が無くても値は成立する。
  行があれば `display_name` と `position` をそこから取る。
  行が無いか、`display_name` が未設定 (NULL または空文字) なら、生の値をそのまま表示する。
  行が無ければ、並び順は既定 (生の値の昇順) にする。
- `filename_word` 軸: **この表の行そのものが照合語リスト**。`raw_value` が
  照合する語、`position` が表示順、`display_name` が表示名。
  行が無ければその軸は何にも一致しない。

`dir_level` 軸を辞書に依存させないことで、軸を足した直後から
再スキャンを待たずに値が出る (architecture.md「データモデルの全体像」の方針と揃う)。スキャン時に辞書行を
UPSERT する処理は必須ではなくなる。値の管理画面は、その時点のアイテムから
生の値を集めて辞書と突き合わせて表示すればよい。

**抽出元か階層番号を変えたら、その軸の辞書の行を消す** (軸の更新と同じトランザクション)。
行は変更前の値の集まりに向けたもので、残すと `dir_level` の表示名が `filename_word` の照合語として解釈されたり、別の階層の値の並び順に効いたりするため。
軸の編集ダイアログでは、抽出元か階層番号を変えている間、辞書が消えることを警告の帯で知らせる。

`position` はリストの並びであり、表示順を決める。照合の優先には使わない。長さが同じ語が複数一致したときだけ、リストの上にあるものを採る。
照合を最長一致にしたので、`数学` と `数学I` のような包含関係を並び順で解決する必要が無い。
`position` に照合の優先度を兼ねさせると、長い語を上に置くために、選択肢が意味の通らない順に並ぶ (共通テストの科目)。
照合の順と表示順を別々に並べ替える案は採らない。並び替え UI が2つに増えると、非技術者に説明しづらいため。

導出のアルゴリズム (読み出し時、アイテム1件ごと):

1. `rel_path` を `/` で分割する。
2. `dir_level` 軸は、対応する位置の要素をそのまま値とする。階層が足りなければ
   「未設定」。表示名と並び順は辞書に行があればそれを使う。
3. `filename_word` 軸は、辞書の行のうち部分一致するものから、語がいちばん長い行を採る。
   同じ長さならリストの上にある行 (`position` が小さい行。`position` も同じなら `id` が小さい行)。一致する行が無ければ「未設定」。

辞書行が古くなる問題は起きない。絞り込みドロップダウンは
**その時点で見えているアイテムに実際に現れた値から作る** ため、
消えたディレクトリの値は自動的に選択肢から落ちる。辞書行を消す・消さないの
判断が不要になる。

**ドロップダウンの選択肢は、閲覧者に見えるアイテムだけから作る**。
匿名閲覧者に非公開アイテムのディレクトリ名が漏れないようにするため
(URL を直接開かれた場合も一覧と同じ判定を通すのと同じ趣旨)。
選択肢は絞り込み前の「見えるアイテム全体」から作り、現在の絞り込み条件では
狭めない (絞り込みを緩める側の選択肢が消えないようにするため)。

**選択肢は表示名でまとめる**。細かい語を大分類にまとめた軸 (`butsuri`・`kagaku` → 「理科」) や表記揺れを、別の仕組みなしに扱えるようにするため。
表示名 (未設定なら生の値。`display_name` が NULL または空文字を未設定とみなす) が同じ値は1つの選択肢にし、選ぶとそのどれかに当たるアイテムが残る。
選択肢の並びは、下のアイテムの並び順の比較キーに従う。
「未設定」は選択肢に出さず、クエリで指す値も持たない。
ここでの未設定は値が無い状態のことで、表示名の文字列ではない。表示名に「未設定」という文字列を付けた値は、ほかの値と同じく選択肢になる。
ある軸で絞り込むと、その軸が未設定のアイテムは残らない。
生の値ごとに選択肢を作ると、同じ「理科」が照合語の数だけ並び、1つ選んでも理科全体では絞れないため。

アイテムの並び順 (→ 「エンドポイント一覧」) における、軸1本ぶんの比較キーは3段。
表示名が同じ値は、選択肢と同じく1つの値として比べる。

1. 表示名 (未設定なら生の値) が一致する辞書の行がある値: 軸の辞書の全行のうち、表示名が一致する行の `position` の最小値の昇順 (同値なら表示名の昇順)。
   見えているアイテムに現れた行だけから取ると、公開の切り替えで並び順が動くため、全行から取る。
2. 表示名が一致する辞書の行が無い値 (`dir_level` 軸のみ発生。`filename_word` 軸は
   辞書の行そのものが値の集合なのでこの段は存在しない): 生の値の昇順。
   自分の行が無くても、生の値が別の行の表示名と一致すれば 1. に入る。
3. 「未設定」: 常に最後。

## 表示タイトル

- `contents.title_template` に `{軸名}` と固定文字を並べたテンプレートを持つ。
- **`{fileName}` は予約プレースホルダー**で、拡張子を除いたファイル名に展開する。
  軸が全て埋まっていても同じタイトルに潰れる (同じフォルダに複数のファイルがある)
  場面を、テンプレート側で区別できるようにするため。
  名前をASCIIにするのは、表示言語によらず一意にするため。この名前の軸は作れない。
- 保存時に、テンプレート中の全プレースホルダーが実在する軸名であることを検証する。
  未定義の軸名を含むテンプレートは 422 で拒否する。
- 軸をリネームしたら、同一トランザクション内でテンプレート中の該当箇所も書き換える。
- テンプレートで参照中の軸の削除は 422 で拒否する。リネームには書き換え先があるが
  削除には無く、放置すると admin が触っていない別の保存操作で、上記の検証が
  突然失敗するようになる。
- 組み立て時、テンプレート中の軸が1つでも「未設定」なら、組み立てを行わず
  ファイル名 (`rel_path` の最後の要素) をそのまま表示する。部分的に欠けたタイトル (「（問題）」だけ、など) を出さないため。
- 軸ごとに `optional_in_title` を持つ。立っている軸は、未設定なら空文字として組み立てを続ける。
  画面では反転して「値が無ければファイル名のまま表示する」(既定でオン) として見せる。オンで起きることを名前がそのまま言うため。
  ただしテンプレート中の軸がすべて未設定なら、ファイル名を表示する。固定文字だけのタイトルを出さないため。軸を参照しない (`{fileName}` だけの) テンプレートはこれに当たらない。
  テンプレートの記法 (`{課程?}` など) ではなく軸の設定にするのは、記号を覚えなくて済むようにするため。
- テンプレートが空 (NULL) ならファイル名をそのまま表示する。
- アイテム1件ごとの手動上書きは持たない。上書きとルールの二重管理になり、「ルールを直したのに反映されない」事故を生むため。拾えないものは、ファイル名を直すか軸の定義を足す。

## アイテムの公開

- `PUT /api/v1/contents/{id}/items/{item_id}` で `published` を切り替える。
  権限は `AuthUser`。
- 一覧画面からのまとめて切り替えに対応するため、複数 id を受ける
  `PUT /api/v1/contents/{id}/items` (`{itemIds: [...], published: bool}`) も置く。
- 管理用の一覧は、表示タイトルかパスに含む文字列で絞り込める (英字の大文字小文字は区別しない)。
  表紙のように同じ種類のファイルをまとめて選び、公開を切り替えるため。
  全選択と一括切り替えは、絞り込みで出ている行だけに効く。絞り込みを変えて見えなくなった行は選択から外す。見えない行が選択に残ると、気づかないまま切り替えてしまうため。
  一覧は全件を返しているので、絞り込みは画面だけで行い、API は変えない。
  絞り込みは URL に持たない。
  次の案は採らなかった。
  - 公開状態でも絞る: 表紙をまとめて選ぶには要らない。
  - 軸の値で絞る: 表紙は科目の値が行ごとに違い、1つの値では選べない。
  - 値の辞書に「閲覧側に出さない」を持たせる: 公開の判定が `published` と2か所に分かれる。
- 閲覧できる条件は「アーカイブの `visibility` を満たす」かつ
  「アイテムが `published`」の両方。一覧は SQL の条件で、
  配信は取得した行の判定で、同じ条件を見る。片方を変えるときはもう片方も直す
  (`archive_items.rs` の2か所に互いを指すコメントがある)。

## アイテムの配信

- **閲覧の一覧と検索は、実体の無い行を外す** (→ 「スキャン」の時点観測)。開けない行を並べないため。
  選択肢と件数も、外した後の行から作る。登録先のフォルダごと無ければ、閲覧用の一覧の応答に `folderMissing` を立て、画面は空の一覧の代わりにそう出す。
  管理用の一覧は外さず、`missing` を付けて返す。画面は行に印を付け、一覧の上に一度だけ知らせる。どちらも、再スキャンで行が外れる。
- `GET /api/v1/contents/{id}/items/{item_id}/download`。
- 相対パスをクエリで受けず、`item_id` から `rel_path` を引く。索引済みの
  アイテムだけが配信対象になるため、`folder` の `?path=` 方式より判定が単純になる。
- 実際のファイル読み出しは `folder` と同じ `resolve_path` +
  `serve_file_response` を共有する (canonicalize + `starts_with` 検証、
  Range 対応、`Content-Disposition`、`X-Content-Type-Options` を再利用)。
- **管理画面からは `GET /api/v1/contents/{id}/items/{item_id}/manage-download` で開き、未公開も渡す**。
  権限はアーカイブを管理できること (`AuthUser` のうち、他人の `private` は `admin` だけ。管理用の一覧と同じ)。
  閲覧用の口に「管理者なら未公開も渡す」分岐を足さず、口を分ける。閲覧側の一覧と配信が同じ条件を見る形 (→ 「アイテムの公開」) を崩さないため。
  管理できる人は公開を切り替えられるので、未公開を開けても見える範囲は広がらない。

| `POST /contents/{id}/rescan` | `AuthUser` | 再スキャン (→ 「スキャン」) |

| `PUT /contents/{id}/items` | `AuthUser` | 公開フラグの一括切り替え |
| `PUT /contents/{id}/items/{item_id}` | `AuthUser` | 公開フラグの単体切り替え |
| `GET /contents/{id}/items/{item_id}/download` | `Viewer` | アイテムの配信 (→ 「アイテムの配信」) |

| `PUT /contents/{id}/axes` | `AdminUser` | 軸・値の辞書・表示タイトルのテンプレートをまとめて置き換える (→ 「軸の定義を外部の AI で作る」) |
| `POST /contents/{id}/axes/import/preview` | `AdminUser` | まとめて置き換える前の導出結果。書き込まない (→ 「軸の定義を外部の AI で作る」) |
| `POST /contents/{id}/axes` | `AdminUser` | 軸の追加 |
| `PUT /contents/{id}/axes/{axis_id}` | `AdminUser` | 軸の名前・抽出元・階層番号・値が無くても組み立てるか・絞り込みに出すか・並び順の変更 |
| `DELETE /contents/{id}/axes/{axis_id}` | `AdminUser` | 軸の削除 (テンプレートで参照中なら422 → 「表示タイトル」) |
| `GET /contents/{id}/axes/{axis_id}/values` | `AuthUser` | 値の辞書。`dir_level` 軸では、現在のアイテムに現れる生の値と突き合わせて返す |
| `PUT /contents/{id}/axes/{axis_id}/values` | `AuthUser` | 値の辞書の一括更新 (追加・削除・表示名・照合する位置・並び順をまとめて送る) |
| `GET /contents/{id}/dir-levels` | `AuthUser` | 階層ごとの値の数と例 (→ 「軸の設定を助ける表示」) |
| `GET /contents/{id}/filename-words` | `AuthUser` | ファイル名の語の候補 (→ 「軸の設定を助ける表示」) |
| `POST /contents/{id}/axes/{axis_id}/values/preview` | `AuthUser` | 保存前の値の辞書での導出結果 (→ 「軸の設定を助ける表示」)。書き込まない |

- **`{id}` に属する `item_id` / `axis_id` だけを操作・返却する**。
  クエリの WHERE 句に必ず所属条件を含める
  (`WHERE id = ? AND archive_id = ?`、軸の値なら
  `JOIN archive_axes ON ... WHERE archive_axes.archive_id = ?`)。
  id 単独で引くと、別のアーカイブのアイテムや軸を横取りして操作できてしまう。
  所属しない id は 404 を返す。
- 軸の値の並び替えは、行を1件ずつ動かすのではなく `PUT .../values` で
  リスト全体を送る。表示順を表す1本のリスト (→ 「軸の値の辞書と導出」) を
  D&D で並べ替えて保存する UI に素直に対応するため。
- アイテムの並び順は `sort` クエリで選ぶ (`axis` / `title` / `new`、既定は
  `axis`)。既定の `axis` は、軸の `position` 順に各軸の値を「軸の値の辞書と導出」の比較キーで
  ソートし、最後に `rel_path` で決定する。軸を1本も定義していないアーカイブは
  `rel_path` 順になる。`title` / `new` の意味論はホーム/グループ/フォルダと同じ
  (→ ui.md「ホーム・グループ・フォルダ・アーカイブの並び順」)。知らない値・未指定は `axis` として扱う (422 にしない)。
- `GET /contents/{id}/archive` のクエリキーのうち、`sort` と、軸名に
  一致しないものは無視する (422 にしない)。軸のリネーム・削除より前に
  共有されたリンクを壊さないため (→ ui.md「アーカイブの一覧画面」。絞り込み状態は URL に持ち、リンクを共有できる)。
  絞り込みに出さない軸 (→ 「軸の定義」) の名前のキーも同じく無視する。
- **クエリの値は選択肢の表示名** (`?教科=理科`)。
  1つの軸で指せる値は1つ (複数選択はしない)。同じキーが複数あるときは、最後の値を使う (クエリを `HashMap` で受けるため。今の挙動と同じ)。
  選択肢との比較は完全一致で、大文字小文字も区別する (ファイル名の照合と違い、表示名は管理者が付けた文字列そのものを指すため)。
  最後の値がどの選択肢にも一致しなければ、前の値には戻らず、その軸の絞り込みを無視する。
  生の値では、表示名でまとめた選択肢 (→ 「軸の値の辞書と導出」) を1つの値で指せないため。
  どの選択肢の表示名にも一致しない値は、軸名に一致しないキーと同じく無視する。
  表示名を変えると、それより前に共有したリンクのその軸の絞り込みは効かなくなるが、軸名の変更と同じ扱いとして受け入れる。
- **選択肢には「それを選んだときに残る件数」を添える**。他の軸の現在の絞り込みを
  効かせたまま、その軸だけを候補の値に置き換えて数える。
  0件になる組み合わせを選ぶ前に見分けられるようにするためで、
  **0件でも選択肢は消さない** (緩める側の選択肢を消さない方針は変えない)。
  選択肢そのものは絞り込み前の全体から作る (→ 「軸の値の辞書と導出」) ので、選択肢の母集団と
  件数の母集団は別であることに注意。
- アイテムの一覧・配信レスポンスは階層 (`rel_path`) を出さない。アーカイブは階層を表に出さないフラットな一覧として見せるため。
  ただし実ファイル名 (`rel_path` の最後の要素) は、表示タイトルとは別に返す。
  ページ内プレイヤーへの振り分け (→ ui.md「音声のページ内プレイヤー」) が拡張子で決まるため、閲覧側にも
  実ファイル名が要る。導出済みタイトルは組み立てで拡張子が失われるため
  代用できない。
- 閲覧用の一覧のアイテムには、行の2段目に出す軸の値 (`subtitle`) を組み立てて返す (→ ui.md「アーカイブの一覧画面」)。
  絞り込みの状態で変わるので、クエリを知っているサーバー側で組み立てる。
- `PUT /contents/{id}/items` の一括切り替えは、`itemIds` に所属しない id が
  1件でもあれば全体を 404 にし、どの行も更新しない。単体切り替えと同じ
  「所属しない id は 404」を、一括の場合も全件成立を条件にして揃える。

## 軸の設定を助ける表示

軸を足すときに、フォルダの構造とファイル名を見ながら決められるようにする。見えていないフォルダの構造やファイル名を思い浮かべながら設定するのは難しいため。
どれもスキャン済みのアイテム (`archive_items.rel_path`) から計算し、新しいデータは持たない。

- **階層ごとの値 (`dir-levels`)**: 階層ごとに、値の種類の数・その階層を持つアイテムの数・値の例 (件数の多い順に5つ) を返す。
  軸の追加・編集ダイアログで、階層番号を数字で入れる代わりに、この一覧から選ばせる。
- **語の候補 (`filename-words`)**: 拡張子を除いたファイル名から語を切り出し、その語を含むアイテムの数を付けて件数の多い順に返す。
  - 英数字・文字以外 (空白・`_`・`-`・括弧など) で区切った塊と、それを文字種 (数字・ラテン文字・漢字・カタカナ・ひらがな) の変わり目でさらに分けた部分の両方を候補にする。
    `2021中1_04_02英語` のように語がくっついた名前から `英語` を出し、`P2Q-part3` の `P2Q` も崩さずに出すため。
  - 分解形 (NFD) の濁点・アクセントなどの結合文字は、前の文字の続きとして扱う。Mac から来たファイル名で語が切れないようにするため。
  - 大文字小文字の違いは1つにまとめる (照合と同じ)。
  - 件数は「切り出した語の中にその語があるアイテムの数」。照合は部分一致なので、照合で当たる件数はこれより多いことがある (`kyuu` は `tankyuu` にも当たる)。正確な件数は予告 (下) で見る。
  - 候補は照合する位置 (「軸の定義」) を見ずに出す。語の頭の行では、文字種の変わり目で分けた語 (`02英語` の `英語`) は当たらない。当たらないことは予告の未設定の件数で分かる。
  - 数字だけ・1文字・1件にしか出ない・全アイテムに出る語は、既定で隠す印 (`hiddenByDefault`) を付ける。トラック番号や、見分けに使えない語で候補が埋もれないようにするため。
    画面では一覧に出さず、検索したときだけ出す (ファイル名に年が入っている場合など)。
  - 照合語に登録済みの語を外すのは画面の側。保存前の行も含めて外すため。
- **導出結果の予告 (`values/preview`)**: 保存前の値の辞書を受け取り、保存済みの軸の定義と合わせて全アイテムを導出し、一致・未設定の件数と未設定の `rel_path` の例 (5件) を返す。
  - ファイル名の語の軸では、辞書の行ごとに、その行で値が決まるアイテムの件数と例 (5件、`id` 付き) も返す。
    語が何を指すかを、ダウンロードしてきたファイルのように名前だけでは分からないときでも中身で確かめるため。画面は例を管理用の配信 (→ 「アイテムの配信」) で開く。
    数えるのは値を決めた行 (最長一致) だけにし、語を含むだけのアイテムは数えない。保存後に実際に付く値と合わせるため。
  - 置き場所は語の候補ではなく辞書の表の行にする。候補のボタンの並びに開閉の欄を足すと折り返しが崩れ、押して行を足す操作も2段になるため。候補の語を確かめるときは、押して行を足してから開く。
  導出は保存後と同じ関数を通す。画面で計算すると照合の規則 (「軸の定義」・「軸の値の辞書と導出」) を TypeScript にも持つことになり、予告と保存後が食い違いうるため。
  入力の検証 (空・重複で 422) も `PUT .../values` と同じにする。導出は `spawn_blocking` で回す。
- **照合語の数の上限**: ファイル名の語の軸では、照合語が1,000行を超えたら `PUT .../values` も予告も 422 にする。予告の照合が「全アイテム × 照合語の数」になるのを抑えるため。
  階層の軸には掛けない。辞書を引くだけで行数に比例せず、画面は現れた値を全種類送り返すので、値の多い階層で保存できなくなるため。
