# 一覧の表示 (フォルダーの索引)

フォルダーの「一覧の表示」(`contents.list_view`、→ folders.md「2つの表示」) は、中のファイルを索引 (`archive_items`) し、平らな一覧を軸で絞り込んで見せる。
コードと API には、前に別の種類だった名残で `archive` の名前が残っている (`/contents/{id}/archive`・`archive_items` など)。この文書の「アーカイブ」は、一覧の表示を使うフォルダーを指す。
見せるかどうかは索引に持たず、フォルダーの公開・非公開の印で決める (→ folders.md「公開と非公開」)。

## スキャン

- `POST /api/v1/contents/{id}/rescan`。権限は `AuthUser`。`user` は自分のアーカイブだけ (→ access.md「ロールと操作」)。
- 再スキャンは、管理画面のボタンと、自動の再スキャン (`contents.auto_rescan_mode` ほか。しない・前回から N 時間たったら・毎日 HH:MM を過ぎたら、既定はしない) で行う。決め方の型と時間の判定は `api::schedule` に置く。夜中の決まった時刻に回せるようにするため。ファイルの変更監視はしない。NAS の上でほかの機械が変えたものを拾えないため。
  - 自動の再スキャンは、1分ごとに見回り (`archive::spawn_auto_rescan`)、最後のスキャン (`contents.last_scanned_at`) から決めた時間が来たものを1件ずつ順に走らせる。同じ NAS を同時に読ませないため。失敗したもの (つながらない・フォルダーが無い) は、試した時刻を前回とみなし、次の回まで試し直さない。
- **一覧の表示を開いたときに、中身の変わったフォルダーだけを読み直す** (`archive::refresh_changed_dirs`)。フォルダーは中のものを足したり消したりすると更新日時が変わるので、スキャンで残したフォルダーの更新日時 (`archive_dirs`) と今の値を比べ、変わったフォルダーは直下を、新しいフォルダーは中ごと読む。置いたファイルが、再スキャンを待たずに一覧に出る。一覧の最初の要求でだけ走らせ、区切りの続きでは走らせない (→ 「一覧の API を区切って返す」)。
  新しいフォルダーを読むときは、走査するエントリの数 (`fs::SCAN_LIMIT`) で打ち切り、そのフォルダーは再スキャンに任せる。一覧を開いた人には止める手段が無いため (→ 「件数の上限」)。
  - 足したファイルの大きさや撮影日は、一覧を待たせないよう裏で読む (その間は排他を持ち、進み具合を出す)。読み終えるまでは、その行はプレビューなしで並ぶ。
  - ファイルの中身を書き換えただけでは、フォルダーの更新日時は変わらない。それは再スキャンで拾う。
  - スキャンが走っている間・NAS につながらない間は何もしない。
- **一覧の表示を使い始めた保存と、場所の変更の直後は、画面が続けてこの口を呼ぶ**。索引が空のまま残ると、次に何を押せばよいか迷うため。作成・更新の API には
  スキャンを含めない。スキャンだけが失敗しても保存は済んでいるので、
  「保存はできた・スキャンはできなかった・再スキャンして」と分けて伝える
  (`$lib/archive-scan.ts`)。
- `walkdir` で `contents.path` 配下を再帰的に走査する。`follow_links = false`。
  ドット始まりのファイル・ディレクトリは常に除外する。
  **Windows では隠し属性の付いたものも除外する** (`AppData` のように名前が
  ドットで始まらない隠しディレクトリがあるため)。
- **シンボリックリンク自体を索引対象から除外する** (`file_type().is_symlink()`)。
  `follow_links = false` は「リンク先のディレクトリへ再帰しない」だけで、
  リンクをエントリとして拾わない意味ではない。`folder` のブラウズが既に
  同じ除外をしている (実装済み: `browse_folder`) ので揃える。除外しなくても
  配信時の `resolve_path` が外部への脱出を防ぐが、辿れないアイテムが一覧に
  並び、リンク名が露出する。
- **除外の規則は、一覧・数え上げ・索引と配信で揃える** (`fs::is_visible_entry` と `fs::has_hidden_component`)。
  索引に出ないアイテムを `rel_path` で直接求められても配信しない (→ folders.md「公開できるフォルダー」)。
  WebLAV 自身の置き場 (設定とデータ) の中も同じく外す (→ folders.md「公開できるフォルダー」)。
- `contents.extensions` (カンマ区切りのテキスト、空なら全ファイル) で絞る。
  比較は小文字化して行う。
- ディスクI/Oは `spawn_blocking` で行い、収集後に1トランザクションで DB を更新する。
- **読めない場所が1つでもあれば同期せず、422 で断る** (内訳 `archiveFolderUnreadable`、最初に読めなかった場所の相対パスを添える)。
  読めなかった分は走査の結果から欠けるので、同期すると「消えた」と見なされて一覧から消えるため。
  登録前の確認 (→ folders.md「登録前の確認」) は、読めた分だけを数え、最初に読めなかった場所を添える。確認ダイアログはそれを出す。
  使い始めた・場所を変えた直後のスキャンがこれで失敗したときは、「再スキャンして」を添えない。直すまで同じ失敗になるため。登録先が無いときも同じ。
- **索引する件数では断らない** (→ 「件数の上限」)。自動の再スキャンだけは、走査するエントリの数 (`fs::SCAN_LIMIT`) で打ち切り、同期せずにやめる。
  途中までの結果で同期すると、残りが「消えた」と見なされるため。
- **登録先のフォルダーが無ければ、422 の内訳 `archiveFolderMissing` で断る**。
  ルートの外を1つの文言に寄せる決まり (→ folders.md「ルートの外は理由を1つに寄せる」) より先に見分ける。
  見るのは登録済みのパスだけなので、任意のパスの有無を探る道具にはならない。
- 同期の内容:
  - 見つかった `rel_path` のうち `archive_items` に無いものを INSERT する。公開するかは行に持たず、印と「新しく見つかったファイルを公開する」の設定で決まる。
  - 既にある行はそのまま残す。
  - 見つからなかった `rel_path` の行を DELETE する。
  - 辿ったフォルダーと更新日時で `archive_dirs` を置き換え、`contents.last_scanned_at` を書く。
- **プレビューの情報 (画像の縦横・テキストか) と写真の撮影日は、スキャンで読んで行に残す** (`file_size`・`modified_ns`・`image_width`・`image_height`・`is_text`・`taken_at`)。
  一覧と検索はこの値を返すだけにし、ファイルを開かない。一覧のたびに写真の先頭を読むと、NAS の数万枚で十数分かかるため。
  前のスキャンと大きさ・更新日時が同じファイルは読み直さない。ただし、読み方の版 (`read_version`、`archive::READ_VERSION`) が古い行と、画像なのに大きさを読めなかった行は読み直す。読み方を変えたとき (撮影日を読むようにした など) と、NAS の読み取りが一時的に失敗したときに、ファイルが変わるまで古い値が残らないようにするため。まだ読んでいない行 (この仕組みより前に索引したもの) は、次のスキャンまでプレビューなしで並べる。その場で読むと、大きいアーカイブでは一覧が開かず、再スキャンのボタンにも届かないため。
- **スキャンの進み具合は `GET` の同じパスで返す** (段階と、読んだ件数 / 全件数と、始めてからの秒数)。`POST` は終わるまで応答しないので、画面は待つ間これを1秒ごとに見て、押したボタンの近く (アイテムのタブはボタンの横、場所の変更は確認の窓の中、一覧の表示を使い始めた保存は保存ボタンの横) に出す (`$lib/archive-scan.ts`)。トーストにしないのは、トーストを完了の知らせに限っているため (→ ui.md「UI 全般」)。
  経過の秒数はサーバーで数える。画面を開き直しても続きから出せるようにするため。
  アイテムのタブは、開いたときにスキャンが走っていれば、終わるまで再スキャンのボタンを押させずに進み具合を出し、終わったら一覧を取り直す。
- **スキャンは、画面を閉じられても最後まで進めて保存する** (止めるのは中止を頼まれたときだけ。→ 「スキャンの中止」)。ハンドラが落とされてもファイルを読むスレッドは止められず読み続けるので、別のタスクで走らせ、読んだ分を捨てない。同じアーカイブの排他も終わるまで持ち、押し直したスキャン (409) が同じフォルダーを同時に読まないようにする。
- 公開・非公開の印は索引と別に持つので、行を消しても印は残る。同じパスがまた現れれば、前と同じ公開に戻る。
- **`path` を変更したら、`archive_items`・`archive_dirs`・公開・非公開の印を
  全削除する** (更新と同じトランザクション内で)。どれも登録先フォルダーを
  起点とする相対パスなので、起点が変われば同じパスが別のファイルを
  指す。残すと、変更前に公開していたものが変更後の無関係なファイルへ
  引き継がれ、意図しない公開が起きる。管理画面の確認ダイアログで、
  公開・非公開の変更が消える旨を伝える。
- 拡張子フィルタ (`extensions`) の変更では行を消さない
  (対象から外れた行は次のスキャンで削除される)。
- 同じアーカイブに対する再スキャンは、プロセス内の per-archive な排他
  (`AppState` が持つ実行中 id の集合) で直列化する。二重クリックで同じ走査が
  二重に走らないようにするため。実行中の再要求は 409 を返す。
  **この排他はアーカイブの更新・削除にも掛ける**。走査中にパスが変わると、
  古いパスを基準に集めた `rel_path` を新しいパスの索引として書き込んでしまう。
  加えて、DB 更新の直前に `path` が走査開始時と同じであることを確認し、
  変わっていればスキャンを破棄してやり直させる (排他の取り漏らしに対する
  最終防御)。
- `rel_path` はパス区切りを `/` に正規化して保存する。Windows と
  他プラットフォームで同じ値になるようにするため。
- スキャン結果 (新規◯件・削除◯件・合計◯件) をレスポンスで返し、管理画面に表示する。
- **スキャンは時点観測**である。走査から次の再スキャンまでの間にファイルが
  消えることはありうる。配信時 (→ 「アイテムの配信」) は必ず実体を確認し、無ければ 404 を返す。
  索引に行があることを実体の存在保証として扱わない。

## スキャンの中止

- `DELETE /contents/{id}/rescan` で、走っているスキャンに中止を頼む。走査のスレッドはファイルを1つ見るごとに印を見て止まり、再スキャンの応答が `cancelled: true` で返る。進み具合を出す3か所 (アイテムのタブ・保存ボタンの横・場所の変更の確認の窓) に「中止する」を置く。時間がかかるのは NAS の数万件を初めて読むときで、拡張子を絞り直したくなるのもその場面のため。
- 走っていなければ何もしない (204)。押したときに終わっていることがあるため。進み具合を出していない排他 (更新・削除・一覧を開いたときの読み直しの比べ) は止めない。止めると保存が抜けるため。
- **止めたときは同期しない**。読んでいないファイルを「消えた」と見なして外さないため。読み終えたファイルだけを書く (新しいものは足し、既にあるものは読んだ値で書き換える)。次のスキャンは、読んだものを大きさと更新日時で読み飛ばすので、続きから進むのと同じになる。
  - フォルダーの更新日時 (`archive_dirs`) と `last_scanned_at` は書かない。全体を見たときにだけ正しい値のため。初めてのスキャンを止めたときは `archive_dirs` が空のままなので、一覧を開いたときの読み直しも走らない。
  - ファイルを集め終える前に止めたときは、読んだものが無いので何も書かない。
  - 読み終えた後に届いた中止は無視して、ふつうに同期する。全部読めているので、同期した方が正しい索引になるため。
- 一覧を開いたときに足したファイルを裏で読む処理も、進み具合を出すので止められる。読まなかった行は大きさなどが空のまま残り、次のスキャンで読む。

## 軸の定義

`archive_axes` の `source` は4値。

| `source` | 使うカラム | 値の集まり方 |
|---|---|---|
| `dir_level` | `dir_level` (1始まり) | スキャン時に自動収集 |
| `filename_word` | (なし) | 管理者が語を登録する |
| `date_year`・`date_month` | (なし) | 撮影日 (無ければ更新日) から自動で決まる |

- 日付の軸の値は、年は `2024`、月は `06` の形 (`archive::date_value`)。文字の順に並べると、年は時の順、月は1月から12月の順になる。
  月は年を問わない。年の軸と月の軸を置けば、年だけ・月だけ・年と月の両方で絞り込めるので、年月を1つの値にする軸は持たない。表示名と並び順は、`dir_level` 軸と同じく値の辞書で上書きする。
  日付は写真の EXIF の撮影日時 (`DateTimeOriginal`、無ければ `DateTime`) を先にし、無ければファイルの更新日を使う (`archive::dated_at`)。撮影日を持たないファイル (動画・文書) にも値を出すため。
  EXIF の日時は時差を持たないので、書かれた年月日と時刻をそのまま UTC として数える。カメラに合わせた日付のまま分けるため。更新日は UTC で年と月を取る。
  年と月を軸の設定にせず抽出元の種類にしたのは、軸の作成・更新・取り込みの形を変えずに済むため。

- `dir_level` は**アーカイブの登録先フォルダーを起点**に数える。
  `rel_path` を `/` で分割した `dir_level - 1` 番目の要素がディレクトリ名に
  当たる場合のみ値になる (最後の要素はファイル名なので対象外)。階層が足りなければ
  「未設定」。
- `filename_word` は、拡張子を含むファイル名に対する**部分一致**で判定する。拡張子で分けたいときに、`.md` のような語で書けるようにするため。
  英字の大文字小文字は区別しない。
  複数一致した場合は、語がいちばん長いものを採る (長さは文字数で比べる)。同じ長さならリストの上にあるもの (`position` が小さいもの。`position` も同じなら `id` が小さいもの)。
- 正規表現は一切受け付けない。軸は技術者でない管理者が定義するため。
- `filename_word` 軸の照合語は、行ごとに照合する位置 (`archive_axis_values.match_position`) を持つ。`anywhere` (既定)・`word_start`・`end`。
  同じ軸の中でも、ファイル名の付け方によって語を当てたい位置が違うため。
  画面の選択肢は「どこでも」「先頭か区切りの直後」「末尾」。`word_start` はファイル名の先頭だけではないので「先頭」とは呼ばない。
  - `word_start` は、ファイル名の先頭か、直前の文字が ASCII の英数字でない位置 (日本語・記号・空白の直後を含む)。
    文字種の変わり目は含めない。英検の `1kyu` の `kyu` に当たるため。
  - `end` は、拡張子の前の末尾 (`2024_answer.pdf` の `answer`) か、ファイル名全体の末尾 (`.pdf`)。拡張子の前の末尾にも当てるのは、拡張子を照らす前に登録した語を、そのまま当て続けるため。
  - 位置で候補を絞ってから最長一致を採る。
  - `dir_level` 軸の行は `anywhere` だけを受け付ける (422)。
- 軸ごとに、閲覧側の絞り込みに出すか (`filterable`、既定は出す) を持つ。
  管理画面の軸の追加・編集ダイアログで切り替え、`POST` / `PUT /contents/{id}/axes` のリクエストと軸の一覧・取得のレスポンスに `filterable` として載せる。リクエストで省略したら出す。
  出さない軸も、表示タイトル (→ 「表示タイトル」) とアイテムの並び順 (→ 「エンドポイント一覧」) には使う。
  閲覧用 API (`GET /contents/{id}/archive`) の軸の定義と選択肢には含めない。閲覧側に選ばせない軸の値を返す理由が無いため。
  出さない軸の名前をクエリキーにした絞り込みは、軸名に一致しないキーと同じく無視する (→ 「エンドポイント一覧」)。
- 軸の `name` は前後の空白を落とし、アーカイブ内で一意、`{` と `}` を含めない
  (表示タイトルのテンプレートでプレースホルダーとして参照するため。→ 「表示タイトル」)。

## 軸の定義を外部の AI で作る

軸の定義は、技術者でない管理者には意外と難しい。そこで、管理者が自分で使っている外部の AI のサービスに考えてもらえるようにする。
画面がプロンプトを作り、管理者が AI に貼り付け、答えを貼り戻す。

- プロンプトは、軸の決まり (この節の上と「表示タイトル」)、アーカイブの構造、答えの形 (JSON) と例からなる。
  構造は「軸の設定を助ける表示」の階層ごとの値と語の候補 (既定で隠すものを除く40語)、アイテムの相対パス (全体から間を空けて150件) から組む。全部を載せると、大きいアーカイブで貼り付けが重くなるため。
  - 文章は画面の表示言語で、言語ごとの Markdown (`frontend/src/lib/axes-ai-prompt/`) に置く。
- 答えは、AI が前後に付けた説明やコードブロックの囲みを除き、最初の `{` から最後の `}` までを JSON として読む。
- 答えの形は、軸の追加と値の辞書の更新の要求ボディを1つにまとめたもの (`axes` の各要素が `name`・`source`・`dirLevel`・`optionalInTitle`・`filterable`・`values`) と `titleTemplate`。
- `POST /contents/{id}/axes/import/preview` で、取り込む前に全アイテムを導出して、軸ごとに値が決まる件数と、アイテムの例 (全体から間を空けて10件) の表示タイトルと値を返す。書き込まない。
- `PUT /contents/{id}/axes` で、今の軸・値の辞書・表示タイトルのテンプレートを1つのトランザクションで置き換える。権限は軸の追加と同じ。
- 確かめる決まりは、軸の追加・値の辞書の更新・テンプレートの保存と同じ関数を通す。予告で通った答えが取り込みでも通り、取り込んだ後の結果が予告と食い違わないため。
  答えの軸の中で名前が重なれば、軸の追加と同じ内訳 (`axisNameTaken`) を返す。階層の番号・値の空や重複など内訳の無い決まりは、どの軸かだけを添える (`importAxisInvalid`)。直すのは AI に頼み直すことになり、軸が分かれば足りるため。
- プロンプトをサーバーで作らず画面で作るのは、文章が画面の表示言語で決まり、表示言語を知っているのがブラウザーだけのため。
- 外へ出るのはファイルのパスの名前だけで、管理者が自分で貼る。パスに人の名前などが入っていることはあるので、プロンプトを出す画面に、AI のサービスに送られることを一言出す。

## 軸の値の辞書と導出

`archive_axis_values` が両方の `source` を兼ねるが、意味が違う。

- `dir_level` 軸: **辞書は表示のための上書きにすぎない**。値そのものは
  `rel_path` の第N階層の文字列であり、辞書に行が無くても値は成立する。
  行があれば `display_name` と `position` をそこから取る。
  行が無いか、`display_name` が未設定 (NULL または空文字) なら、生の値をそのまま表示する。
  行が無ければ、並び順は既定 (生の値の昇順) にする。
- `filename_word` 軸: **この表の行そのものが照合語リスト**。`raw_value` が
  照合する語、`position` が表示順、`display_name` が表示名。
  行が無ければその軸は何にも一致しない。

`dir_level` 軸を辞書に依存させないことで、軸を足した直後から
再スキャンを待たずに値が出る (architecture.md「データモデルの全体像」の方針と揃う)。スキャン時に辞書行を
UPSERT する処理は必須ではなくなる。値の管理画面は、その時点のアイテムから
生の値を集めて辞書と突き合わせて表示すればよい。

**抽出元か階層番号を変えたら、その軸の辞書の行を消す** (軸の更新と同じトランザクション)。
行は変更前の値の集まりに向けたもので、残すと `dir_level` の表示名が `filename_word` の照合語として解釈されたり、別の階層の値の並び順に効いたりするため。
軸の編集ダイアログでは、抽出元か階層番号を変えている間、辞書が消えることを警告の帯で知らせる。

`position` はリストの並びであり、表示順を決める。照合の優先には使わない。長さが同じ語が複数一致したときだけ、リストの上にあるものを採る。
照合を最長一致にしたので、`数学` と `数学I` のような包含関係を並び順で解決する必要が無い。
`position` に照合の優先度を兼ねさせると、長い語を上に置くために、選択肢が意味の通らない順に並ぶ (共通テストの科目)。
照合の順と表示順を別々に並べ替える案は採らない。並び替え UI が2つに増えると、非技術者に説明しづらいため。

導出のアルゴリズム (読み出し時、アイテム1件ごと):

1. `rel_path` を `/` で分割する。
2. `dir_level` 軸は、対応する位置の要素をそのまま値とする。階層が足りなければ
   「未設定」。表示名と並び順は辞書に行があればそれを使う。
3. `filename_word` 軸は、辞書の行のうち部分一致するものから、語がいちばん長い行を採る。
   同じ長さならリストの上にある行 (`position` が小さい行。`position` も同じなら `id` が小さい行)。一致する行が無ければ「未設定」。

辞書行が古くなる問題は起きない。絞り込みドロップダウンは
**その時点で見えているアイテムに実際に現れた値から作る** ため、
消えたディレクトリの値は自動的に選択肢から落ちる。辞書行を消す・消さないの
判断が不要になる。

**ドロップダウンの選択肢は、閲覧者に見えるアイテムだけから作る**。
匿名閲覧者に非公開アイテムのディレクトリ名が漏れないようにするため
(URL を直接開かれた場合も一覧と同じ判定を通すのと同じ趣旨)。
選択肢は絞り込み前の「見えるアイテム全体」から作り、現在の絞り込み条件では
狭めない (絞り込みを緩める側の選択肢が消えないようにするため)。
見えるアイテム全体に値が1つも無い軸は、選べるのが「すべて」だけになるので返さない (公開の切り替えで値を持つアイテムが見えれば、また返る)。
ほかの軸で絞った結果が0件になっても、軸は返し続ける。選ぶたびに欄が出入りして並びがずれるのを避けるため。

**選択肢は表示名でまとめる**。細かい語を大分類にまとめた軸 (`butsuri`・`kagaku` → 「理科」) や表記揺れを、別の仕組みなしに扱えるようにするため。
表示名 (未設定なら生の値。`display_name` が NULL または空文字を未設定とみなす) が同じ値は1つの選択肢にし、選ぶとそのどれかに当たるアイテムが残る。
選択肢の並びは、下のアイテムの並び順の比較キーに従う。
「未設定」は選択肢に出さず、クエリで指す値も持たない。
ここでの未設定は値が無い状態のことで、表示名の文字列ではない。表示名に「未設定」という文字列を付けた値は、ほかの値と同じく選択肢になる。
ある軸で絞り込むと、その軸が未設定のアイテムは残らない。
生の値ごとに選択肢を作ると、同じ「理科」が照合語の数だけ並び、1つ選んでも理科全体では絞れないため。

アイテムの並び順 (→ 「エンドポイント一覧」) における、軸1本ぶんの比較キーは3段。
表示名が同じ値は、選択肢と同じく1つの値として比べる。

1. 表示名 (未設定なら生の値) が一致する辞書の行がある値: 軸の辞書の全行のうち、表示名が一致する行の `position` の最小値の昇順 (同値なら表示名の昇順)。
   見えているアイテムに現れた行だけから取ると、公開の切り替えで並び順が動くため、全行から取る。
2. 表示名が一致する辞書の行が無い値 (`dir_level` 軸のみ発生。`filename_word` 軸は
   辞書の行そのものが値の集合なのでこの段は存在しない): 生の値の昇順。
   自分の行が無くても、生の値が別の行の表示名と一致すれば 1. に入る。
3. 「未設定」: 常に最後。

## 表示タイトル

- `contents.title_template` に `{軸名}` と固定文字を並べたテンプレートを持つ。
- **`{fileName}` は予約プレースホルダー**で、拡張子を除いたファイル名に展開する。
  軸が全て埋まっていても同じタイトルに潰れる (同じフォルダーに複数のファイルがある)
  場面を、テンプレート側で区別できるようにするため。
  名前をASCIIにするのは、表示言語によらず一意にするため。この名前の軸は作れない。
- 保存時に、テンプレート中の全プレースホルダーが実在する軸名であることを検証する。
  未定義の軸名を含むテンプレートは 422 で拒否する。
- 軸をリネームしたら、同一トランザクション内でテンプレート中の該当箇所も書き換える。
- テンプレートで参照中の軸の削除は 422 で拒否する。リネームには書き換え先があるが
  削除には無く、放置すると admin が触っていない別の保存操作で、上記の検証が
  突然失敗するようになる。
  画面では、削除の確認にその軸を外したテンプレートの案 (`frontend/src/lib/title-template.ts`) を出し、その場で直させてから、テンプレートを保存して削除する。押してから断ると、エラーを閉じてテンプレートを直しに行き、もう一度削除を押し直すことになるため。
- 組み立て時、テンプレート中の軸が1つでも「未設定」なら、組み立てを行わず
  ファイル名 (`rel_path` の最後の要素) をそのまま表示する。部分的に欠けたタイトル (「（問題）」だけ、など) を出さないため。
- 軸ごとに `optional_in_title` を持つ。立っている軸は、未設定なら空文字として組み立てを続ける。
  画面では反転して「値が無ければファイル名のまま表示する」(既定でオン) として見せる。オンで起きることを名前がそのまま言うため。
  ただしテンプレート中の軸がすべて未設定なら、ファイル名を表示する。固定文字だけのタイトルを出さないため。軸を参照しない (`{fileName}` だけの) テンプレートはこれに当たらない。
  テンプレートの記法 (`{課程?}` など) ではなく軸の設定にするのは、記号を覚えなくて済むようにするため。
- テンプレートが空 (NULL) ならファイル名をそのまま表示する。
- アイテム1件ごとの手動上書きは持たない。上書きとルールの二重管理になり、「ルールを直したのに反映されない」事故を生むため。拾えないものは、ファイル名を直すか軸の定義を足す。

## アイテムの公開

- `PUT /api/v1/contents/{id}/items/{item_id}` で公開を切り替える。アイテムのパスに、フォルダーの公開・非公開の印を付ける (→ folders.md「公開と非公開」)。
  権限は `AuthUser`。
  閲覧の画面でも、書き換えられる人には行のメニューに「非公開にする」を出す。見ている場で外せるようにするため。押した行は、その場で「元に戻す」の行に替える。
- 一覧画面からのまとめて切り替えに対応するため、複数 id を受ける
  `PUT /api/v1/contents/{id}/items` (`{itemIds: [...], published: bool}`) も置く。「すべて選択」したときは、番号の代わりに結果の集まりと外した行を送る (→ 「まとめて公開を切り替える」)。
- 管理画面のアイテムのタブは、表示タイトルかパスに含む文字列で絞り込める (→ ui.md「アーカイブのアイテムのタブ」)。
  表紙のように同じ種類のファイルをまとめて選び、公開を切り替えるため。
  全選択と一括切り替えは、絞り込みで出ている行だけに効く。絞り込みを変えると選択を外す。見えない行が選択に残ると、気づかないまま切り替えてしまうため。
  名前の語と公開の状態はサーバーで照らす (→ 「一覧の API を区切って返す」)。公開の状態は URL に持たない。
  次の案は採らなかった。
  - 軸の値で絞る: 表紙は科目の値が行ごとに違い、1つの値では選べない。
  - 値の辞書に「閲覧側に出さない」を持たせる: 公開の判定が印と2か所に分かれる。
- 閲覧できる条件は「フォルダーの `visibility` を満たす」かつ
  「アイテムのパスが公開 (`folder_marks::Marks::is_public`)」の両方。一覧と検索と配信は
  同じ判定を見る。片方を変えるときはもう片方も直す
  (`archive_items.rs` の2か所に互いを指すコメントがある)。

## アイテムの配信

- **一覧と検索は、行ごとに実体があるかを確かめない**。スキャンの後に消えたファイルも、次の再スキャンで行が外れるまで並び、開くと 404 になる。
  確かめると、NAS の数万件で一覧のたびに1分ほどかかるため。写真の管理のアプリも、消えたものは次の読み込みまで残す。
  登録先のフォルダーごと無ければ、閲覧用の一覧は行を並べずに `folderMissing` を立て、画面は空の一覧の代わりにそう出す。管理用の一覧は行を並べたまま `folderMissing` を立て、画面は一覧の上に知らせる。
- `GET /api/v1/contents/{id}/items/{item_id}/download`。
- 受けた値をそのままファイルのパスにせず、`item_id` から索引の `rel_path` を引く。索引済みの
  アイテムだけが配信対象になるため、`folder` の `?path=` 方式より判定が単純になる。
- 実際のファイル読み出しは `folder` と同じ `resolve_path` +
  `serve_file_response` を共有する (canonicalize + `starts_with` 検証、
  Range 対応、`Content-Disposition`、`X-Content-Type-Options` を再利用)。
- **Markdown のプレビューの相対パス (→ ui.md「PDF・動画・テキストのビューアー」) は、`GET /api/v1/contents/{id}/archive/download?path=` で開く**。
  `path` も索引の `rel_path` と突き合わせるだけで、そのままファイルのパスにはしない。あとは `item_id` で指したときと同じ判定で渡す。索引に無いパスは404。閲覧用の一覧のアイテムに `relPath` を載せ、プレビューはそこから解決する。
- **管理画面からは `GET /api/v1/contents/{id}/items/{item_id}/manage-download` で開き、未公開も渡す**。
  権限はアーカイブを管理できること (`AuthUser` のうち、他人の `private` は `admin` だけ。管理用の一覧と同じ)。
  閲覧用の口に「管理者なら未公開も渡す」分岐を足さず、口を分ける。閲覧側の一覧と配信が同じ条件を見る形 (→ 「アイテムの公開」) を崩さないため。
  管理できる人は公開を切り替えられるので、未公開を開けても見える範囲は広がらない。

## 大きなアーカイブの一覧

数十万件のアーカイブも、件数で断らずに扱う。一覧は全件を一度に返さず、見える辺りだけを区切って返す。
Plex・Jellyfin は一覧を区切って取り (何件目から何件)、Google Photos・iOS の写真は全体の件数と大きさを先に知って中身は見える辺りだけ読む。WebLAV も同じ形にしている。

30万件で測った値 (Core i5-1130G7、写真1枚をリンクで増やしたもの):

| | 全件を返していたとき | 区切って返す今 |
|---|---|---|
| 閲覧の一覧の最初の応答 | 2.7秒・56MB | 導出結果を作る1回目は約2.5秒、2回目から 0.1秒前後・1区切り 100KB 程度 |
| ブラウザーの JS のメモリ | 約500MB | 約20MB |
| 中ほどへ飛んだときに行が出るまで | — | 0.3秒 |
| 名前の絞り込み | 画面の中で数秒 | 0.8秒 |
| 全部選んで公開を切り替える | 要求の大きさの上限 (2MB) で断られる | 0.4秒 |

スキャンと同期 (全部変わった再スキャンで約12秒) は変えていない。版を数えるトリガー (下) を足しても変わらなかった。

### 導出の結果と印をサーバーのメモリに持つ

区切って返すと、1つの一覧を何度にも分けて取る。区切るたびに全件を導出すると、30万件で毎回約2.5秒かかる。

- **アーカイブごとに、導出済みの全アイテム (軸の値・表示タイトル・プレビューの値) をメモリに持つ** (`archive_index::ArchiveIndex`)。軸の値は表示名ごとに1つにまとめ、アイテムからは番号で指す。数十万件が同じ文字列をそれぞれ持つと、メモリが件数に比例して膨らむため。並び順ごとの全件の並びも、要るときに一度だけ作って持つ。絞り込んでも並びは変わらないため。
- **公開・非公開の印 (`Marks`) も横に持つ**。印は導出と別に変わるので、導出の結果には混ぜず、絞るときに当てる。1件の切り替えで導出を作り直すと、管理のタブで切り替えるたびに数秒待つため。印はファイルごとに1行で (→ 「まとめて公開を切り替える」)、全部を切り替えると件数ぶんになるので、要求のたびに DB から読み直さない。フォルダーの表示・配信・リンクの一覧も、同じ持ったものを使う。
  印は導出の結果と別に、フォルダーの数だけ持つ (最後に使ってから10分で捨てる)。管理画面の件数や検索のように多くのフォルダーの印を引く所が、数を縛った導出の結果を押し出さないため。
- **版は DB のトリガーで進める** (`archive_versions`)。導出の版 (`index_version`) は索引の行・軸・値の辞書・テンプレート・登録先が変わると進み、印の版 (`marks_version`) は印と「新しく見つかったファイルを公開する」が変わると進む。書く経路が多く、コードの側で進めると1つ漏らしただけで古い一覧や古い公開を返すため。
  バックアップから戻したときは、全部捨てる (DB が丸ごと替わり、版の数も当てにならないため)。
- 版を先に読んでから材料を読む。持つ結果は読んだ版より新しいことはあっても古いことはなく、作る間に材料が変わっても、次の要求で版の違いに気づいて作り直す。同じアーカイブを同時に作り始めない (1つだけ作り、ほかの要求はそれを待つ)。冷えたところへ要求が重なると、それぞれ数秒の導出を回すため。
- 導出の結果は、最後に使ってから10分で捨て、同時に持つのは4アーカイブまで (古いものから捨てる)。授業で開くアーカイブは数個に限られ、1つ作り直しても数秒で済むため。
- ヘッダーの検索は、持っていればそれを使い、無ければ作るが持たない (`index_if_cached_or_build`)。多くのアーカイブを一度に見るので、持つと開いている一覧の分を追い出すため。
- 次の案は採らない。
  - 導出の結果を DB の列に持つ: 軸の値の比較キーは辞書の `position` と表示名のまとめ方で決まり、SQL の `ORDER BY` に載せにくい。辞書を変えるたびに全行を書き直すことにもなる。
  - 導出を速くするだけ: 区切るたびに全件を回す形は残り、件数に比例して遅くなる。

### 一覧の API を区切って返す

- **最初の要求で、絞って並べた結果 (アイテムの番号の列) をサーバーで作り、名前 (`snapshot`) を付けて返す**。続きは `/archive/page` (管理用は `/manage-archive/page`) に `snapshot` と位置 (`offset`・`limit`) を渡して引く。
  途中でほかの人が公開を切り替えたり再スキャンしたりしても、取った行と後で取る行がずれない (`offset` で毎回絞り直すと、1件ずれて重複か欠けが出る)。Jellyfin・Google Photos が結果の集まりを持つのと同じ考え方。
  - 結果は番号の列 (1件8バイト、30万件で2.4MB) で持つ。最後に使ってから10分で捨て、全部で64MB を超えたら古いものから捨てる。閲覧は匿名でもでき、絞り込みを変えるたびに作られるので、数で縛らず量で縛る。0件の結果も1つ4KB と数え、量の上限で数も縛る。捨てた後の要求は 409 にし、画面は見ていた所から取り直す。
  - 結果は、作った口 (閲覧用・管理用) と作った人 (ログインしたユーザー、匿名) に結び付け、ほかの口や人からは引かせない。管理用の結果には未公開も入っているため。
  - 行の中身は引くときの導出の結果から出す。**閲覧用では、引くときの公開の状態でもう一度確かめる**。結果を作った後に非公開になった行の名前を出さないため。消えた行と非公開になった行は、詰めずに `null` にし、画面は「見つかりません」の行にする。
  - 応答に、結果を作ったときより索引か印が新しくなったか (`stale`) を載せる。画面は一覧の上に「一覧が更新されました」と再読み込みのボタンを出す。勝手に取り直すと、見ている行が動くため。取り直すと、管理のタブの選択は外す (選択は前の結果の番号で持つため)。鳴らしている音声と開いているビューアーは、前の結果のまま続ける。
- 区切りの大きさは500件 (`limit` の既定と上限)。行は約200バイトなので1回100KB 程度。
- 軸の選択肢と件数・パンくず・件数 (`total`: 絞り込み後、`totalAll`: 軸で絞った後、名前の語と公開の状態で絞る前。名前で絞り込み中の「N / M 件」の M) は最初の要求だけが返す。開いたときの読み直し (`refresh_changed_dirs`) も最初の要求でだけ走らせる。区切りごとに走らせると、NAS の数千のフォルダーを区切りの数だけ見に行き、更新され続けるフォルダーがあると版が進み続けるため。
- **API では軸の絞り込みを `axis.<軸名>` の形で送る**。軸の名前をそのままキーにすると、`offset`・`status` などの名前の軸と取り違えるため。画面の URL は今の形 (`?科目=国語`) のままにし、画面が送るときに直す (`$lib/archive-list-request.ts`)。軸の名前の予約 (`sort`・`filter`) は増やさない。
- **名前の絞り込み (`filter`) はサーバーで照らす**。手元に全件が無いため。
  - 当たり方の規則は `$lib/list-filter.ts` と同じものを Rust に持つ (`api::list_filter`)。両方を同じ表 (`frontend/src/lib/list-filter-cases.json`) でテストし、食い違わないようにする。強調の位置は画面が出す。
  - 管理のタブはパスでも照らす (続いた文字列だけ)。公開の状態 (`status`) でも絞り、状態ごとの件数を返す。
  - 選択肢の件数・状態ごとの件数は、名前の語と公開の状態の絞り込みも効かせて数える。
  - 語は shallow routing で URL に写し、ページの読み込みは走らせない。取り直しは画面が打ち止めて0.3秒後に行う。

### 画面が見える辺りを取りに行く

- 最初の要求で全体の件数を知り、`WindowVirtualizer` に全体の段の数を渡す。まだ取っていない行は、同じ形の空の行で場所を取る (`archive-row-placeholder.svelte`)。描かれたときに、その行の区切りを取りに行く (`$lib/archive-paged-list.svelte.ts`)。
- 行の高さは揃えていない。空の行はタイトルと2段目の高さで場所を取るので、多くの行と同じ高さになる。タイトルが折り返す行を取ると少し動くが、取るのは見えている辺りだけなので目立たない。
- スクロールが止まったら、見えている所から遠い区切りの要求を取り消す。弾くようにスクロールしたとき、通らなくなった要求が詰まらないように。
- **手元に残す区切りは20区切り (1万行) まで**にし、最後に要ったのが古いものから捨てる。全部残すと、スマートフォンで以前と同じ数百MBに戻るため。
- 名前の語・軸・並び順を変えたら、最初の区切りから取り直す。
- **戻ったときは、元の位置から取る**。見えていた先頭の行の位置を SvelteKit の snapshot に残し、戻ったらその区切りを取ってから、その行へスクロールする。
- 取れなかった区切りは、その場所に「読み込めませんでした」と再試行のボタンを出す。
- **段の数が10万を超えたら、ページに分ける**。要素の高さには上限があり (Firefox で約1,790万 px、Chrome で約3,350万 px)、1段72px で約25万段を超えると最後まで届かないため。一覧の上と下に「前の 100,000 件」「次の 100,000 件」と位置を出す。タイルは1段に何枚も並ぶので、段の数で分け、ボタンの件数は1ページの件数 (段の数 × 1段の枚数) にする。

### 続けて鳴らす音声とビューアー

並びは、押した時点で手元にある連続した行から作る。

- **音声は、残り10曲になったら次の区切りを取り、並びを伸ばす** (`nowPlaying.play` の `more`)。曲の差し替えと `play()` は、終わった操作の中で同期的に行う (`now-playing.svelte.ts` の ADR: Safari が非同期の `play()` を拒むため)。終わってから取りに行くと、ロック画面で続けて鳴らしているときに止まる。続きを取る役は再生の側が持つので、一覧を離れても続けて鳴らす。音声の無い区切りは飛ばして進む。
- **ビューアーは、開くときに前後の区切りを取っておき、その範囲で前後に移る**。PhotoSwipe もファイルのビューアーも、開いた時点の並びを持って前後を決めるため。範囲は開いた行の前後500件以上で、端の手前で行き止まりになる。上の数字はその範囲の中での位置。
- 消えた行と非公開になった行は、並びに入れない。

### まとめて公開を切り替える

- `PUT /contents/{id}/items` は、番号の一覧 (`itemIds`) の代わりに、`snapshot` と外した番号 (`exceptIds`) を受ける。手元に全件が無いと番号を集められず、30万件の番号は要求の大きさの上限も超えるため。
  **対象は、画面が見ていた結果の集まりの番号そのもの**にし、書き込むときに絞り込みをやり直さない。やり直すと、その間に表示名が変わって絞り込みが効かなくなったときや、新しいファイルが入ったときに、見ていないものまで切り替えてしまうため。`snapshot` が捨てられていたら 409 にする。
  結果を作った後に索引から消えた番号は、飛ばして残りを切り替える (消えたファイルに切り替える中身は無く、1件のために全体を断ると押し直しても同じになるため)。応答で切り替えた件数を返す。
  番号の一覧で送るときの、所属しない番号を 404 にする決まり (→ 「エンドポイント一覧」) は変えない。
- 管理のタブの「すべて選択」は、結果の集まりの全部を選ぶ。そこから外した行を `exceptIds` に入れ、「N 件を選択中」の数は全体から外した数を引いて出す。
- 印はまとめて書く (パスの列を JSON にして `json_each` で展開する)。1件ずつ書くと、25万件で書き込みを10秒近く塞いでいたため。
- 印はファイルごとに書く。フォルダーの印1つにまとめる案は採らない。フォルダーの印は、後からそのフォルダーに入ったファイルにも効くので、まとめた後に入ったファイルまで、見ていないのに公開・非公開が決まってしまうため。

### 件数の上限

- **索引する件数では断らない**。以前の上限 (10万件) は全件を一度に返す作りに合わせた値で、区切って返せば要らない。
- 走査するエントリ数の上限 (`fs::SCAN_LIMIT`、50万件) は、人が見ていない走査 (自動の再スキャン・一覧を開いたときの読み直し) と登録前の確認にだけ掛ける。対象の拡張子に当たらないファイルばかりの巨大なツリーで長く居座っても、止める人がいないため。手で始めたスキャンは中止できるので掛けない。
- 登録前の確認 (→ folders.md「登録前の確認」) は、数え上げを `fs::COUNT_LIMIT` (10万件) で打ち切って「100,000 個以上」と出す。確認の窓が出るまで待たせないため。

### ほかに全件を前提にしているもの

- ヘッダーの検索 (`search_items`)・アイテムの数 (`item_counts`)・リンクの一覧のファイル (`folder_search::archive_sources`) は、メモリの導出結果か印を使う。
- 軸の設定を助ける表示 (`dir-levels`・`filename-words`・`values/preview`) は、サーバーで全件から数えて結果だけを返すので、形は変えていない。
- AI に渡す依頼文 (`axes-ai-dialog.svelte`) は、パスの例だけを返す口 (`GET /contents/{id}/path-samples`) を使う。依頼文に載せるのは、並べたうえで間を空けて選んだ150件だけのため。全件を返す管理用の口 (`GET /contents/{id}/items`) は、使うのがこのダイアログだけだったので無くした。

- **`{id}` に属する `item_id` / `axis_id` だけを操作・返却する**。
  クエリの WHERE 句に必ず所属条件を含める
  (`WHERE id = ? AND archive_id = ?`、軸の値なら
  `JOIN archive_axes ON ... WHERE archive_axes.archive_id = ?`)。
  id 単独で引くと、別のアーカイブのアイテムや軸を横取りして操作できてしまう。
  所属しない id は 404 を返す。
- 軸の値の並び替えは、行を1件ずつ動かすのではなく `PUT .../values` で
  リスト全体を送る。表示順を表す1本のリスト (→ 「軸の値の辞書と導出」) を
  D&D で並べ替えて保存する UI に素直に対応するため。
- アイテムの並び順は `sort` クエリで選ぶ (`axis` / `title` / `new`、既定は
  `axis`)。既定の `axis` は、軸の `position` 順に各軸の値を「軸の値の辞書と導出」の比較キーで
  ソートし、最後に `rel_path` で決定する。軸を1本も定義していないアーカイブは
  `rel_path` 順になる。`title` / `new` の意味論はホーム/グループ/フォルダーと同じ
  (→ ui.md「ホーム・グループ・フォルダー・アーカイブの並び順」)。知らない値・未指定は `axis` として扱う (422 にしない)。
- `GET /contents/{id}/archive` のクエリキーのうち、`sort` と、軸名に
  一致しないものは無視する (422 にしない)。軸のリネーム・削除より前に
  共有されたリンクを壊さないため (→ ui.md「アーカイブの一覧画面」。絞り込み状態は URL に持ち、リンクを共有できる)。
  絞り込みに出さない軸 (→ 「軸の定義」) の名前のキーも同じく無視する。
- **クエリの値は選択肢の表示名** (`?教科=理科`)。
  1つの軸で指せる値は1つ (複数選択はしない)。同じキーが複数あるときは、最後の値を使う (クエリを `HashMap` で受けるため。今の挙動と同じ)。
  選択肢との比較は完全一致で、大文字小文字も区別する (ファイル名の照合と違い、表示名は管理者が付けた文字列そのものを指すため)。
  最後の値がどの選択肢にも一致しなければ、前の値には戻らず、その軸の絞り込みを無視する。
  生の値では、表示名でまとめた選択肢 (→ 「軸の値の辞書と導出」) を1つの値で指せないため。
  どの選択肢の表示名にも一致しない値は、軸名に一致しないキーと同じく無視する。
  表示名を変えると、それより前に共有したリンクのその軸の絞り込みは効かなくなるが、軸名の変更と同じ扱いとして受け入れる。
- **選択肢には「それを選んだときに残る件数」を添える**。他の軸の現在の絞り込みを
  効かせたまま、その軸だけを候補の値に置き換えて数える。
  0件になる組み合わせを選ぶ前に見分けられるようにするためで、
  **0件でも選択肢は消さない** (緩める側の選択肢を消さない方針は変えない)。
  選択肢そのものは絞り込み前の全体から作る (→ 「軸の値の辞書と導出」) ので、選択肢の母集団と
  件数の母集団は別であることに注意。
- アイテムの一覧・配信レスポンスにフルパス (登録先のパスとつないだもの) は出さない。登録先からの相対パス (`relPath`) は返し、Markdown のプレビューが相対パスの画像とリンクを解決するのに使う (→ 「アイテムの配信」)。
  画面は `relPath` を表示せず、階層を表に出さないフラットな一覧として見せる。
  実ファイル名 (`rel_path` の最後の要素) は、表示タイトルとは別に返す。
  ページ内プレイヤーへの振り分け (→ ui.md「音声のページ内プレイヤー」) が拡張子で決まるため、閲覧側にも
  実ファイル名が要る。導出済みタイトルは組み立てで拡張子が失われるため
  代用できない。
- 閲覧用の一覧のアイテムには、行の2段目に出す軸の値 (`subtitle`) を組み立てて返す (→ ui.md「アーカイブの一覧画面」)。
  絞り込みの状態で変わるので、クエリを知っているサーバー側で組み立てる。
- `PUT /contents/{id}/items` の一括切り替えは、`itemIds` に所属しない id が
  1件でもあれば全体を 404 にし、どの行も更新しない。単体切り替えと同じ
  「所属しない id は 404」を、一括の場合も全件成立を条件にして揃える。

## 軸の設定を助ける表示

軸を足すときに、フォルダーの構造とファイル名を見ながら決められるようにする。見えていないフォルダーの構造やファイル名を思い浮かべながら設定するのは難しいため。
どれもスキャン済みのアイテム (`archive_items.rel_path`) から計算し、新しいデータは持たない。

- **階層ごとの値 (`dir-levels`)**: 階層ごとに、値の種類の数・その階層を持つアイテムの数・値の例 (件数の多い順に5つ) を返す。
  軸の追加・編集ダイアログで、階層番号を数字で入れる代わりに、この一覧から選ばせる。
- **語の候補 (`filename-words`)**: 拡張子を除いたファイル名から語を切り出し、その語を含むアイテムの数を付けて件数の多い順に返す。
  - 英数字・文字以外 (空白・`_`・`-`・括弧など) で区切った塊と、それを文字種 (数字・ラテン文字・漢字・カタカナ・ひらがな) の変わり目でさらに分けた部分の両方を候補にする。
    `2021中1_04_02英語` のように語がくっついた名前から `英語` を出し、`P2Q-part3` の `P2Q` も崩さずに出すため。
  - 分解形 (NFD) の濁点・アクセントなどの結合文字は、前の文字の続きとして扱う。Mac から来たファイル名で語が切れないようにするため。
  - 大文字小文字の違いは1つにまとめる (照合と同じ)。
  - 件数は「切り出した語の中にその語があるアイテムの数」。照合は部分一致なので、照合で当たる件数はこれより多いことがある (`kyuu` は `tankyuu` にも当たる)。正確な件数は予告 (下) で見る。
  - 候補は照合する位置 (「軸の定義」) を見ずに出す。語の頭の行では、文字種の変わり目で分けた語 (`02英語` の `英語`) は当たらない。当たらないことは予告の未設定の件数で分かる。
  - 数字だけ・1文字・1件にしか出ない・全アイテムに出る語は、既定で隠す印 (`hiddenByDefault`) を付ける。トラック番号や、見分けに使えない語で候補が埋もれないようにするため。
    画面では一覧に出さず、検索したときだけ出す (ファイル名に年が入っている場合など)。
  - 照合語に登録済みの語を外すのは画面の側。保存前の行も含めて外すため。
- **導出結果の予告 (`values/preview`)**: 保存前の値の辞書を受け取り、保存済みの軸の定義と合わせて全アイテムを導出し、一致・未設定の件数と未設定の `rel_path` の例 (5件) を返す。
  - ファイル名の語の軸では、辞書の行ごとに、その行で値が決まるアイテムの件数と例 (5件、`id` 付き) も返す。
    語が何を指すかを、ダウンロードしてきたファイルのように名前だけでは分からないときでも中身で確かめるため。画面は例を管理用の配信 (→ 「アイテムの配信」) で開く。
    数えるのは値を決めた行 (最長一致) だけにし、語を含むだけのアイテムは数えない。保存後に実際に付く値と合わせるため。
  - 置き場所は語の候補ではなく辞書の表の行にする。候補のボタンの並びに開閉の欄を足すと折り返しが崩れ、押して行を足す操作も2段になるため。候補の語を確かめるときは、押して行を足してから開く。
  導出は保存後と同じ関数を通す。画面で計算すると照合の規則 (「軸の定義」・「軸の値の辞書と導出」) を TypeScript にも持つことになり、予告と保存後が食い違いうるため。
  入力の検証 (空・重複で 422) も `PUT .../values` と同じにする。導出は `spawn_blocking` で回す。
- **照合語の数の上限**: ファイル名の語の軸では、照合語が1,000行を超えたら `PUT .../values` も予告も 422 にする。予告の照合が「全アイテム × 照合語の数」になるのを抑えるため。
  階層の軸には掛けない。辞書を引くだけで行数に比例せず、画面は現れた値を全種類送り返すので、値の多い階層で保存できなくなるため。
